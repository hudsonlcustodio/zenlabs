## User story

COMO implementing agent, QUERO a borda pública provisionada exatamente como `aws-topology.md` §2 desenha, PARA nenhum objeto de mídia seja alcançável sem uma URL assinada e nenhuma instância seja exposta diretamente.

## Context

`aws-topology.md` §2 routes Route53 → CloudFront → S3 (static and media, via OAC) or EC2 (dynamic). §2.1 records why there is no load balancer at MVP: a single instance behind CloudFront meets the ≥ 99.5% target and an ALB arrives with the second instance, at gate G-A.

## Acceptance criteria

- **AC-1** A CloudFront distribution per environment routes `/_next` static assets and media to S3 through **Origin Access Control**, and everything else to the compute origin. The S3 origin is not publicly reachable by any path.
- **AC-2** TLS is enforced end-to-end: HTTP redirects to HTTPS, a modern minimum TLS version is set, and the certificate is managed and auto-renewing.
- **AC-3** Route53 hosted zones and records exist per environment with distinct hostnames; no environment resolves to another environment's distribution.
- **AC-4** Media delivery is signed-URL only: the distribution rejects an unsigned request to a media path, and the cache policy never caches a signed media response across users (`security-architecture.md` §6).
- **AC-5** No load balancer resource is created; the promotion-gate check from `P17.01` AC-6 is asserted to be green for this story's plan (`aws-topology.md` §2.1, gate G-A).

## BDD examples

- EX-P17-10 GIVEN an unsigned request to a media path, WHEN it reaches the distribution, THEN it is rejected without reaching S3.
- EX-P17-11 GIVEN a direct request to the S3 media bucket, WHEN it is made from outside CloudFront, THEN it is denied.

## Verification gate

The distribution plan asserts OAC on the S3 origin, TLS redirect and minimum version; an unsigned media request is rejected in the deployed non-production environment; direct S3 access is denied; no ALB/ELB resource appears in the plan.
