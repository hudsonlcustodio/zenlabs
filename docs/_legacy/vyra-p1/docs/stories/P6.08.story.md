# Story P6.08 — FF-07 consumption derived from the ledger

- **Story ID**: `P6.08`
- **Epic**: `P6` (`docs/epics/epic-P6.md`)
- **Status**: `draft`

- **IMPLEMENTATION NOT STARTED**

## User story

COMO architect, QUERO a check that no mutable balance is authoritative, PARA the shortcut that would break FR-UC05 fails the build.

## Context

FF-07 requires all consumption to be derived from the ledger. FR-UC05 states `remaining_minutes` must not be the canonical source of truth.

## Acceptance criteria

- **AC-1** Any column or cache read as an authoritative balance fails FF-07, naming the read.
- **AC-2** Derived or memoised balances are permitted only where the ledger remains the source and the derivation is recomputable.
- **AC-3** Entitlement checks in guards read the derived value rather than a stored one.
- **AC-4** The check runs in the fitness-function stage from P1.06.

## BDD examples

- EX-P6-05 GIVEN code reading a mutable balance column as authoritative, WHEN CI runs, THEN FF-07 fails.

## Verification gate

FF-07 green on the clean tree and red on a seeded mutable balance.
