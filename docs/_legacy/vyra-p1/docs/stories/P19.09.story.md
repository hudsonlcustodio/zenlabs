## User story

COMO frontend engineer, QUERO primitivos de calendário com fuso horário sempre explícito, PARA que nenhum horário de publicação seja exibido sem dizer em que fuso ele acontece.

## Context

`VYRA_PRODUCT_EXPERIENCE.md` §27 fixes month, week and agenda views and — the rule that prevents a whole class of scheduling incidents — that a publication time is never displayed without a timezone anywhere in the product. Editorial scheduling is a database-table dispatcher (`ADR-0010`) with tenant-authoritative times, so the viewer's timezone is frequently not the scheduling timezone.

## Acceptance criteria

- **AC-1** Three view primitives exist — month grid, week columns, agenda list — sharing one item-chip component and one selection model; view and date range are reflected in the URL.
- **AC-2** The month grid follows §27.2: `surface-1` cells with `border-subtle`, a 2px lime top edge on today, up to three items plus `+n`, past days dimmed to `text-tertiary`, out-of-month days at `bg-sunken`.
- **AC-3** **Timezone is always explicit**: the calendar header declares its timezone; a time rendered by any calendar primitive without a timezone is a type error. When the viewer's timezone differs from the authoritative one, both are shown on hover and in any scheduling surface.
- **AC-4** Cells and chips accept drop targets from `P19.08`, with validity supplied as data; drag is disabled on coarse pointers below `md`, where scheduling happens through an explicit action instead (§27.4, §22.4).
- **AC-5** The grid is keyboard-navigable as a two-dimensional grid with roving tabindex; `Enter` on a cell invokes the caller's create action and `Enter` on a chip opens the item.

## BDD examples

- EX-P19-09 GIVEN a publication time, WHEN it renders on a calendar, THEN it is never displayed without a timezone.
- EX-P19-24 GIVEN a viewer whose timezone differs from the tenant's, WHEN a chip is hovered, THEN both times are shown.

## Verification gate

Three views render with a shared chip and selection model and round-trip through the URL; a time without a timezone is a type error; dual-timezone display asserted; drop targets accept validity as data and drag is disabled below `md`; two-dimensional keyboard navigation asserted; axe zero serious/critical.
