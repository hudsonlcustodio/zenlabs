## User story

COMO implementing agent, QUERO uma matriz que prove os 14 critérios em todas as telas das três superfícies, PARA que a ausência de Storybook seja compensada por algo que reprova o build.

## Context

`ADR-0028` removed Storybook and accepted `RISK-05`/`GATE-UX01` on the promise of targeted tests plus the running application. `VYRA_PRODUCT_EXPERIENCE.md` §34 turns that promise into 14 named criteria. This story is where the promise is finally settled: one machine-readable matrix, every screen × every criterion, blocking in CI.

## Acceptance criteria

- **AC-1** A **screen inventory** is derived from the blueprint list in §31, §32 and §33 and reconciled against the routes `apps/web` actually renders. A screen without a blueprint, or a blueprint without a screen, fails the reconciliation naming the difference (`ASM-P24-03`).
- **AC-2** The 14 criteria of §34 are each bound to a concrete check: C-01 blueprint region and primary-action review, C-02 token lint, C-03 `P24.01` and `P24.06`, C-04/C-05 `P24.02`, C-06/C-07/C-08 the state-coverage checks from `P21.11`/`P22.11`/`P23.09`, C-09 the authorization matrix, C-10 `P24.05`, C-11 `P24.04`, C-12 `P24.03`, C-13 the string-source test, C-14 `FF-17` and `EX-P15-02`.
- **AC-3** The result is a machine-readable matrix — screen × criterion × result — published as a CI artifact so the state of the product's experience is inspectable without reading code.
- **AC-4** The suite is wired into `security/static` and is **blocking**; a regression on any screen × criterion fails CI naming both.
- **AC-5** C-01 — the one criterion that cannot be fully automated — is bound to a structural assertion that is checkable: exactly one primary action per screen, the blueprint's declared regions present in the declared order, and type roles used at the declared levels. What remains subjective is recorded as a reviewed checklist item with a named reviewer, not silently skipped.
- **AC-6** `GATE-UX01` is re-recorded as open with this suite named as the accepted substitute, so the acceptance in `ADR-0028` is traceable to something that exists.

## BDD examples

- EX-P24-06 GIVEN a screen added without a blueprint entry, WHEN the inventory reconciliation runs, THEN it fails naming the screen.
- EX-P24-07 GIVEN a regression in any §34 criterion on any screen, WHEN CI runs, THEN it fails naming the screen and the criterion.
- EX-P24-15 GIVEN a screen with two primary actions, WHEN the C-01 structural assertion runs, THEN it fails naming the screen.

## Verification gate

The screen inventory reconciles against the blueprint list with zero difference in both directions; all 14 criteria are bound to concrete checks and green for every screen; the matrix is published as a CI artifact; the suite is blocking in `security/static`; the C-01 structural assertions pass and its reviewed portion has a named reviewer; `GATE-UX01` is recorded as open with this suite named as its substitute.
