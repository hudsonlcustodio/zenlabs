## User story

COMO tenant, QUERO a missing collection recorded as a gap, PARA I can tell "we do not know" apart from "it was zero".

## Context

`performance.md` §5 fixes the behaviour: partial data yields a snapshot with the available fields and a `raw_payload` for the rest; a failed collection retries within its window and then records a gap, never fabricating values and never blocking other windows.

## Acceptance criteria

- **AC-1** A partial platform response produces a snapshot with the available fields populated and the full `raw_payload` retained.
- **AC-2** A failed collection retries within its own window (`performance.md` §5), with the retry budget as configuration rather than a literal.
- **AC-3** After the retries are exhausted the window is recorded as a gap; no value is fabricated and no field is defaulted to zero (I-PF1).
- **AC-4** A gap in one window never blocks or cancels the remaining windows for the same publication.

## BDD examples

- EX-P14-04 GIVEN a platform returning partial data, WHEN the collection completes, THEN the available fields plus the full `raw_payload` are stored and the other windows are unaffected.

## Verification gate

Integration tests over the partial-response, exhausted-retry and independent-window cases, asserting no fabricated value in any of them.
