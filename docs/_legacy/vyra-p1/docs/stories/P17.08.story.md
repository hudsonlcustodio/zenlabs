## User story

COMO implementing agent, QUERO um host de computação que execute os cinco processos em contêiner com troca verificada por health-check e rollback para a imagem anterior, PARA que um deploy ruim seja reversível em minutos e não em uma reconstrução.

## Context

`aws-topology.md` §3 fixes EC2 with Docker Compose, images from ECR tagged by commit SHA, an instance profile scoped to one environment, stateless processes, and a deployment procedure of *pull → health-check → cut over → keep the previous image for rollback*. There is no orchestrator by decision (ADR-0020, brief §5/§26/§44).

## Acceptance criteria

- **AC-1** One EC2 instance per environment runs the five `architecture.md` §2.1 processes as containers from a single compose definition held in the repository, with the `P17.07` instance profile attached and no long-lived credential on the host.
- **AC-2** The instance is not directly reachable from the internet: only CloudFront may reach the dynamic origin, and administrative access is through SSM Session Manager, not an open SSH port.
- **AC-3** Each container declares a health check; the cutover procedure starts the new image, waits for health, switches traffic, and only then stops the previous container. A container that never becomes healthy aborts the cutover with the previous image still serving.
- **AC-4** The previous image tag is retained and a **rollback command** restores it without a rebuild. A rollback drill is executed and its elapsed time recorded.
- **AC-5** Statelessness is asserted: a test confirms no product data is written to the host filesystem by any process, and that terminating and replacing the instance loses nothing (`NFR-11`, `FF-21`).
- **AC-6** No orchestrator, no service mesh and no second instance are introduced; the promotion-gate check from `P17.01` AC-6 is green for this plan.

## BDD examples

- EX-P17-20 GIVEN a new image that never becomes healthy, WHEN cutover runs, THEN traffic stays on the previous image and the deploy fails.
- EX-P17-21 GIVEN a rollback is requested, WHEN it executes, THEN the previous image tag serves traffic without a rebuild.
- EX-P17-22 GIVEN the instance is terminated and replaced, WHEN the environment is reconciled, THEN no product data is lost.

## Verification gate

The five processes run on the instance from the committed compose definition; the instance has no open SSH port and no long-lived credential; an unhealthy image aborts cutover; the rollback drill succeeds and its elapsed time is recorded; the statelessness assertion passes; the promotion-gate check is green.
