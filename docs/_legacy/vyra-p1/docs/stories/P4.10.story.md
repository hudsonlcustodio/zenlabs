## User story

COMO QA reviewer, QUERO a harness asserting each adapter's failure mapping, PARA an adapter that swallows a provider failure is caught.

## Context

`testing-strategy.md` class 4: every adapter maps each provider failure fixture to the correct error class.

## Acceptance criteria

- **AC-1** The harness is table-driven over ports and fixtures so new adapters inherit coverage.
- **AC-2** Every failure fixture asserts the expected taxonomy class.
- **AC-3** Provisional fixtures are skipped with their gate named rather than silently omitted.
- **AC-4** The suite runs on every pipeline execution per `testing-strategy.md` §6.

## BDD examples

- EX-P4-02 GIVEN a provider rate-limit fixture, WHEN the harness runs, THEN the adapter's mapping to the rate-limit class is asserted.
