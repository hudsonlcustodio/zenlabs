## User story

COMO implementing agent, QUERO um harness de conformidade que rode em CI, PARA que a ausência de Storybook seja substituída por algo mais forte: verificação que reprova o build.

## Context

`ADR-0028` recorded `ux-storybook-adapter-unsupported` and sanctioned targeted component tests plus the running application as the substitute, accepted as `RISK-05`/`GATE-UX01`. `VYRA_PRODUCT_EXPERIENCE.md` §23.6 turns that sanction into six concrete checks. This story builds them and wires them into the `security/static` stage, where they block.

## Acceptance criteria

- **AC-1** **axe**: every primitive and every composed region asserts zero serious or critical violations. A new primitive without an axe assertion fails a coverage check that enumerates the export surface.
- **AC-2** **Keyboard traversal**: for every primitive and every overlay, a test asserts that all interactive elements are reachable in DOM order, that no trap exists outside a modal, and that focus returns correctly from every overlay.
- **AC-3** **Contrast**: the headless token computation from `P18.02` AC-4 runs here as a gate over both themes and the raised-contrast set.
- **AC-4** **Reduced motion**: the enumeration from `P18.06` AC-6 runs here as a gate, asserting no computed duration exceeds 1ms under `prefers-reduced-motion` except the sanctioned opacity fades.
- **AC-5** **Screen-reader semantics**: a name/role/value snapshot exists per primitive; a change to any accessible name is a deliberate snapshot update.
- **AC-6** **Token lint**: the rules from `P18.01` AC-4, `P18.04` AC-1, `P18.05` AC-3 and `P18.07` AC-3 run as one gate, so a component cannot reference a raw colour, an off-scale length, a shadow on flat content or a direct Lucide import.
- **AC-7** **PD-10 (accessibility is structural)** becomes mechanical: the harness is wired into the `security/static` stage of `cicd.md` §1 and is blocking. `git ls-files` asserts no Storybook page-story file exists, keeping ADR-0028 true rather than merely stated.

## BDD examples

- EX-P18-36 GIVEN a new primitive exported without an axe assertion, WHEN the coverage check runs, THEN it fails naming the export.
- EX-P18-37 GIVEN a component whose accessible name changed, WHEN the snapshot test runs, THEN it fails until the snapshot is deliberately updated.
- EX-P18-38 GIVEN a Storybook page-story file is added, WHEN CI runs, THEN the ADR-0028 assertion fails naming the file.

## Verification gate

All six checks green in the `security/static` stage and blocking; the export-coverage check proves every primitive is covered by axe, keyboard and screen-reader assertions; each check turns red on its own seeded violation; no Storybook page-story file exists.
