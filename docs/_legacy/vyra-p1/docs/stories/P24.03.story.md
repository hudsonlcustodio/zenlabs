## User story

COMO implementing agent, QUERO semântica assistiva verificada em telas compostas, PARA que primitivos acessíveis não sejam montados em telas inacessíveis.

## Context

`P18.16` proved axe and screen-reader semantics for primitives. The composition is where heading order breaks, where two `<h1>`s appear, where a landmark goes missing and where a live region announces the wrong thing. §23.2 fixes the structure and §34 C-12 makes it a screen criterion.

## Acceptance criteria

- **AC-1** Every screen asserts **zero serious or critical** axe violations at the same thresholds as `P18.16`, in both themes and at three representative breakpoints.
- **AC-2** Document structure is asserted per screen: exactly one `<h1>`, no skipped heading levels, the required landmark set present, and lists and tables using real semantics.
- **AC-3** A name/role/value snapshot exists per screen; a change to any accessible name in a composition is a deliberate snapshot update.
- **AC-4** Live-region behaviour is asserted per screen: async outcomes announce `polite`, errors announce as `alert`, and server-driven updates coalesce per §17.4.
- **AC-5** Screen-level accessible-authentication and redundant-entry criteria are asserted where they apply (§23.5): paste is not blocked in the MFA field, and the request composer does not re-ask for data already on the tenant profile.

## BDD examples

- EX-P24-10 GIVEN any screen, WHEN axe runs in both themes at three breakpoints, THEN zero serious or critical violations are reported.
- EX-P24-11 GIVEN a screen with two `<h1>` elements, WHEN the structure assertion runs, THEN it fails naming the screen.

## Verification gate

Axe green at zero serious/critical for every screen in both themes at three breakpoints; per-screen structure assertions pass; name/role/value snapshots recorded for every screen; live-region behaviour asserted; the two WCAG 2.2 screen-level criteria asserted where applicable.
