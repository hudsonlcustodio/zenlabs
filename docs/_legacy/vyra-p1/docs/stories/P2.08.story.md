## User story

COMO architect, QUERO a check that fails when a client-owned table lacks tenancy or RLS, PARA the guarantee survives every future table added by an agent.

## Context

FF-01: every client-owned table has tenancy and RLS. The check must be table-driven so new tables are covered automatically rather than by remembering to extend a list.

## Acceptance criteria

- **AC-1** The check enumerates tables from the live schema, not from a hand-maintained list.
- **AC-2** A client-owned table without `tenant_id` fails, naming the table.
- **AC-3** A client-owned table without an enabled and forced RLS policy fails, naming the table.
- **AC-4** Exceptions come only from the annotated allowlist derived from `database-schema.md` §2.1, and an unannotated exception fails.

## BDD examples

- EX-P2-02 GIVEN a new client-owned table with no RLS policy, WHEN CI runs, THEN FF-01 fails naming the table.

## Verification gate

FF-01 green on the clean schema and red on each seeded violation.
