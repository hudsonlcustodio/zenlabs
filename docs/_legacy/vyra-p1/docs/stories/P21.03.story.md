## User story

COMO cliente, QUERO uma tela que responda primeiro o que precisa de mim, PARA que eu nunca descubra tarde que um roteiro esperava minha aprovação.

## Context

`FR-P01` asks for a dashboard summarising pipeline state, consumption and recent performance. `VYRA_PRODUCT_EXPERIENCE.md` §31.3 fixes the hierarchy that makes it a product rather than a report: the action rail first, then metrics, then pipeline and consumption, then performance and activity. PD-02 is why.

## Acceptance criteria

- **AC-1** The `L-dashboard` layout of §31.3 renders in the stated order, with metrics set at the display scale PD-03 requires and no decoration around them, with the action rail appearing **only when non-empty** — never as an empty region.
- **AC-2** The action rail lists items in `SCRIPT_REVIEW` and `VIDEO_REVIEW` — the only two states where the client is the bottleneck (§21.2) — each opening its approval surface directly. These are the only lime elements on the screen.
- **AC-3** Each region has its own streaming boundary and its own `P18.14` skeleton, so a slow region never delays the action rail (§18.3, `NFR-03`).
- **AC-4** The consumption meter renders committed and reserved separately, because a reservation is not a charge (§31.12), and folds from the ledger rather than from a cached total (`FF-07`).
- **AC-5** Blocked items raise a danger banner above the action rail with the §21.3 reason and next action; `FAILED` items appear the same way. Neither is hidden in a secondary tab.
- **AC-6** The first-run state replaces the metric, pipeline and performance regions with a single `first-run` empty state and the action rail is absent, per §31.3.

## BDD examples

- EX-P21-14 GIVEN nothing is pending, WHEN the dashboard renders, THEN the action rail is absent rather than empty.
- EX-P21-15 GIVEN one slow region, WHEN the dashboard loads, THEN the action rail renders before that region resolves.
- EX-P21-16 GIVEN a held reservation, WHEN the consumption meter renders, THEN reserved and committed are shown separately.

## Verification gate

Region order and streaming boundaries asserted; the action rail is present only when non-empty and is the only lime region; consumption folds from the ledger with reserved and committed distinguished; blocked and failed items raise the danger banner with reason and next action; the first-run state replaces the data regions.
