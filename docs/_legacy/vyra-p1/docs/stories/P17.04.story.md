## User story

COMO implementing agent, QUERO os buckets de mídia e conhecimento criados privados, criptografados e com layout de chave por tenant, PARA que um objeto público seja inexpressável e não apenas desaconselhado.

## Context

`aws-topology.md` §5 fixes two buckets per environment, Block Public Access at account and bucket level, OAC-only delivery, a tenant-prefixed non-semantic key layout, versioning on media, lifecycle transitions and SSE-KMS. `FF-21` forbids media on local disk; this is where it must instead live.

## Acceptance criteria

- **AC-1** `vyra-<env>-media` and `vyra-<env>-knowledge` exist per environment with **Block Public Access enabled at both account and bucket level**, and a bucket policy that permits only the CloudFront OAC principal and the environment's instance profile.
- **AC-2** SSE-KMS encryption is enforced by bucket policy: an unencrypted `PutObject` is rejected, not silently encrypted.
- **AC-3** Versioning is enabled on the media bucket; MFA-delete is not required at MVP and its absence is recorded rather than left implicit.
- **AC-4** The key layout `<env>/<tenantId>/<kind>/<uuid>` is enforced by the instance-profile policy through a prefix condition, so a process cannot write outside its environment prefix.
- **AC-5** Lifecycle rules transition source and intermediate artifacts to infrequent access after 90 days; expiry rules are parameterised and are wired to the retention table in `database-schema.md` §5, whose enforcement is `P16.04`.
- **AC-6** A plan-time assertion fails if any bucket in any environment lacks Block Public Access, lacks SSE-KMS, or carries a public ACL or policy statement.

## BDD examples

- EX-P17-04 GIVEN an S3 bucket without Block Public Access, WHEN the plan is checked, THEN it fails before apply.
- EX-P17-12 GIVEN an unencrypted `PutObject`, WHEN it reaches the bucket, THEN it is rejected.

## Verification gate

Both buckets exist per environment; the public-access and encryption assertions are green and turn red on a seeded violation; an unencrypted put is rejected in the deployed non-production environment; lifecycle rules match the parameterised retention configuration.
