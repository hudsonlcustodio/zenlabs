## User story

COMO operations manager, QUERO periodic reconciliation of in-flight provider work, PARA a lost webhook delays a job instead of stranding it forever.

## Context

`provider-architecture.md` §7 and `workflows-state-machines.md` §7. Polling is the primary path and webhooks are an accelerator (OQ-P7-01).

## Acceptance criteria

- **AC-1** A loop periodically reconciles items in provider-pending states against provider status.
- **AC-2** Reconciliation uses the stored provider job reference and never resubmits work (`provider-architecture.md` §6).
- **AC-3** Crash recovery re-enters reconciliation rather than restarting the operation.
- **AC-4** Loop lag and stuck-item counts are exposed as metrics for P16.02.

## BDD examples

- EX-P7-07a GIVEN a provider job whose webhook never arrived, WHEN reconciliation runs, THEN the job's status is resolved by polling rather than by resubmission.

## Verification gate

Integration tests covering missing-webhook and crash-recovery paths.
