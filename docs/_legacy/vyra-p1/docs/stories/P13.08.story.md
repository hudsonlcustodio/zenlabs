# Story P13.08 — TikTok publishing adapter with the unaudited restriction

## User story

COMO tenant, QUERO the TikTok channel to state exactly what it can do while the app is unaudited, PARA I am never sold reach the platform does not currently permit.

## Context

`social-publishing.md` §3 records the confirmed TikTok facts: unaudited clients are restricted to `SELF_ONLY` viewership, may allow at most 5 posting users per 24-hour window with those accounts private at posting time, and require an audit to lift the restriction. RISK-01 and GATE-TT01 make this a launch gate for the channel, not a design constraint.

## Acceptance criteria

- **AC-1** `TikTokPublishingProvider` implements the `PublishingProvider` port in `packages/providers` (`provider-architecture.md` §1).
- **AC-2** Creator information is queried before posting so posting eligibility reflects the account's real state (`social-publishing.md` §3.1).
- **AC-3** While the app is unaudited, publication proceeds as `SELF_ONLY`, the item is flagged and the tenant is informed; the product never implies public reach (`social-publishing.md` §5, RISK-01).
- **AC-4** The 5-users-per-24h and visibility constraints are operational configuration consumed by the `P13.04` admission control, not constants (FF-13).

## BDD examples

- EX-P13-08a GIVEN an unaudited app, WHEN a TikTok publication succeeds, THEN the resulting item is flagged as `SELF_ONLY` and the tenant is informed.
