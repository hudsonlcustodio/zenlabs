## User story

COMO frontend engineer, QUERO uma hierarquia de feedback com regiões vivas, PARA que nada essencial dependa de um toast e que todo desfecho assíncrono seja anunciado.

## Context

`VYRA_PRODUCT_EXPERIENCE.md` §17 fixes what may and may not be a toast, the five-level feedback hierarchy and the live-region contract. The prohibition list matters more than the feature: validation errors, destructive confirmations and anything the user must read to proceed are never toasts.

## Acceptance criteria

- **AC-1** A toast system exists with the placement, stacking limit (3, then `+n more`) and durations of §17.1: 5s default, 8s with an action, sticky for errors until dismissed.
- **AC-2** The prohibition list of §17.2 is enforced by API: the toast component accepts no `variant` that renders a validation error, no confirm/cancel pair, and no content marked as required-to-proceed. A destructive confirmation cannot be expressed as a toast.
- **AC-3** Three banner primitives exist for hierarchy levels 2 and 3: region banner (inside a card or section), page banner (under the page header) and global banner (under the topbar), each with tone, icon, message, optional action and optional dismissal.
- **AC-4** A live-region service exists: async outcomes announce through `aria-live="polite"`, errors through `role="alert"`, every toast is mirrored into it, and server-driven state changes coalesce to at most one announcement every 10 seconds (§17.4).
- **AC-5** An `Undo` affordance is supported on toasts for reversible actions only; a toast offering undo for an irreversible action is a type error, because §17.2 and PD-07 forbid it.

## BDD examples

- EX-P18-28 GIVEN a validation error, WHEN the developer attempts to render it as a toast, THEN the API refuses it and the form renders it inline.
- EX-P18-29 GIVEN four rapid server-driven state changes, WHEN they are announced, THEN at most one announcement is made in the ten-second window.

## Verification gate

Toast placement, stacking and durations asserted; the prohibition list is enforced at the type level; three banner primitives render at their hierarchy levels; live-region announcements and coalescing asserted; undo restricted to reversible actions.
