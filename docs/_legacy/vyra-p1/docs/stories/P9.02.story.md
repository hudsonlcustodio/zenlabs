# Story P9.02 — Parsing pipeline

## User story

COMO implementing agent, QUERO each accepted input type parsed into normalised text with provenance, PARA downstream chunking never has to know the original format.

## Context

`knowledge-engine.md` §1-§2. Parsing runs in `apps/worker-ai` under the P7.04 harness so tenancy holds.

## Acceptance criteria

- **AC-1** Each accepted type in `knowledge-engine.md` §2 has a parser producing normalised text.
- **AC-2** Parsing preserves provenance so a chunk can be traced to its location in the source.
- **AC-3** A parser failure records a specific failure reason rather than a generic error (FR-KN04).
- **AC-4** Parsing runs inside the worker harness with tenant context set.

## BDD examples

- EX-P9-02a GIVEN a PDF whose text layer is absent, WHEN parsing runs, THEN a specific failure reason is recorded rather than an empty success.

## Verification gate

Integration tests per input type with success and failure fixtures.
