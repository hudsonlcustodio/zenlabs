# Story P8.11 — FF-06 content state changes only via the engine

- **Story ID**: `P8.11`
- **Epic**: `P8` (`docs/epics/epic-P8.md`)
- **Status**: `draft`

## User story

COMO architect, QUERO a check that nothing but the engine writes content state, PARA the transition table cannot be circumvented by a repository call.

## Context

FF-06 requires content state to change only via the workflow engine. Module 8's invariant states the same rule.

## Acceptance criteria

- **AC-1** A write to the content state column from outside the engine fails FF-06, naming the write.
- **AC-2** Direct SQL updates to the state column fail the check as well as ORM writes.
- **AC-3** The check runs in the fitness-function stage from P1.06.

## BDD examples

- EX-P8-01 GIVEN a repository writing `content_item.state` directly, WHEN CI runs, THEN FF-06 fails naming the write.

## Verification gate

FF-06 green on the clean tree and red on a seeded direct write.
