## User story

COMO implementing agent, QUERO uma infraestrutura descrita em código com estado remoto e uma lane de CI própria, PARA nenhuma alteração de infraestrutura possa ser feita à mão sem que a próxima execução a denuncie.

## Context

`aws-topology.md` describes the topology but names no tool and creates no resource. `cicd.md` §6 fixes GitHub OIDC federation to a least-privilege AWS role per environment and forbids long-lived AWS keys in repository secrets. This story establishes the substrate every other `P17` story writes into, and resolves `ASM-P17-01`.

## Acceptance criteria

- **AC-1** An `infra/` workspace exists with the IaC tool and provider versions pinned in the repository, not assumed from the operator machine. The chosen tool is recorded, closing `ASM-P17-01`.
- **AC-2** Remote state is versioned, encrypted at rest with KMS, locked against concurrent writes, and stored **per environment** with no shared state object.
- **AC-3** CI authenticates to AWS through GitHub OIDC federation to a role scoped to one environment per job. A grep assertion proves no long-lived AWS access key exists in repository secrets or in any workflow file (`cicd.md` §6).
- **AC-4** The infrastructure CI lane runs `fmt`, `validate`, a static policy check and `plan` on every pull request, posts the plan summary, and **never** applies from a pull request. Apply runs only from the default branch or a manual dispatch, per environment.
- **AC-5** A drift check runs the plan against the deployed state on a schedule and fails when the plan is non-empty, naming each drifted resource.
- **AC-6** The static policy check contains the promotion-gate rule from `scalability-gates.md`: a resource type on the deliberately-absent list (ALB/ELB, EKS/ECS, ElastiCache, EventBridge, multi-AZ RDS, service mesh, data-lake services) fails the check citing its gate id.

## BDD examples

- EX-P17-02 GIVEN a resource is created outside code, WHEN the drift check runs, THEN it fails naming the resource.
- EX-P17-07 GIVEN a pull request adding an ElastiCache cluster, WHEN the policy check runs, THEN it fails citing gate G-E.

## Verification gate

The infra lane is green on an empty plan; a seeded hand-created resource turns the drift check red; a seeded ElastiCache resource turns the policy check red naming G-E; no long-lived AWS key exists anywhere in the repository.
