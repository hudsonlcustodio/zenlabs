## User story

COMO platform operator, QUERO provider limits expressed as configuration, PARA a provider changing a limit is an operational change rather than a release.

## Context

FF-13 requires provider limits to be configuration, not constants. ASM-MT01 makes the same point for Meta rate limits and PPA behaviour.

## Acceptance criteria

- **AC-1** Rate limits, timeouts, page sizes and retry budgets are read from configuration.
- **AC-2** A numeric provider limit appearing as a literal in adapter or domain code fails FF-13.
- **AC-3** Defaults exist in configuration so absence is not a silent zero.

## BDD examples

- EX-P4-08a GIVEN a hard-coded per-day publication limit, WHEN CI runs, THEN FF-13 fails naming the file.

## Verification gate
