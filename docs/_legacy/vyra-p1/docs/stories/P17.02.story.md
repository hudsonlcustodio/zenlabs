# Story P17.02 — Three separated environments and the NFR-12 separation check

## User story

COMO implementing agent, QUERO development, staging e production isolados por construção, PARA `NFR-12` seja uma propriedade verificável e não uma promessa operacional.

## Context

`NFR-12` and `aws-topology.md` §7 require that the three environments share no database, bucket, queue, secret, credential, token or provider key. `P16.10` verifies this at wave 13; this story is what makes it true at wave 3, and resolves `ASM-P17-02`.

## Acceptance criteria

- **AC-1** Three environments — `development`, `staging`, `production` — are instantiated from one parameterised module set, so a resource that exists in one exists in all three or in none, and no environment is a hand-built variant.
- **AC-2** Every resource name and every ARN is environment-prefixed by construction (`vyra-<env>-*`), and the module makes an unprefixed name impossible to express rather than merely discouraged.
- **AC-3** A **separation check** enumerates every IAM policy statement in every environment and fails when any principal in environment A is granted access to a resource in environment B, naming both environments, the principal and the resource.
- **AC-4** No secret, credential, token or provider key is shared: the check asserts that each environment's Secrets Manager path prefix and KMS key set are disjoint from the others'.
- **AC-5** `PROVIDER_MODE=mock` is enforced by configuration in development and staging; only production carries `live`, and a time-boxed live test in a lower environment requires an explicit, expiring override that the check reports (`aws-topology.md` §7, `NFR-13`).
- **AC-6** `sa-east-1` is asserted once, centrally: a resource declared in any other region fails the plan check naming the resource and the region (ADR-0019).

## BDD examples

- EX-P17-03 GIVEN a policy grants staging access to a production bucket, WHEN the separation check runs, THEN it fails naming both environments.
- EX-P17-09 GIVEN a resource declared in `us-east-1`, WHEN the plan check runs, THEN it fails naming the resource and the region.

## Verification gate

Three environments plan cleanly from one module set; the separation check is green and turns red on a seeded cross-environment grant; the disjointness assertion on secret paths and KMS keys passes; a seeded non-`sa-east-1` resource fails the region assertion.
