## User story

COMO security reviewer, QUERO tenancy filtering inside the retrieval query itself, PARA a similarity search can never surface another tenant's material.

## Context

FF-05 requires vector retrieval to filter tenancy in SQL. FR-KN03 extends tenant scoping explicitly to embedding retrieval. ADR-0007 keeps vectors inside PostgreSQL so RLS applies.

## Acceptance criteria

- **AC-1** The retrieval query filters on tenant in SQL, not by post-filtering results in application code.
- **AC-2** Retrieval executes inside the `TenantContext` transaction so RLS applies as a second layer.
- **AC-3** The retrieval API cannot be invoked without a tenant scope; no default or global mode exists.
- **AC-4** Query construction satisfies FF-22, so no filter is assembled by string interpolation.

## BDD examples

- EX-P9-04 GIVEN two tenants with identical documents, WHEN tenant A retrieves, THEN no chunk belonging to tenant B is returned.
- EX-P9-01 GIVEN a retrieval query whose SQL omits the tenancy filter, WHEN CI runs, THEN FF-05 fails.

FF-05 passes; class 7 isolation suite extended to retrieval.
