## User story

COMO operations manager, QUERO to manage client configuration, requests, briefings and scripts, and to act on a tenant's behalf where policy allows, PARA internal operations do not depend on database access.

## Context

FR-S01, FR-S02 and FR-S07 fix the internal management surface. `api-contracts.md` §4 restricts these routes to internal roles, requires an explicit `tenantId` and requires an audit write on every mutation.

## Acceptance criteria

- **AC-1** Client and request management use the §4 internal routes; the screen never reaches a Portal route with an impersonated session.
- **AC-2** Acting on a tenant's behalf is possible only where the tenant's policy allows it, per FR-S07, and the acting actor is recorded rather than the tenant.
- **AC-3** Every mutation writes an audit record carrying actor, role, subject, before and after, correlation id and IP, as `security-architecture.md` §9 requires.
- **AC-4** Tenant selection is explicit and visible on every internal screen, so a cross-tenant action is never taken by accident.

## BDD examples

- EX-P15-01 GIVEN a `QA_REVIEWER` session, WHEN a Control screen route is requested, THEN the server denies it rather than rendering a filtered view.

## Verification gate

Class 6 coverage of the internal routes by role; integration coverage asserting an audit record is written for each mutation performed from these screens.
