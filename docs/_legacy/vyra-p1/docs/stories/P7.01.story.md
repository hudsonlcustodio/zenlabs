## User story

COMO architect, QUERO events written in the same transaction as the state they describe, PARA an event can never claim something the database did not record.

## Context

`architecture.md` §7 and ADR-0009. `database-schema.md` §5 retains published outbox rows for 30 days as outbox hygiene.

## Acceptance criteria

- **AC-1** `domain_event` rows are written inside the same transaction as the state change that produced them.
- **AC-2** The row carries the event type, payload, tenant, correlation identifier and publication status.
- **AC-3** Payload types come from `packages/contracts` so producers and consumers cannot drift.
- **AC-4** Published rows are retained 30 days per `database-schema.md` §5, with cleanup scheduled in P16.04.

## BDD examples

- EX-P7-01 GIVEN a state change whose transaction rolls back, WHEN the relay runs, THEN no event is published.

## Verification gate

Integration test asserting rollback produces no outbox row.
