# Story P14.07 — FF-16 dashboards never call providers synchronously

- **Story ID**: `P14.07`
- **Epic**: `P14` (`docs/epics/epic-P14.md`)
- **Status**: `draft`
- **Wave**: 9
- **Priority**: P0
- **Story points**: 3

- **IMPLEMENTATION NOT STARTED**

## User story

COMO architect, QUERO the no-synchronous-call rule enforced by the build, PARA a convenient shortcut in a handler cannot quietly reintroduce provider traffic on dashboard open.

## Context

FF-16 is the Phase 13 acceptance gate. It forbids `modules/performance/**` request handlers from importing `PublishingProvider` and asserts the performance endpoint makes zero provider calls against the mock. Phase 13's definition of done is exactly "opening a dashboard makes zero provider calls".

## Acceptance criteria

- **AC-1** A `dependency-cruiser` rule forbids `modules/performance/**` request handlers from importing `PublishingProvider`, and it fails the build on any such import.
- **AC-2** A test asserts the performance endpoint makes zero provider calls against the mock, and fails if any call is observed.
- **AC-3** The check runs in the CI fitness-function stage from P1.06 and is red when a provider call is seeded into the read path.

## BDD examples

- EX-P14-01 GIVEN a performance request, WHEN the endpoint serves it, THEN zero provider calls are observed against the mock.

## Verification gate

FF-16 green on the clean tree and red on a seeded synchronous provider call in a performance handler.
