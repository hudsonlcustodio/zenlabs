## User story

COMO portal user, QUERO account prerequisites checked before I schedule, PARA a missing Page authorization is a message today rather than a failed post next week.

## Context

ADR-0017 requires connection health — account type, Page link, PPA, 2FA, token validity and quota — to be validated **before** scheduling. RISK-17 records the prerequisite failure mode; FR-SP05 forbids supporting personal Instagram accounts and requires stating this in onboarding.

## Acceptance criteria

- **AC-1** Connection health checks cover the linked Facebook Page, admin-equivalent permission, Page Publishing Authorization, 2FA completion and token validity, and run before scheduling rather than at publish time (`social-publishing.md` §2.1).
- **AC-2** A personal Instagram account is refused at connection time with explicit remediation text; support is never implied (FR-SP03, FR-SP05).
- **AC-3** The Instagram ceiling of 100 API-published posts per rolling 24 hours and the TikTok unaudited posting limits are stored as operational configuration and used for admission control, never as hardcoded constants (ASM-MT01, FF-13).
- **AC-4** `GET /social-connections` returns health with the failing prerequisite named, so the remediation is actionable (`api-contracts.md` §3.7).

## BDD examples

- EX-P13-06 GIVEN a personal Instagram account, WHEN connection is attempted, THEN it is refused at connection time rather than at publish time.

## Verification gate

Integration test per prerequisite failure and class 4 adapter coverage mapping each platform rejection fixture to the correct error class, including `connection_invalid`.
