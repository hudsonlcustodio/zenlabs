# Story P13.12 — FF-29 publication is authorized and deduplicated

## User story

COMO architect, QUERO duplicate and unauthorized publication made structurally impossible, PARA T-17 is closed by a constraint instead of by a code review.

## Context

FF-29 asserts the partial unique index on `(content_item_id, channel_id)`, double-publishes and asserts one `external_post_id` and one platform call, and runs an authorization test for the schedule and publish routes. T-17 in `threat-model.md` requires `READY` state, a valid connection, an authorized actor and consent re-checked at dispatch, with every publication audited.

## Acceptance criteria

- **AC-1** The partial unique index `(content_item_id, channel_id) WHERE status <> 'cancelled'` is asserted to exist against the migrated database.
- **AC-2** A double publish yields exactly one `external_post_id` and exactly one platform call.
- **AC-3** The schedule and publish routes are covered by the class 6 authorization matrix for every role, and consent is re-checked at dispatch (T-17).
- **AC-4** Every publication writes an audit record, and the class 12 end-to-end path completes through schedule and publish against mocks (`testing-strategy.md` class 12).

## BDD examples

- EX-P13-01 GIVEN a connected channel, WHEN the same content item is dispatched to it twice, THEN exactly one `external_post_id` exists and exactly one platform call was made.

## Verification gate

FF-29 green in CI together with class 6, class 10 and class 12 suites; FF-29 turns red when the partial unique index is dropped.
