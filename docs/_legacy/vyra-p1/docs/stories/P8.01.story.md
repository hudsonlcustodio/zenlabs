## User story

COMO portal user, QUERO to submit a request with only what is genuinely required, PARA requesting content is not itself a chore.

## Context

FR-CR01 to FR-CR03 and `domain-model.md` §6. ASM-CR01 makes only `objective` and `channel` mandatory; over-requiring fields is explicitly rejected by the brief.

## Acceptance criteria

- **AC-1** `ContentRequest` is a first-class entity, not free text (FR-CR01).
- **AC-2** Only `objective` and `channel` are mandatory; every other field in FR-CR02 is optional (ASM-CR01).
- **AC-3** Validation is expressed in Zod schemas from `packages/contracts` and shared with the API contract tests.
- **AC-4** The aggregate is tenant-scoped and RLS-protected.

## BDD examples

- EX-P8-01a GIVEN a request with objective and channel only, WHEN it is submitted, THEN it is accepted.
