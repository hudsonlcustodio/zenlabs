# Story P16.10 — Environment separation verification and the production gate register

- **Story ID**: `P16.10`
- **Epic**: `P16` (`docs/epics/epic-P16.md`)
- **Status**: `draft`
- **Wave**: 13

- **IMPLEMENTATION NOT STARTED**

## User story

COMO platform operator, QUERO environment separation verified against real resources and every external gate listed with what it blocks, PARA launch readiness is a checklist with evidence rather than a memory.

## Context

`epic-P1` records that NFR-12 is prepared in P1 but only fully verifiable once real resources exist, and names this epic as the place. `implementation-sequencing.md` rule 4 states external gates never block a phase; they block production launch of the affected capability. `risks.md` §3 lists the twelve gates and their owners.

## Acceptance criteria

- **AC-1** A verification asserts that development, staging and production share no database, bucket, queue, secret, credential, token or provider key, as NFR-12 and `aws-topology.md` §7 require.
- **AC-2** The register lists every gate in `risks.md` §3 with the capability it blocks and its owner, including GATE-NOTIF01 from `P16.06` and GATE-UX01 from `P15.01`.
- **AC-3** The register states, for each gate, that it blocks production launch of the affected capability and not the phase, per `implementation-sequencing.md` rule 4.
- **AC-4** Production deployment remains gated on staging smoke green, a reviewed migration plan and human approval, per `cicd.md` §5, with the security/static stage green on the exact SHA being deployed.

## BDD examples

- EX-P16-06 GIVEN staging under the declared load profile, WHEN the class 14 suite runs, THEN P95 read latency is under 500 ms, P95 write latency is under 800 ms and critical screen load is under 3 s.

## Verification gate

Integration assertion that no resource identifier, secret path or provider key is shared across environments; register review showing every `risks.md` §3 gate present with owner and blocked capability.
