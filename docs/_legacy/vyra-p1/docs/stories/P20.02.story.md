## User story

COMO frontend engineer, QUERO que a navegação seja renderizada a partir do manifesto de rotas do servidor, PARA que um item escondido e uma rota negada nunca discordem.

## Context

`P3.07` builds the route manifest that `FF-17` enumerates. `VYRA_PRODUCT_EXPERIENCE.md` §3.2 fixes seven navigation rules, and §2.2–§2.4 fix the three surfaces' information architecture. Deriving the rail from the manifest is what makes G4 of `epic-P15` — *a hidden control and a denied route can never disagree* — structurally true rather than reviewed.

## Acceptance criteria

- **AC-1** The rail renders from the server-resolved route manifest for the session. An item whose route the session cannot enter is **absent**, not disabled and not greyed; a hand-maintained navigation list is a defect and the source assertion proves the manifest is the only source (`ASM-P20-01`).
- **AC-2** The three information architectures of §2.2, §2.3 and §2.4 are declared as data: Portal five L1 items, Studio seven, Control five, each with their L2 sets.
- **AC-3** Navigation depth is at most three — surface → section → object. A fourth level is a drawer or a tab inside the object; a rail item at depth four fails the IA assertion.
- **AC-4** The rail does not scroll at a 900px-tall viewport for any surface, asserted by test for all three item sets.
- **AC-5** Active state renders as a 2px lime left indicator plus `text-primary` on `surface-2`; the active item is also `aria-current="page"`.
- **AC-6** Tabs are only for views of one object and breadcrumbs only on object detail, both enforced by the component API: the tab primitive rejects heterogeneous object targets and the breadcrumb primitive requires a collection root.

## BDD examples

- EX-P20-01 GIVEN a session that cannot enter Control, WHEN the shell renders, THEN no Control rail item exists and a direct route request is denied server-side.
- EX-P20-10 GIVEN a rail item declared at depth four, WHEN the IA assertion runs, THEN it fails naming the item.

## Verification gate

The rail renders solely from the route manifest and the source assertion proves it; the three IA declarations match §2.2–§2.4; depth ≤ 3 asserted; the rail does not scroll at 900px for any surface; `aria-current` and the active indicator asserted; tab and breadcrumb constraints enforced at the API level.
