## User story

COMO portal user, QUERO to track in-flight items and see the editorial calendar, PARA I know what is coming and when without asking.

## Context

FR-P03 requires tracking in-flight content items and their state; FR-P06 requires viewing the editorial calendar. `api-contracts.md` §3.2 and §3.3 fix the list, filter and schedule routes. FR-CA01 fixes what a calendar entry carries.

## Acceptance criteria

- **AC-1** The item list uses the allowlisted filters in `api-contracts.md` §3.2 — state, `campaignId`, channel — and cursor pagination per §1, never offset pagination.
- **AC-2** The calendar renders channel, date, time, campaign, status and external post id where present, the fields FR-CA01 names.
- **AC-3** Scheduling and schedule cancellation use the §3.3 routes; the screen adds no scheduling semantics of its own.
- **AC-4** Item state labels come from the transition table rather than from screen-local strings, so the surface cannot invent a state the engine does not have.

## BDD examples

- EX-P15-09 GIVEN a content item owned by another tenant, WHEN its identifier is requested from a Portal screen, THEN the response is `404` and the screen renders a not-found state indistinguishable from a nonexistent item.

## Verification gate

Integration coverage of list filtering and cursor pagination; object-scope test asserting a foreign identifier yields `404` per `api-contracts.md` §2.
