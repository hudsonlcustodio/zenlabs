# Story P18.08 — Core control primitives

## User story

COMO frontend engineer, QUERO botões, campos e seletores próprios com todos os estados e operabilidade por teclado desde o primeiro commit, PARA que acessibilidade seja estrutural e não uma passada posterior.

## Context

`ADR-0003` vendors shadcn/ui into `packages/ui` as project-controlled primitives. `NFR-14` makes keyboard operability and accessible naming architectural. `VYRA_PRODUCT_EXPERIENCE.md` §13.2 fixes the eight control states, and §7.4 makes height a density token.

## Acceptance criteria

- **AC-1** The control set exists and is owned in-repo: button (primary, secondary, ghost, destructive), text input, textarea, select, combobox, checkbox, radio group, switch, slider and segmented control. Each is composed from tokens only.
- **AC-2** Every control implements the eight states of §13.2 — rest, hover, focus, filled, invalid, disabled, read-only, loading — with `filled` deliberately identical to `rest`, because a value is not a state.
- **AC-3** Every control is fully operable by keyboard with the expected role semantics, is reachable in DOM order, and shows `glow-focus` on `:focus-visible`. Focus is never removed; a component suppressing the focus ring fails the harness.
- **AC-4** A disabled control that carries information is focusable-but-`aria-disabled` with a discoverable reason, so a keyboard user can find out why (§23.3). A silently disabled control with no reason fails the review checklist in `P18.16`.
- **AC-5** Control height comes from `--vyra-control-h`; textarea starts at 3 rows, auto-grows to 12, then scrolls (§13.2).
- **AC-6** Each control ships an axe assertion with zero serious or critical violations, and a screen-reader name/role/value snapshot.

## BDD examples

- EX-P18-21 GIVEN any control, WHEN it receives keyboard focus, THEN `glow-focus` is visible against the surface it sits on.
- EX-P18-22 GIVEN a disabled control carrying information, WHEN a keyboard user focuses it, THEN its reason is announced.

## Verification gate

Every control renders its eight states; keyboard operability and role semantics asserted per control; focus ring visible on every surface in both themes; axe zero serious/critical; name/role/value snapshots recorded; height follows the density token in both modes.
