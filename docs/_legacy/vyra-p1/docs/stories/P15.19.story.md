## User story

COMO administrator, QUERO to manage tenants, internal users, role assignments and integrations and to read operational and security status, PARA administration is a governed surface rather than a shell session.

## Context

FR-C01, FR-C02, FR-C08 and FR-C09 fix these views. `api-contracts.md` §5 makes tenant creation `SUPER_ADMIN`, role assignment `SUPER_ADMIN` with MFA required and audited, and consent revocation likewise. `security-architecture.md` §1.1 requires MFA for `ADMIN` and `SUPER_ADMIN`, which FF-23 asserts.

## Acceptance criteria

- **AC-1** Role assignment and consent revocation re-assert MFA before submission, matching the `api-contracts.md` §5 declaration and the RISK-11 mitigation.
- **AC-2** Tenant status changes use `PATCH /control/tenants/{id}/status` and are audited, per §5.
- **AC-3** Integration management surfaces social connection health from `api-contracts.md` §3.7 and provider configuration, and exposes no token value anywhere, since tokens exist only as ciphertext under FF-10.
- **AC-4** The status view renders auth failures, lockouts, authorization denials and secret findings, the Security dashboard content named in `observability.md` §5, without exposing the finding contents.
