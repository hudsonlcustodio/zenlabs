# Story P23.09 — Audit explorer, security surface and Control state coverage

## User story

COMO administrador, QUERO explorar a trilha de auditoria por ator, objeto e correlação, PARA que uma investigação seja uma consulta e não uma escavação.

## Context

`FR-C07` covers the audit trail and `ADR-0024` fixes audit and governance. `FF-11` makes it append-only and `FF-20` keeps sensitive material out of it — which means the UI must render a redacted field as `[redacted]` rather than as an empty cell, because an empty cell is indistinguishable from missing data. This story also carries the Control blueprint coverage gate.

## Acceptance criteria

- **AC-1** The audit explorer renders over the virtualised `P19.04` grid, filterable by actor, action, object, tenant, date range and **correlation id**, with cursor pagination and no edit or delete affordance (`FF-11`).
- **AC-2** An entry drawer renders the before/after diff where one exists; sensitive-action entries — consent revocation, usage adjustment, role change — are visually elevated so an investigation starts from them.
- **AC-3** **Redacted fields render as `[redacted]`, never as blank**, so an operator can distinguish redaction from absence (`FF-20`). A seeded blank redaction fails the assertion.
- **AC-4** The security surface of §33.10 renders the risk summary, active sessions, lockout and rate-limit state, and the read-only policy panel sourced from configuration; every action on it requires MFA re-assertion (`RISK-11`).
- **AC-5** Session revocation and forced MFA re-enrolment are available, destructive-guarded, and state that revocation applies on the user's next request.
- **AC-6** A coverage check enumerates every Control blueprint in §33 and asserts each has an implemented loading, empty, error and denied state, with the correct empty-state kind; a new Control route without them fails CI naming the route.
- **AC-7** The `md` read-only degraded mode of §22.1 is implemented for the ledger and audit surfaces, and the sub-`md` designed refusal renders for every Control route.

## BDD examples

- EX-P23-05 GIVEN an audit entry with a redacted field, WHEN it renders, THEN it shows `[redacted]` rather than an empty cell.
- EX-P23-22 GIVEN a correlation id, WHEN it is used as a filter, THEN every entry sharing it is returned across actors and objects.
- EX-P23-23 GIVEN a Control route added without a denied state, WHEN CI runs, THEN the coverage check fails naming the route.

## Verification gate

The virtualised audit explorer filters by all six dimensions including correlation id with no mutation affordance; the entry drawer renders diffs and elevates sensitive actions; redacted fields render as `[redacted]` and the assertion turns red on a seeded blank; the security surface renders with MFA-gated actions and honest revocation timing; the Control blueprint coverage check is green and turns red on a seeded missing state; the `md` read-only mode and sub-`md` refusal render.
