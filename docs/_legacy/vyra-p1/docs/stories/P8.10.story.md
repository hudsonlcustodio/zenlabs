# Story P8.10 — Domain event emission

- **Story ID**: `P8.10`
- **Epic**: `P8` (`docs/epics/epic-P8.md`)
- **Status**: `draft`
- **Wave**: 5
- **Priority**: P0

- **IMPLEMENTATION NOT STARTED**

## User story

COMO implementing agent, QUERO transitions to emit their declared events through the outbox, PARA downstream work is triggered reliably rather than by direct calls.

## Context

`architecture.md` §7 and §4.1 rule 2: cross-module communication is via published application services or domain events.

## Acceptance criteria

- **AC-1** Each transition emits exactly the events its declaration names, in the same transaction as the state change.
- **AC-2** Event payload types come from `packages/contracts`.
- **AC-3** No transition publishes directly to a queue; the P7.02 relay is the only publisher.

## BDD examples

- EX-P7-01 GIVEN a transition whose transaction rolls back, WHEN the relay runs, THEN its events are not published.

## Verification gate

Integration tests asserting event emission per transition.
