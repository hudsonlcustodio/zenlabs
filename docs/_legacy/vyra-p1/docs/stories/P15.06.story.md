# Story P15.06 — Portal script approval screen

## User story

COMO portal user, QUERO to read a proposed script and approve or reject it with a reason, PARA nothing is voiced in my name that I have not read.

## Context

This is the script review screen that `epic-P10`, `epic-P12` and `P12.03` all place out of their own scope. FR-P04 requires approval or rejection with a reason on rejection; `api-contracts.md` §3.2 exposes T05 and T06 as resource sub-actions rather than a generic RPC endpoint.

## Acceptance criteria

- **AC-1** The screen renders the script together with the retrieval and prompt-version trace that FR-IN05 makes available, so a reviewer can see what informed it.
- **AC-2** Approve posts to the T05 sub-action with an `Idempotency-Key`; reject posts to the T06 sub-action and cannot be submitted without a reason, per the T06 precondition.
- **AC-3** When the tenant policy is `AUTO`, the screen states that approval was applied by policy rather than presenting a control that does nothing (FR-AP06).
- **AC-4** A `state_transition_not_allowed` response renders as that stable code from `api-contracts.md` §1.1, not as a generic failure.

## BDD examples

- EX-P15-03 GIVEN a rejection submitted without a reason, WHEN the approval screen posts it, THEN the API refuses it and the screen renders the stable `validation_failed` code.

## Verification gate

Class 3 contract coverage of the T05 and T06 sub-actions from the rendered screen; class 6 coverage asserting only the portal user may invoke them.
