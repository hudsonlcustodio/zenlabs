# Story P1.09 — Worker process bootstraps: `worker-ai`, `worker-media`, `worker-social`

- **Story ID**: `P1.09`
- **Epic**: `P1` (`docs/epics/epic-P1.md`)
- **Status**: `done`
- **Wave**: 1
- **Priority**: P0
- **Story points**: 5
- **Depends on**: `P1.05`
- **IMPLEMENTATION COMPLETE**

## User story

COMO implementing agent, QUERO the three worker processes to exist as bootstrapped, stateless shells, PARA `P7.04`'s worker harness has three named hosts to run in and `apps/worker-social` stops being a process the architecture names and the backlog never creates.

## Context

`architecture.md` §2.1 fixes five processes. `apps/web` is bootstrapped by `P15.02`, `apps/api` by `P1.08`. The three workers were referenced as "affected surfaces" by `P7`, `P9`, `P10` and `P11` but created by nothing; `apps/worker-social` was never named anywhere in the backlog at all. This story closes that half of gap **G-01**. It creates process shells only — no queue consumer, no handler, no tenant context. `P7.04` fills them.

## Acceptance criteria

- **AC-1** `apps/worker-ai`, `apps/worker-media` and `apps/worker-social` each boot as a long-running process with typed configuration from `packages/config`, failing fast and non-zero on a missing key.
- **AC-2** Each process declares its responsibility and its intended queue set exactly as tabulated in `architecture.md` §2.1 and `aws-topology.md` §6, as a machine-readable manifest — not as a comment — so `P7.04` and `P17` consume one source instead of two.
- **AC-3** Each process implements graceful shutdown on `SIGTERM`: it stops accepting new work, drains in-flight work within a bounded timeout, and exits zero. A test asserts the exit code and the drain bound.
- **AC-4** Each process exposes a liveness signal carrying the running commit SHA (`cicd.md` §3) without opening an HTTP port that serves product data.
- **AC-5** Each process is stateless: a test asserts no local filesystem write during boot or during an idle cycle (`NFR-11`).
- **AC-6** The `P1.03` dependency assertion covers all three processes; at this point each may depend only on `packages/config` and `packages/observability`.

## BDD examples

- EX-P1-07 GIVEN a worker receives `SIGTERM` while idle, WHEN it shuts down, THEN it exits zero within the configured drain bound.
- EX-P1-08 GIVEN a worker manifest names a queue that does not exist in `aws-topology.md` §6, WHEN CI runs, THEN the manifest assertion fails naming the queue.

## Verification gate

All three processes boot and shut down cleanly in CI; the queue manifest assertion is green against `aws-topology.md` §6; the dependency edge set for each matches its declared manifest; the fail-fast boot test exits non-zero on a missing key.
