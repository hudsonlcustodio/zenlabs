## User story

COMO platform operator, QUERO retry policy applied by the framework, PARA an unhealthy provider degrades one capability instead of the platform.

## Context

`provider-architecture.md` §5-§6 and `workflows-state-machines.md` §5 fix retry and dead-lettering. Per-transition retry budgets are declared by the workflow engine in P8 and consumed here.

## Acceptance criteria

- **AC-1** Retry with exponential backoff and jitter is framework behaviour, configurable per port.
- **AC-2** Only classes marked retryable by the taxonomy are retried; terminal failures are never retried.
- **AC-3** A circuit breaker opens on sustained failure and its state is observable.
- **AC-4** Retry counts and breaker thresholds come from configuration (FF-13), not from literals.

## BDD examples

- EX-P4-03a GIVEN a terminal error class, WHEN the framework handles it, THEN zero retries are attempted.
