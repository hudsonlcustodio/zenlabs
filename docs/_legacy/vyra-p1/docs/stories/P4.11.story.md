# Story P4.11 — Runtime credential resolver and FF-14 (Secrets Manager)

- **Story ID**: `P4.11`
- **Epic**: `P4` (`docs/epics/epic-P4.md`)
- **Status**: `draft`
- **Wave**: 2
- **Priority**: P0
- **Story points**: 5
- **Depends on**: `P4.06`
- **IMPLEMENTATION NOT STARTED**

## User story

COMO implementing agent, QUERO every runtime credential to arrive through one resolver backed by Secrets Manager, and the direct-environment path to be banned by lint, PARA the ban lands before ten provider adapters exist rather than after.

## Context

`ADR-0022` fixes Secrets Manager + KMS + IAM least privilege. `FF-14` — *"runtime credentials come from Secrets Manager"* — had **no owning story**: it appeared exactly twice in the backlog, both times as an *out of scope* deferral in `P1.05` and `P1.07` pointing at epic `P16`, which never claimed it. That is gap **G-02**, and this story closes it.

`P4` is the correct home and wave 2 is the correct time. `P4` is where credential-mode behaviour is first written (`P4.06`, `PROVIDER_MODE`), and `FF-14`'s check is an ESLint ban on `process.env.<PROVIDER>_API_KEY` outside the resolver — exactly the kind of rule that becomes unpayable if it arrives after `P4`'s ten adapters, `P11`'s live media adapters and `P13`'s live social adapters. By wave 10 the violation surface would be the whole provider layer.

## Acceptance criteria

- **AC-1** A single `SecretResolver` in `packages/config` is the only code path that reads a runtime credential. It resolves from AWS Secrets Manager in `PROVIDER_MODE=live`, and from an explicitly fake, non-secret fixture set in `mock` — a fixture that cannot be mistaken for a real credential by shape.
- **AC-2** `FF-14` exists as an ESLint rule: any read of a credential-shaped environment key (`*_API_KEY`, `*_SECRET`, `*_TOKEN`, `*_PRIVATE_KEY`) **outside** the resolver module is an error, in `apps/*` and `packages/*` alike. A seeded violation turns the rule red naming the file and the key.
- **AC-3** The resolver caches a resolved secret in memory for a bounded TTL, never writes it to disk (`NFR-11`), never logs it, and returns it through a type that the redaction layer recognises so `FF-20` cannot be bypassed by interpolation.
- **AC-4** Secret paths are environment-scoped by construction: the resolver composes the path from the environment name, making a cross-environment credential inexpressible rather than merely discouraged (`NFR-12`, `aws-topology.md` §7).
- **AC-5** Rotation is non-disruptive: when a secret version changes, the next resolution after the TTL picks it up without a process restart, and a resolution failure fails the call with `provider_unavailable` rather than falling back to a stale or environment-sourced value.
- **AC-6** No test, fixture or CI job holds a live credential; `FF-08` and `FF-19` remain green with this story merged.

## BDD examples

- EX-P4-11 GIVEN a module outside the resolver reads `HEYGEN_API_KEY` from the environment, WHEN CI runs, THEN FF-14 fails naming the file and the key.
- EX-P4-12 GIVEN `PROVIDER_MODE=mock`, WHEN a credential is resolved, THEN the value comes from the fake fixture set and no AWS call is made.
- EX-P4-13 GIVEN a resolved secret is interpolated into a log line, WHEN the redaction layer runs, THEN the value is replaced and the raw value never reaches the sink.

## Verification gate

`FF-14` present in the fitness suite and green; the seeded violation turns it red; a mock-mode resolution makes zero AWS calls; a redaction fixture confirms no resolved secret survives the logger; `FF-08` and `FF-19` still green.
