## User story

COMO cliente novo, QUERO saber exatamente o que falta e quem está agindo em cada passo, PARA que a espera por algo que a VYRA faz nunca pareça uma tarefa minha esquecida.

## Context

`VYRA_PRODUCT_EXPERIENCE.md` §30.1 fixes the six-step activation spine and the rule that separates a premium managed service from a self-serve tool: a step VYRA owns says so and gives the client no false agency. Steps 3 and 4 depend on external gates (`GATE-HG02`, `GATE-EL01`) and must be honest about that without exposing provider names (PD-01).

## Acceptance criteria

- **AC-1** The six steps of §30.1 render as an ordered checklist with per-step state — `todo`, `waiting on VYRA`, `blocked`, `done` — and each states **what it unlocks**, not merely that it is incomplete.
- **AC-2** Steps VYRA owns (Digital Twin provisioning, voice clone) render `waiting on VYRA` with elapsed time and **no client action**. No disabled button hints at an action the client does not have.
- **AC-3** Consent (step 2) blocks every generation path and says so; knowledge (step 5) **warns and never blocks**, per §30.1. The blocking/non-blocking distinction is data, not copy.
- **AC-4** A VYRA-owned step exceeding its expected duration switches to an explicit "we're on it" state with a contact action, so silence is never the client's experience of a delay.
- **AC-5** The onboarding surface is the Portal home until it completes, then collapses into the Account section; the transition is one-way and is not re-shown.
- **AC-6** Completion renders the §30.4 moment exactly once: the only use of `display-2xl` in the product, one action — request the first content item — and no repeat.
- **AC-7** The whole flow is operable on a 320px viewport by keyboard, including the consent scroll-to-end gate and any file upload.

## BDD examples

- EX-P21-11 GIVEN a step VYRA owns, WHEN it renders, THEN it shows elapsed time and exposes no client action.
- EX-P21-12 GIVEN onboarding completes, WHEN the completion moment renders, THEN it appears once and is never re-shown.
- EX-P21-13 GIVEN no knowledge source exists, WHEN the checklist renders, THEN it warns and does not block the request path.

## Verification gate

Six steps render with correct per-step state and unlock statements; VYRA-owned steps expose no client action; the blocking/warning distinction is data-driven; the overdue state renders with a contact action; the completion moment fires exactly once; the flow completes at 320px by keyboard.
