## User story

COMO architect, QUERO AI disclosure declared through the official mechanism or the publication blocked, PARA no post ever hides that it was generated by VYRA.

## Context

FR-SP04 requires official disclosure mechanisms where the platform provides them and forbids any mechanism that hides the AI-generated nature. `social-publishing.md` §3.2 states all VYRA output is AI-generated. GATE-TT02 leaves the TikTok AIGC wire mapping unconfirmed, so the adapter defines a `declareAiGenerated(...)` capability and the publication is blocked while the mapping is unresolved rather than guessed.

## Acceptance criteria

- **AC-1** The publish request builder sets the disclosure capability for every AI-generated item, on every platform that offers one (FF-15).
- **AC-2** When a platform requires disclosure and the mapping is unresolved, publication is **blocked**, not attempted and not silently skipped (GATE-TT02).
- **AC-3** No configuration key can suppress disclosure; keys matching `disableAiDisclosure|hideAiGenerated` are banned by the FF-15 grep.
- **AC-4** Disclosure resolvability is part of the dispatch pre-flight from `P13.06` (`social-publishing.md` §4), so the block happens before any platform call.

## BDD examples

- EX-P13-03 GIVEN an AI-generated item whose platform disclosure mapping is unresolved, WHEN publication is attempted, THEN it is blocked rather than published.

## Verification gate

FF-15 green in the CI fitness stage: the request-builder assertion, the blocked-publication guard test and the banned-config-key grep all pass, and a seeded suppression path turns FF-15 red.
