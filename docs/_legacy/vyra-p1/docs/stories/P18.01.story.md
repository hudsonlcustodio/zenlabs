## User story

COMO frontend engineer, QUERO um sistema de tokens em duas camadas ligado ao Tailwind, PARA que um componente só consiga expressar valores sancionados e uma mudança de identidade seja uma mudança de arquivo.

## Context

`VYRA_PRODUCT_EXPERIENCE.md` §4 fixes the token system and supersedes `ASM-BR01` — the assumption that no branding existed and that tokens would stay placeholders. This story is where the VYRA visual identity stops being a document and becomes the only way to express a colour, a size or a duration in the product.

## Acceptance criteria

- **AC-1** Two token layers exist and are distinguishable by name: **primitive** tokens hold raw values (`--vyra-lime-400`) and **semantic** tokens hold roles (`--vyra-accent-solid`). Both are exported as CSS custom properties **and** as a typed TypeScript object, generated from one source so the two can never drift.
- **AC-2** The complete token set of `VYRA_PRODUCT_EXPERIENCE.md` §4 exists: `bg`, `surface` (1–4 plus sunken and inverse), `border` (subtle, default, strong, accent, danger), `text` (primary, secondary, tertiary, disabled, on-accent, inverse), the lime and violet scales, and the semantic accent roles.
- **AC-3** A Tailwind preset maps every semantic token to a utility, and the preset **removes** Tailwind's default colour, spacing, radius and shadow scales so an unsanctioned utility does not exist to be typed.
- **AC-4** A **token lint** fails on: a raw colour literal (hex, `rgb`, `hsl`, named) in any component; a direct reference to a primitive token from a component; and any CSS length value outside the spacing scale from `P18.04`. It names the file, the line and the value.
- **AC-5** **PD-05 (restraint is the brand)** is made enforceable rather than aspirational. The accent budget rule of §4.5 is checkable: a lint rule flags more than one `accent-solid` fill within a single component subtree, and the violet budget's four sanctioned semantic families are declared as named semantic tokens rather than as free use of the violet scale.
- **AC-6** An export snapshot test records the full token set; adding, removing or renaming a semantic token is a deliberate snapshot update, never an accident.

## BDD examples

- EX-P18-01 GIVEN a component using a raw hex colour, WHEN the token lint runs, THEN it fails naming the file and the value.
- EX-P18-10 GIVEN a component importing `--vyra-lime-400` directly, WHEN the token lint runs, THEN it fails and points at the semantic role it should use instead.

## Verification gate

The token lint is green across `packages/ui` and turns red on a seeded raw colour and on a seeded primitive-token reference; the CSS and TypeScript exports are generated from one source and are asserted equal; the Tailwind preset exposes no default palette utility; the export snapshot matches.
