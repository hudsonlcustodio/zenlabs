## User story

COMO frontend engineer, QUERO overlays com foco preso, retorno de foco e sem empilhamento, PARA que nenhum usuário de teclado fique preso e nenhuma tela empilhe três camadas de decisão.

## Context

`VYRA_PRODUCT_EXPERIENCE.md` §16 fixes the container-selection table, six behavioural rules and the destructive-dialog treatment. The no-stacking rule is a product decision, not a technical limit: a dialog over a drawer over a page means the information architecture failed.

## Acceptance criteria

- **AC-1** Five overlay primitives exist with the widths of §16.1: dialog (440/560/720), drawer (480/640/840), bottom sheet (92vh max), popover (≤ 360) and tooltip.
- **AC-2** **No stacking**: one dialog or one drawer at a time. A dialog opened from a drawer replaces it and restores it on close, and the restore is asserted by test.
- **AC-3** Focus moves to the container on open — to the heading, not the first field, unless the container is a single-field form — is trapped for modal containers, and **returns to the invoking element** on close. Both are asserted for every primitive.
- **AC-4** `Escape` closes; when a form inside is dirty, `Escape` prompts instead of discarding. Header and footer are sticky; only the body scrolls.
- **AC-5** A drawer representing an object carries its own URL parameter so it is linkable and survives refresh, and closing it restores the previous URL.
- **AC-6** Destructive dialogs use `e5`, place the destructive control on the right, **never** focus it by default, and state the consequence as a sentence rather than a title.
- **AC-7** The scrim is `rgba(4,5,6,.72)` with at most 8px backdrop blur (§9.5), fading at `dur-base` and respecting reduced motion.

## BDD examples

- EX-P18-05 GIVEN a dialog is opened and closed, WHEN focus is inspected, THEN it returns to the invoking element.
- EX-P18-26 GIVEN a dialog opened from a drawer, WHEN the dialog closes, THEN the drawer is restored in its previous state.
- EX-P18-27 GIVEN a destructive dialog, WHEN it opens, THEN focus is not on the destructive control.

## Verification gate

Five primitives with correct widths and roles; focus trap and focus return asserted for each; no-stacking and drawer-restore asserted; dirty-form `Escape` prompts; drawer URL round-trips; destructive dialog focus and layout asserted; axe zero serious/critical for every primitive.
