## User story

COMO governance owner, QUERO sensitive actions recorded in the append-only audit trail, PARA who did what, when, and under which versions is answerable after the fact.

## Context

`security-architecture.md` §9 and ADR-0024. The table and its immutability came from P2.07; this story supplies the writes.

## Acceptance criteria

- **AC-1** Login, logout, MFA change, role change, session revocation and lockout each write an audit record.
- **AC-2** Records capture actor, action, subject, timestamp and the versions active at the time.
- **AC-3** Audit writes participate in the same transaction as the action, so a successful action without its record is impossible.

## BDD examples

- EX-P3-08a GIVEN a role change that fails to commit, WHEN the transaction rolls back, THEN no audit record survives claiming it happened.

## Verification gate

FF-11 plus integration assertions on each sensitive action.
