## User story

COMO security reviewer, QUERO uploads validated by content rather than by declaration, PARA a renamed executable or a decompression bomb is refused at the door.

## Context

`security-architecture.md` §7 and FR-KN05: malicious content, oversized documents and malformed uploads. FF-26 asserts the controls hold.

## Acceptance criteria

- **AC-1** Content type is verified against the actual bytes, not the declared type or extension.
- **AC-2** Size limits are enforced from configuration before the file is fully processed.
- **AC-3** Archive and compressed formats are bounded so a decompression bomb is refused.
- **AC-4** Rejections produce a stable error code and no partial artefact is left behind.

## BDD examples

- EX-P9-03 GIVEN an upload whose declared type does not match its content, WHEN it is received, THEN it is rejected before parsing.
