## User story

COMO platform operator, QUERO one queue and DLQ per worker with declared retry behaviour, PARA a poisoned message stops one flow instead of blocking everything.

## Context

`architecture.md` §2.1 defines `worker-ai`, `worker-media` and `worker-social`. `workflows-state-machines.md` §5 fixes retry, backoff and dead-lettering.

## Acceptance criteria

- **AC-1** Each worker has its own queue and DLQ; no queue is shared across workers.
- **AC-2** Visibility timeout, retry budget and backoff come from configuration (FF-13).
- **AC-3** Messages exceeding the budget land in the DLQ with their error class recorded rather than being dropped.
- **AC-4** Queue age is exposed as a metric so NFR-07 can trigger a review.

## BDD examples

- EX-P7-04 GIVEN a job exceeding its retry budget, WHEN the final attempt fails, THEN the message lands in the DLQ with its error class recorded.
