## User story

COMO tenant, QUERO metrics from different platforms mapped into one vocabulary, PARA I can read them side by side without pretending they are identical.

## Context

`provider-architecture.md` §1 declares `fetchMetrics(ExternalPostRef) -> RawMetrics` on the `PublishingProvider` port. `performance.md` §1 states platforms do not return the same metrics, so normalization maps what exists and leaves the rest `NULL`. `performance.md` §6 records that cross-platform aggregation sums non-equivalent quantities (ASM-PF01).

## Acceptance criteria

- **AC-1** Collection calls `fetchMetrics` through the port; no domain or application code imports a platform SDK (FF-02, FF-03).
- **AC-2** A per-platform mapper writes the normalized columns it can populate and leaves the others `NULL`, never zero (I-PF1).
- **AC-3** The unmapped remainder is preserved verbatim in `raw_payload` so the same payload can be re-normalized later without refetching (I-PF2).
- **AC-4** Each platform failure fixture maps to a declared error class in the P4 taxonomy, including `rate_limited` and `connection_invalid` (`api-contracts.md` §1.1).
- **AC-5** No mapper invents a field the platform did not return, and no cross-platform sum is computed in this module (ASM-PF01, `performance.md` §6).

## BDD examples

- EX-P14-04a GIVEN two platforms returning different metric sets, WHEN both are normalized, THEN each snapshot populates only its available fields and both retain their full raw payload.

## Verification gate

Class 4 adapter tests over recorded metric fixtures per platform plus class 1 unit tests of each mapper, all under `PROVIDER_MODE=mock` (FF-08).
