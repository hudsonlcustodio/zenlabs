# Story P22.10 — Cross-tenant performance experience

- **Story ID**: `P22.10`

## User story

COMO operador, QUERO comparar desempenho entre clientes a partir de snapshots, PARA que eu observe a operação inteira sem nunca disparar uma chamada a provedor.

## Context

`FR-S09` asks to observe performance across tenants. `FF-16` and `FR-PF05` apply identically here: the read path never calls a provider. `VYRA_PRODUCT_EXPERIENCE.md` §32.14 adds a client dimension and one rule the Portal does not need — a client with no publications appears with explicit zeros rather than being absent, so it cannot be overlooked.

## Acceptance criteria

- **AC-1** The screen renders the §31.11 composition plus a client dimension in the trend chart and a client column in the table; it is cross-tenant by default and scopes down through the client selector.
- **AC-2** Zero provider calls on open and on every filter change (`FF-16`).
- **AC-3** The snapshot-age stamp and gap semantics from `P19.02` apply unchanged; aggregates are labelled `indicative`.
- **AC-4** A client with no publications in the period renders with explicit zeros rather than being omitted from the table.
- **AC-5** Loading, filtered-empty, absent-by-design and error states render per region, and the table uses the `P19.03` grid with cursor pagination.

## BDD examples

- EX-P22-25 GIVEN a client with no publications in the period, WHEN the table renders, THEN it appears with explicit zeros.
- EX-P22-26 GIVEN a filter change, WHEN it is applied, THEN zero provider calls are recorded.

## Verification gate

Cross-tenant composition renders with a client dimension; zero provider calls on open and on filter change; snapshot age and gap semantics preserved; zero-publication clients appear with explicit zeros; region states and cursor pagination render.
