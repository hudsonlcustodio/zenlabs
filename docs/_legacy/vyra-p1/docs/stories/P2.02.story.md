# Story P2.02 — Migration tooling, role split and destructive-change detector

## User story

COMO platform operator, QUERO migrations applied by a privileged role that the application never uses, PARA the application role can be denied BYPASSRLS without breaking schema evolution.

## Context

`architecture.md` §5 requires `vyra_migrator` and `vyra_app` with the application role neither owning tables nor holding `BYPASSRLS`. `migrations.md` requires a destructive-change detector.

## Acceptance criteria

- **AC-1** `vyra_migrator` owns the schema and applies migrations; `vyra_app` has DML only and lacks `BYPASSRLS`.
- **AC-2** Forward migration runs cleanly against a restored snapshot.
- **AC-3** The destructive-change detector blocks a column or table drop pending explicit approval.
- **AC-4** Migration ordering is deterministic and re-running an applied migration is a no-op.

## BDD examples

- EX-P2-04 GIVEN a migration that drops a column, WHEN the detector runs, THEN the migration is blocked pending explicit approval.
