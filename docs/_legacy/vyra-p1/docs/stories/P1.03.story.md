# Story P1.03 — Boundary lint rules and FF-04 dependency-graph check

## User story

COMO architect, QUERO module and layer boundaries enforced mechanically, PARA a violation fails the build instead of becoming permanent debt.

## Context

`architecture.md` §4.1 states four dependency rules and §4.2 states the three-layer import direction. FF-04 requires the graph to be a DAG with declared edges only.

## Acceptance criteria

- **AC-1** Every module declares `allowedDependencies`; an undeclared edge fails lint.
- **AC-2** An import of another module's `infrastructure/` or `domain/` internals fails lint.
- **AC-3** `domain/` importing a provider SDK, `aws-sdk` or the ORM fails lint (rule exists now; targets appear in P2/P4).
- **AC-4** A dependency cycle fails FF-04 and the failure names both edges.
- **AC-5** The rules run in CI, not only in an editor.

## BDD examples

- EX-P1-01 GIVEN a cycle between two packages, WHEN CI runs, THEN FF-04 fails naming both edges.
- EX-P1-03a GIVEN an import of `../other-module/infrastructure/repo`, WHEN lint runs, THEN it is rejected.

## Verification gate

FF-04 passes on the clean tree and fails on each seeded violation.
