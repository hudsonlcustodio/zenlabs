## User story

COMO administrador, QUERO ver o impacto de uma mudança de plano antes de aplicá-la, PARA que reduzir um direito nunca bloqueie clientes por acidente.

## Context

`FR-C03` covers plans, entitlements and subscription state. Reducing an entitlement below a tenant's current consumption exhausts it immediately, which blocks new requests and approvals. `VYRA_PRODUCT_EXPERIENCE.md` §33.4 requires an impact preview and explicit acknowledgement. `ADR-0029` leaves payment an extension point, and `FR-BL05` makes that deliberate — the UI must say so.

## Acceptance criteria

- **AC-1** Plan list and plan detail render with an entitlement table and the list of assigned tenants; plan states are `draft`, `active` and `retired` and a retired plan cannot be newly assigned.
- **AC-2** An **impact preview** computes, before submission, which assigned tenants would be affected by an entitlement change — specifically those whose current consumption exceeds the proposed entitlement — and requires explicit acknowledgement naming the count.
- **AC-3** Plan changes are MFA-gated and audited; the audit record captures the before and after entitlement values.
- **AC-4** The payment extension point is stated as **deliberately unimplemented** per `ADR-0029` and `FR-BL05` — not as "coming soon", not as a disabled button, but as a recorded architectural decision with its rationale.
- **AC-5** Subscription state per tenant renders `active`, `past_due`, `suspended` and `cancelled` (§21.4), each stating what it blocks for that tenant.

## BDD examples

- EX-P23-06 GIVEN an entitlement change that would fall below a tenant's current consumption, WHEN it is submitted, THEN an impact preview is shown and explicit acknowledgement is required.
- EX-P23-16 GIVEN the plans screen, WHEN the payment section renders, THEN it states the extension point as a deliberate decision rather than as pending work.

## Verification gate

Plan list and detail render with entitlements and assignments; the impact preview computes affected tenants and requires acknowledgement naming the count; plan changes are MFA-gated with before/after values audited; the payment extension point is stated as deliberate; the four subscription states render with what each blocks.
