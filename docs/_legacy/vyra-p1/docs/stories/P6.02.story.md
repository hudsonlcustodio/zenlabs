## User story

COMO implementing agent, QUERO reservations keyed so that duplication is structurally impossible, PARA idempotency does not depend on application code being careful.

## Context

`usage-ledger.md` §5 fixes the idempotency keys. ADR-0030 fixes the wider idempotency strategy. T08 acquires the reservation as a precondition.

## Acceptance criteria

- **AC-1** `usage_reservation` carries the idempotency key fixed by `usage-ledger.md` §5 with a unique index enforcing it.
- **AC-2** A reservation has an explicit state so held, committed and released are distinguishable.
- **AC-3** The T08 key `sha256(scriptVersionId+voiceCloneId+params)` is representable exactly as specified.
- **AC-4** Concurrent identical reservation attempts result in one row, with the loser observing the existing reservation rather than failing the request.

## BDD examples

- EX-P6-02a GIVEN two concurrent identical reservation attempts, WHEN both execute, THEN exactly one reservation row exists.

## Verification gate

Class 10 idempotency tests green for the reservation key.
