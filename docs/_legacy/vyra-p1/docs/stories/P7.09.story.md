# Story P7.09 — FF-28 generation idempotency check

- **Story ID**: `P7.09`

## User story

COMO architect, QUERO a check that generation paths declare and use an idempotency key, PARA the duplicate-submission failure mode cannot be reintroduced.

## Context

FF-28 requires every generation to be idempotent. The keys are fixed by `workflows-state-machines.md` T08 to T11 and `usage-ledger.md` §5.

## Acceptance criteria

- **AC-1** A generation path without a declared idempotency key fails FF-28, naming the path.
- **AC-2** The declared key must be one enforced by the P7.05 table rather than an ad hoc string.
- **AC-3** The check runs in the fitness-function stage from P1.06.

## BDD examples

- EX-P7-09a GIVEN a generation path with no declared idempotency key, WHEN CI runs, THEN FF-28 fails naming the path.

## Verification gate

FF-28 green on the clean tree and red on the seeded omission.
