## User story

COMO usuário, QUERO que condições que afetam tudo apareçam uma vez no topo com a próxima ação, PARA que eu descubra que meu plano acabou antes de preencher um formulário que será recusado.

## Context

`VYRA_PRODUCT_EXPERIENCE.md` §17.3 places whole-screen conditions at hierarchy level 3 and §31.0 enumerates the Portal's global states. The design principle is in §28.4: the screen never lets a user attempt an action the guard will refuse — which means the condition must be visible before the attempt.

## Acceptance criteria

- **AC-1** A global banner region under the topbar renders at most one banner at a time, ordered by severity, using the `P18.12` banner primitive.
- **AC-2** The condition set is declared as data and covers: subscription `past_due` and `suspended`, entitlement exhausted, consent revoked or superseded, Digital Twin not `active`, and — Studio and Control only — degraded or unavailable provider. Each carries its next action.
- **AC-3** A banner that blocks an action is paired with the action's own disabled state and reason, so the user meets the same explanation in both places rather than two different ones (§28.4).
- **AC-4** Provider degradation is **never shown in the Portal** (PD-01): the client sees the consequence in VYRA vocabulary, not the provider's health. A provider banner rendered on a Portal route fails the surface assertion.
- **AC-5** Banners are announced through the live region on first appearance, are dismissible only when informational, and are never dismissible when they block an action.

## BDD examples

- EX-P20-16 GIVEN a suspended subscription, WHEN any Portal route renders, THEN a non-dismissible banner states the condition and its next action.
- EX-P20-17 GIVEN a degraded provider, WHEN a Portal route renders, THEN no provider banner appears and the surface assertion passes.

## Verification gate

One banner at a time, severity-ordered; the declared condition set renders with its next action; a blocking condition also disables the corresponding action with the same reason; a provider banner on a Portal route fails the surface assertion; announcement and dismissibility rules asserted.
