# Story P23.06 — Usage ledger experience with the reservation chain

## User story

COMO administrador, QUERO ler o ledger de consumo com a cadeia de reserva, commit e release visível, PARA que uma divergência de consumo seja explicável linha a linha em vez de discutida.

## Context

`FR-C04` covers consumption ledgers per tenant. `ADR-0018` fixes the append-only ledger with reserve, commit and release points, `FF-11` makes it append-only and `FF-07` makes all consumption derive from it. `VYRA_PRODUCT_EXPERIENCE.md` §33.5 draws the consequence for the UI: there is no edit affordance anywhere, and a correction is a new entry called an adjustment.

## Acceptance criteria

- **AC-1** The ledger renders over the virtualised `P19.04` grid with a running balance column, filterable by tenant, period and entry type, with cursor pagination (`Newer`/`Older`).
- **AC-2** **No edit or delete affordance exists** anywhere on the surface. An `Record adjustment` action creates a **new entry**; the copy says adjustment, never correction or edit. A seeded edit control fails the append-only assertion (`FF-11`).
- **AC-3** Entry types are visually distinct: reservation held, commit, release and adjustment. A reservation is never presented as a charge.
- **AC-4** An entry drawer renders the **reserve → commit → release chain** for its generation attempt, so an operator can follow one attempt end to end (`ADR-0018`, T08/T11/T12).
- **AC-5** A commit is marked as final and non-reversible in the UI (T11 has no compensation), so no operator expects a reversal that the architecture forbids.
- **AC-6** Adjustments require MFA re-assertion, a reason, and produce an audit record; the ledger row links to that audit entry.

## BDD examples

- EX-P23-01 GIVEN any ledger or audit surface, WHEN it renders, THEN no edit or delete affordance exists.
- EX-P23-17 GIVEN a generation attempt, WHEN its entry drawer opens, THEN the reserve, commit and release entries for that attempt are shown as one chain.
- EX-P23-18 GIVEN a committed entry, WHEN it renders, THEN it is marked final and offers no reversal.

## Verification gate

The virtualised ledger renders with a running balance and cursor pagination; the append-only assertion turns red on a seeded edit control; the four entry types are visually distinct with reservations never shown as charges; the reserve/commit/release chain renders per attempt; commits are marked final; adjustments are MFA-gated, reasoned and audited with a link from the row.
