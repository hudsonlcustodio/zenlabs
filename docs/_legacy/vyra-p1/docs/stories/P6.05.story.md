# Story P6.05 — Plan catalogue and entitlement derivation

## User story

COMO administrator, QUERO plans and entitlements derived rather than hand-edited, PARA an entitlement can never drift from the plan that grants it.

## Context

FR-UC02 fixes Essential 15, Growth 30, Scale 60 and Enterprise custom. Module 16's invariant is that entitlement is derived, never hand-edited.

## Acceptance criteria

- **AC-1** The plan catalogue represents the four MVP plans with quantities as configuration (OQ-P6-01 for Enterprise).
- **AC-2** Entitlement for a period is derived from plan plus subscription state, with no directly writable entitlement field.
- **AC-3** Remaining capacity is computed as entitlement minus the ledger fold, never stored as an authoritative column.
- **AC-4** Plan changes take effect at the boundary fixed by the subscription's billing cycle rather than immediately mid-period.

## BDD examples

- EX-P6-05a GIVEN an attempt to write an entitlement value directly, WHEN it is made, THEN no such writable path exists.

## Verification gate

Integration tests asserting derivation and the absence of a writable entitlement.
