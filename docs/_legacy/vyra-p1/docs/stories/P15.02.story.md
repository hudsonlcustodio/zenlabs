## User story

COMO architect, QUERO Portal, Studio and Control served by one application behind role-based routing, PARA the three surfaces share authentication, contracts and design system instead of drifting into three products.

## Context

`prd.md` §5 defines three **logical** surfaces and brief §4 warns against building three systems. ADR-0003 fixes one Next.js App Router application hosting all three, with server components keeping authorization and data access server-side.

The shell those route groups render into — topbar, navigation rail, content and drawer regions, command palette, notification centre and global surfaces — is built by `P20` at wave 4, because a shell needs identity (`P3`) and primitives (`P18`, `P19`), not the domain. This story is the **routing and authorization** half: it creates the three route groups, resolves surface entry server-side, and registers every rendered route in the `P3.07` manifest.

## Acceptance criteria

- **AC-1** One application hosts the three surface route groups; no second deployable web application is created (ADR-0003).
- **AC-2** Surface entry is resolved server-side from the session role, never from a client-held claim (`api-contracts.md` §2).
- **AC-3** A session lacking the surface's role receives a denial from the server, not a redirect produced after rendering privileged data.
- **AC-4** Every rendered route registers in the P3.07 manifest so FF-17 can enumerate it, including the route groups' own entry routes.
- **AC-5** The three route groups render into the single `P20.01` shell composition, supplying only their surface label, rail item set, density and chrome. A per-surface shell fork in `apps/web` is a defect and the composition assertion from `P20.01` AC-1 covers `apps/web` as well as `packages/ui`.

## BDD examples

- EX-P15-01 GIVEN a `QA_REVIEWER` session, WHEN a Control screen route is requested, THEN the server denies it rather than rendering a filtered view.

## Verification gate

Class 6 authorization coverage for the surface entry routes; integration test asserting no privileged payload is emitted on a denied request.
