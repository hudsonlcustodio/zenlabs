## User story

COMO architect, QUERO one interface per external capability, PARA a vendor can be replaced without touching the domain.

## Context

`provider-architecture.md` §1 enumerates the ports. `architecture.md` §3 states external systems are reached only through `packages/providers`.

## Acceptance criteria

- **AC-1** Every port in `provider-architecture.md` §1 is declared, including the video, voice, LLM, social, storage and notification capabilities.
- **AC-2** Port signatures use only `packages/contracts` types; no vendor shape appears in a signature.
- **AC-3** `PaymentProvider` and `EmailProvider` exist as declared extension points with no implementation (ADR-0029, ADR-0027).
- **AC-4** Ports express capability, not vendor workflow, so a second vendor can satisfy the same interface.
- **AC-5** The package depends only on `packages/contracts`, verified by FF-04.

## BDD examples

- EX-P4-01a GIVEN a port signature, WHEN it is inspected, THEN every type it names is exported by `packages/contracts`.
