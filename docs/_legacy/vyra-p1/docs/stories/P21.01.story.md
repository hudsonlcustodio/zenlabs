## User story

COMO cliente, QUERO uma superfície que fale a minha língua e não a da máquina, PARA que eu experimente pedir, aprovar e observar resultados sem tocar em nenhum detalhe técnico.

## Context

PD-01 is the product's founding asymmetry: the client never sees the machine, while Studio and Control do. `prd.md` §1 states it as the core product principle. `VYRA_PRODUCT_EXPERIENCE.md` §2.2 fixes the Portal's two-level information architecture and §31.0 its shell chrome; §7.4 makes the Portal *comfortable* density.

## Acceptance criteria

- **AC-1** The Portal route group renders the `P20` shell with the Portal chrome of §31.0: surface label, `Request content` in the topbar on every screen, the notification bell, the account menu, and the Twin chip when the twin is not `active`.
- **AC-2** The two-level information architecture of §2.2 is implemented exactly — Overview, Content (Pipeline · Library), Calendar, Performance, Account (Plan & usage · Digital Twin · Consent · Profile & security) — and **approvals are not a navigation item**, because an approval is an event surfaced by the pipeline, the dashboard action rail and the notification centre.
- **AC-3** Comfortable density is applied at the surface root through the `P18.04` token override, with zero component-level branching.
- **AC-4** A **Portal vocabulary lint** runs over the `(portal)` route group and its string table and fails on any provider name, model identifier, queue name, job id, retry count, prompt reference or engine term. It names the file and the term.
- **AC-5** No client-facing URL carries a `tenantId` (`api-contracts.md` §1); an assertion enumerates every Portal route and fails on one that does.

## BDD examples

- EX-P21-01 GIVEN any Portal screen, WHEN the vocabulary lint runs, THEN no provider name, model identifier, queue, job id or retry count appears.
- EX-P21-10 GIVEN the Portal rail, WHEN it renders, THEN approvals appear as an event in the action rail and never as a navigation item.

## Verification gate

Portal chrome renders on every route; the §2.2 IA matches exactly; comfortable density is token-only; the vocabulary lint is green and turns red on a seeded provider name; no Portal route carries a `tenantId`.
