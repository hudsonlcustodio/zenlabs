# Story P1.06 — CI pipeline stages 1-5

- **Story ID**: `P1.06`
- **Epic**: `P1` (`docs/epics/epic-P1.md`)
- **Status**: `done`
- **Wave**: 1
- **Priority**: P0
- **Story points**: 5
- **Depends on**: `P1.03`
- **IMPLEMENTATION COMPLETE**

## User story

COMO platform operator, QUERO a pipeline that runs the verification stages in a fixed order, PARA every later fitness function has a place to be attached.

## Context

`cicd.md` defines stages 1-5. This story wires them on a repository that still has no application code.

## Acceptance criteria

- **AC-1** Stages 1-5 run in the documented order and the pipeline is red if any stage is red.
- **AC-2** Fitness functions are a first-class stage, not an optional job.
- **AC-3** The pipeline is green on the current application-free tree.
- **AC-4** The pipeline runs on pull request and on merge to `main`.
- **AC-5** No stage requires a provider credential (FF-08 precondition).

## BDD examples

- EX-P1-06a GIVEN a failing lint rule, WHEN the pipeline runs, THEN later stages do not report success.

## Verification gate

Pipeline green end-to-end; a seeded lint failure turns it red.
