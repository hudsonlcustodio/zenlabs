## User story

COMO estrategista de conteúdo, QUERO ver versões, comparar mudanças e saber quantas revisões restam, PARA que o orçamento de revisão nunca acabe de surpresa.

## Context

T07 caps script revisions at `maxScriptRevisions`; exceeding it moves the item to `BLOCKED`. `VYRA_PRODUCT_EXPERIENCE.md` §25.4 requires the budget to be visible and the last-revision consequence to be stated **before** it happens — a warning after the fact is worthless.

## Acceptance criteria

- **AC-1** The version rail lists every `ScriptVersion` with its state and author, newest first, with the current version marked. A rejected version carries its rejection reason attached to it.
- **AC-2** Any two versions compare in a side-by-side, read-only diff with word-level insert and delete marks in `status-success` and `status-danger` at 12% tint.
- **AC-3** The diff is navigable change-by-change with `n` and `p`, and each change is announced by a screen reader (§25.5).
- **AC-4** The revision budget renders as `Revisions n / m` sourced from `maxScriptRevisions`; at the last permitted revision the workspace states that the next rejection moves the item to `BLOCKED` (T07).
- **AC-5** A version that produced a downstream generation is marked as such and cannot be silently superseded — the rail states which version the current audio and video derive from.
- **AC-6** The whole rail and diff are keyboard operable, and the diff view is reachable from both the workspace and the Portal approval surface's `Compare` control (`P21.09` AC-1).

## BDD examples

- EX-P22-12 GIVEN the last permitted revision, WHEN the workspace renders, THEN it states that the next rejection moves the item to `BLOCKED`.
- EX-P22-13 GIVEN a diff between two versions, WHEN a screen-reader user presses `n`, THEN the next change is announced.

## Verification gate

The version rail lists versions with state, author and rejection reasons; word-level diff renders with correct tints; change-by-change keyboard navigation announces each change; the revision budget renders and warns before the final rejection; the version that produced the current media is identified; the diff is reachable from both entry points.
