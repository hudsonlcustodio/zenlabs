## User story

COMO administrador, QUERO gerenciar usuários internos e papéis sem conseguir me trancar para fora, PARA que governança de acesso não crie um incidente de acesso.

## Context

`FR-C02` covers internal users and role assignments. `P3.06` fixes the role model and `P3.02` opaque sessions with revocation. `VYRA_PRODUCT_EXPERIENCE.md` §33.3 adds the two protections that keep an administration screen from becoming an outage: self-demotion prevention and last-admin protection.

## Acceptance criteria

- **AC-1** The user grid renders over `P19.03` with role, status and MFA state; a user drawer shows roles, active sessions, MFA state and that user's audit history.
- **AC-2** A role matrix renders which roles hold which capabilities, sourced from the `P3.06` role model rather than from a duplicated UI table.
- **AC-3** Role changes require MFA re-assertion and are audited; **self-demotion is prevented** with an explanation, and the **last remaining administrator cannot be demoted or disabled**, also with an explanation.
- **AC-4** Session revocation is available per session and for all sessions of a user; the screen states that revocation takes effect on the user's next request, matching `P3.02`'s behaviour rather than implying instant termination.
- **AC-5** Invited, active and disabled states are distinct, and an invitation that has expired states it and offers re-invitation.

## BDD examples

- EX-P23-14 GIVEN the last remaining administrator, WHEN demotion is attempted, THEN it is refused with an explanation.
- EX-P23-15 GIVEN a session is revoked, WHEN the screen renders, THEN it states that revocation applies on the next request.

## Verification gate

User grid and drawer render with roles, sessions and MFA state; the role matrix derives from the role model; role changes are MFA-gated and audited; self-demotion and last-admin demotion are refused with explanations; session revocation states its timing; invitation states render distinctly.
