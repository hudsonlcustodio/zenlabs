## User story

COMO QA reviewer, QUERO a table-driven suite proving isolation for every client-owned table, PARA a new table without RLS fails the suite rather than passing unnoticed.

## Context

`testing-strategy.md` class 7 and §4: tenant fixtures always create at least two tenants so isolation is observable by default.

## Acceptance criteria

- **AC-1** Fixtures seed at least two tenants for every run.
- **AC-2** The suite enumerates client-owned tables from the schema and asserts read and write denial across tenants for each.
- **AC-3** Every repository path is exercised, not only direct SQL.
- **AC-4** Adding a client-owned table without RLS causes a failure without editing the suite.

## BDD examples

- EX-P2-01 GIVEN two seeded tenants, WHEN tenant A attempts to read tenant B by any repository path, THEN the attempt returns nothing.

## Verification gate

Class 7 suite green; seeded unprotected table turns it red.
