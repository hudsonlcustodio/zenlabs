# Story P11.06 — INGESTING state with retry budget and reconciler

## User story

COMO operations manager, QUERO ingestion modelled as its own state with its own recovery, PARA generated and stored are distinguishable facts rather than one implied step.

## Context

ADR-0034 and FR-WF02. T11a copies and verifies, T11b exhausts the budget into BLOCKED preserving the provider reference, T11c is operator-driven ingestion retry only.

## Acceptance criteria

- **AC-1** The copy from the provider asset into VYRA-owned S3 is verified by checksum before T11a creates the `MediaAsset`.
- **AC-2** The ingestion retry budget comes from configuration and uses exponential backoff.
- **AC-3** Budget exhaustion fires T11b: `ingestion_failed`, provider reference preserved, usage committed, no release, no automatic re-render.
- **AC-4** T11c allows an `OPERATIONS_MANAGER` to retry ingestion only, using the preserved reference.
- **AC-5** A reconciler detects items stuck in `INGESTING` and escalates them for manual recovery.
- **AC-6** The manual-recovery path has a runbook entry, delivered in P16.03.

## BDD examples

- EX-P11-02 GIVEN a completed render whose asset copy fails until the budget is exhausted, WHEN T11b fires, THEN usage stays committed, the provider reference is preserved and no second render is submitted.
- EX-P11-04 GIVEN an operator retrying ingestion after T11b, WHEN T11c runs, THEN exactly one commit and one submission still exist.
