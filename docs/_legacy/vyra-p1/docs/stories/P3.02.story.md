## User story

COMO administrator, QUERO sessions that I can kill immediately, PARA a compromised session ends when I say so, not when a token expires.

## Context

ADR-0005 chooses opaque server-side sessions precisely so revocation is authoritative. Module `identity` carries the invariant that a session is revocable at any time.

## Acceptance criteria

- **AC-1** Session identifiers are opaque and carry no embedded claims.
- **AC-2** Every request resolves the session server-side and honours the revocation marker.
- **AC-3** Revocation takes effect on the next request with no cache window that outlives it.
- **AC-4** Session cookies are set with the flags fixed by `security-architecture.md` §1.

## BDD examples

- EX-P3-01 GIVEN a session revoked by an administrator, WHEN the holder issues the next request, THEN it is rejected.
