# Story P16.06 — `NotificationProvider` with in-app delivery; `EmailProvider` deferred

## User story

COMO portal user, QUERO to be told in-app when something needs me or something failed, PARA I am not the last to know, and without VYRA picking an email vendor arbitrarily to achieve it.

## Context

ADR-0027 defines two ports and defers only the vendor: `NotificationProvider` for channel-agnostic dispatch and `EmailProvider` for transport, with GATE-NOTIF01 holding the vendor decision open. FR-NT02 forbids choosing one without an ADR. `P4.01` already declares the notification capability among the ports; `P3.01` defers password reset delivery here. MVP ships in-app only, which needs no vendor.

## Acceptance criteria

- **AC-1** Every trigger in FR-NT01 routes through `NotificationProvider`: script awaiting approval, video awaiting approval, generation failed, content published, low provider balance, social integration expiring, Voice Clone ready, Digital Twin active.
- **AC-2** The `notification` table from `database-schema.md` §3.7 records kind, recipient reference, payload, status, `sent_at` and attempts, and is tenant-scoped.
- **AC-3** Dispatch is consumed off the `notification-send` queue that `aws-topology.md` §6 already allocates to `worker-social`, with retry and DLQ behaviour identical to every other queue.
- **AC-4** `EmailProvider` remains declared and unimplemented; no vendor name, SDK or credential appears anywhere, per ADR-0027 and FR-NT02. GATE-NOTIF01 stays open and is recorded in the launch register in `P16.10`.
- **AC-5** Notification payloads carry no secret, token or document text, so `observability.md` §1 redaction rules are not the last line of defence.

## BDD examples

- EX-P16-05 GIVEN a script awaiting approval, WHEN the notification is dispatched, THEN it is delivered in-app through `NotificationProvider` and no `EmailProvider` implementation is invoked.

## Verification gate

Integration coverage asserting each FR-NT01 trigger produces exactly one `notification` row; class 9 coverage of retry and DLQ on `notification-send`; a static assertion that no `EmailProvider` implementation exists.
