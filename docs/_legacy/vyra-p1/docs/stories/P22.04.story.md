## User story

COMO operador, QUERO curar fontes de conhecimento e ver exatamente quais trechos sustentaram uma saída, PARA que eu possa auditar uma afirmação em vez de confiar nela.

## Context

`FR-S03` covers knowledge sources and their processing state; `knowledge-engine.md` §4 defines the retrieval trace. `FF-27` contains prompt injection through data-region isolation and output validation, and `RISK-06` is the reason: a knowledge source is untrusted client content. Making the owning tenant visible on every source is how an operator can see the isolation rather than assume it.

## Acceptance criteria

- **AC-1** The source grid renders per §32.6 with processing state from the closed set `uploaded`, `processing`, `indexed`, `partial`, `failed` (§21.4), rendered through the `P18.13` status components.
- **AC-2** Every source displays its **owning tenant**, and a cross-tenant source never appears in a scoped list. A seeded cross-tenant row fails the isolation assertion (`FF-27`, `RISK-06`).
- **AC-3** Upload uses the `P19.06` primitive: type and size validated before transfer with the reason stated on rejection, per-file progress, cancel per file, and no page blocking.
- **AC-4** A source drawer shows chunk previews, coverage summary and the processing history; a `partial` source states which portion failed and what that excludes from retrieval.
- **AC-5** The retrieval-trace screen of §32.7 renders the query, the ranked chunk list with scores, the chunk content, its source, and the generated output above with `term` marks linking down to the chunks that supported it.
- **AC-6** A chunk whose source has since been deleted states that fact in the row rather than resolving to a `404`, so a trace remains readable after retention acts on its source (`FF-31`).

## BDD examples

- EX-P22-05 GIVEN a knowledge source, WHEN it renders, THEN its owning tenant is visible and no cross-tenant source appears in the list.
- EX-P22-14 GIVEN a chunk whose source was deleted, WHEN the trace renders, THEN the row states the deletion rather than failing.
- EX-P22-15 GIVEN an unsupported file type, WHEN it is selected, THEN it is rejected before transfer with the reason stated.

## Verification gate

Five processing states render through the status components; owning tenant is visible on every source and the isolation assertion turns red on a seeded cross-tenant row; pre-transfer validation rejects with reasons; the source drawer explains partial processing; the trace renders query, ranked chunks, source and linked output; a deleted source is stated rather than 404ed.
