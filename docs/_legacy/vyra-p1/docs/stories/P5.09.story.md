## User story

COMO governance owner, QUERO every governance action recorded with the versions active at the time, PARA FR-ID03 is answerable years later.

## Context

FR-ID03 requires audit of who approved, when, and which versions were active. The append-only table and write path already exist from P2.07 and P3.08.

## Acceptance criteria

- **AC-1** Consent grant, consent change, revocation, twin state change and voice clone state change each write an audit record.
- **AC-2** Each record names the actor, the timestamp and the identity element versions active at that moment.
- **AC-3** Audit writes share the transaction with the governance state change.

## BDD examples

- EX-P5-09a GIVEN a consent revocation, WHEN the audit trail is queried, THEN it names the actor, time and the active identity element versions.

FF-11 plus integration assertions per governance action.
