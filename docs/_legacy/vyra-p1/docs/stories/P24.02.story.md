## User story

COMO implementing agent, QUERO que cada tela e cada jornada sejam completáveis apenas com teclado, PARA que operabilidade não dependa do mouse em nenhum ponto do produto.

## Context

`VYRA_PRODUCT_EXPERIENCE.md` §23.3 fixes the interaction rules and §34 C-04/C-05 make them screen-level criteria. The failure mode this story exists to catch is specific: accessible primitives composed into an inaccessible screen — a focus trap that never releases, a drawer that drops focus to the body, a grid whose rows are unreachable.

## Acceptance criteria

- **AC-1** A traversal test per screen asserts every interactive element is reachable in DOM order, that tab order matches visual order, and that no focus trap exists outside a modal container.
- **AC-2** A focus-return test opens **every** overlay each screen can open and asserts focus returns to the invoking element on close, including the drawer→dialog→drawer restore path from `P18.11` AC-2.
- **AC-3** Complex interactions are covered end-to-end by keyboard: grid navigation across a virtual boundary, board drag with `Space`/arrows/`Escape`, calendar two-dimensional navigation, editor node insertion and diff navigation, and the media player's full keyboard map.
- **AC-4** Three **journey** tests run keyboard-only end to end: Portal request → approve → schedule; Studio script → submit → QA verdict; Control tenant suspension with MFA re-assertion.
- **AC-5** `:focus-visible` is asserted present on every interactive element on every screen in both themes, and a screen suppressing a focus ring fails naming the element.
- **AC-6** A disabled control that carries information is asserted focusable-but-`aria-disabled` with a discoverable reason (§23.3).

## BDD examples

- EX-P24-02 GIVEN any screen, WHEN a focus-return check runs over every overlay it opens, THEN focus returns to the invoking element in every case.
- EX-P24-09 GIVEN the Studio script workspace, WHEN a keyboard user inserts a node and navigates the diff, THEN both complete without a pointer.

## Verification gate

Per-screen traversal and focus-return suites are green; complex interactions complete by keyboard including virtual-boundary grid navigation and board drag; the three journeys complete keyboard-only; focus visibility asserted on every interactive element in both themes; informative disabled controls are discoverable.
