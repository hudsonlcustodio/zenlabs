## User story

COMO operations manager, QUERO to manage calendar and publication and observe performance across tenants, PARA scheduling problems are caught internally before a client sees a missed slot.

## Context

FR-S08 requires managing calendar and publication; FR-S09 requires observing performance across tenants. FR-PF05 and FF-16 still apply: cross-tenant observation reads snapshots, never providers. RISK-01 means TikTok reach may be restricted to `SELF_ONLY` until GATE-TT01 closes, and the surface must state that rather than imply reach.

## Acceptance criteria

- **AC-1** Publishing screens read and act through the calendar and publication contracts rather than writing publication state directly, so FF-29 deduplication stays the only mechanism.
- **AC-2** Cross-tenant performance reads snapshots only and makes zero provider calls (FF-16).
- **AC-3** Where a platform restriction applies — the TikTok `SELF_ONLY` case in RISK-01 — the screen states the restriction explicitly instead of implying public reach.
- **AC-4** Where AI disclosure is required and unresolved, the screen shows publication as blocked, matching the FF-15 guard rather than offering an override.
