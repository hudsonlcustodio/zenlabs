## User story

COMO operations manager, QUERO to observe generation queues and act on stuck work, and to manage Digital Twins and Voice Clones, PARA a stalled pipeline is something I can see and unblock rather than something a client reports.

## Context

This is the Studio screen referenced by `epic-P5` (Studio screens), `epic-P7` (queue observation) and `epic-P11` (Studio generation screens). FR-S05 requires observing and controlling generation queues with retry, cancel and requeue; FR-S04 requires managing the twin and voice clone lifecycles.

## Acceptance criteria

- **AC-1** Queue views render depth, oldest-message age, in-flight and DLQ depth, the queue metrics named in `observability.md` §3.
- **AC-2** Requeue, reconcile and ingestion-retry actions map exactly to `POST /studio/content-items/{id}/requeue`, `POST /studio/generation-attempts/{id}/reconcile` and `POST /studio/content-items/{id}/ingestion/retry` from `api-contracts.md` §4; the screen invents no operator action.
- **AC-3** The ingestion-retry control is presented as retrying the asset copy only and never as a re-render, matching the T11c semantics and guard G-5 that FF-32 protects.
- **AC-4** Twin provisioning and voice verification start use the §4 routes; the screen offers no path that could simulate or proxy provider voice verification, which FF-12 forbids.
- **AC-5** Every mutation from this screen writes an audit record, because `api-contracts.md` §4 requires an audit write on every internal mutation.
