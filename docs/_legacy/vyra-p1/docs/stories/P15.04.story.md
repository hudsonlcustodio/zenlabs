## User story

COMO portal user, QUERO one screen summarising pipeline state, consumption and recent performance, PARA I know where my content stands without opening four screens.

## Context

FR-P01 requires a dashboard summarising pipeline state, consumption and recent performance. Consumption is a ledger fold read through `GET /usage/current-cycle`; performance is read from snapshots only, because FR-PF05 and FF-16 forbid a provider call on dashboard open.

## Acceptance criteria

- **AC-1** The dashboard summarises pipeline state, consumption and recent performance, the three elements FR-P01 names.
- **AC-2** Consumption is read from the ledger-derived route in `api-contracts.md` §3.5 and never from a mutable counter (FR-UC05).
- **AC-3** Opening the dashboard triggers zero provider calls (FR-PF05, FF-16).
- **AC-4** No `tenantId` is sent in path, query or body; tenancy is derived server-side per the `api-contracts.md` §1 tenant-scoping rule.

## BDD examples

- EX-P15-04 GIVEN the performance screen is opened, WHEN it renders, THEN zero provider calls are recorded against the mock.

## Verification gate

Integration test asserting the dashboard issues no provider call and no request carries a client-supplied tenant identifier.
