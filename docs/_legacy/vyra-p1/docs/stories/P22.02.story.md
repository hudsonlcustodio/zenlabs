## User story

COMO estrategista de conteúdo, QUERO um workspace onde briefing, conhecimento usado, tempo estimado e conformidade de marca fiquem visíveis enquanto escrevo, PARA que eu não descubra um problema só depois de submeter.

## Context

`FR-S02` and `FR-S07` make Studio the only place scripts are authored. `VYRA_PRODUCT_EXPERIENCE.md` §25.3 fixes the three-pane layout and §25.4 the behaviours: autosave, live runtime estimate, knowledge provenance and brand compliance in the inspector. `P19.07` provides the editor primitive; this story is the workspace around it.

## Acceptance criteria

- **AC-1** The `L-workspace` of §25.3 renders: context pane (brief, objective, channel and format, brand rules, knowledge used, revision counter), the editor canvas, and the inspector (versions, runtime estimate, brand compliance).
- **AC-2** Autosave fires on a 2s idle or on blur and shows `Saved {relative}` in `mono-sm`; this is the **only** autosaving surface in the product. A save failure retains the local buffer and shows an inline error — the buffer is never discarded.
- **AC-3** The runtime estimate recalculates live from the spoken word count at the tenant's configured words-per-minute (`OQ-PX-02`, `ASM-P22-02`), excludes `direction` and `broll` nodes, and shows the delta against the channel's target duration.
- **AC-4** Knowledge provenance is visible: a `term` mark links to the supporting chunk, and hovering shows the source with a link to the retrieval trace (`knowledge-engine.md` §4). This is the operator-visible half of `FF-27`'s containment story.
- **AC-5** Brand compliance renders the last result with each failed rule quoted and a jump-to-offending-range control. It **never auto-edits** the script.
- **AC-6** Single-writer: opening a script another operator holds renders read-only with the holder's name and an audited `Take over` action (`ASM-P22-03`).
- **AC-7** `Submit for approval` is a pinned bar action; it is disabled with a stated reason when the script violates a schema cardinality rule or when the item's state does not permit submission.

## BDD examples

- EX-P22-06 GIVEN a script open in another operator's session, WHEN it is opened, THEN it renders read-only with the holder's name and an audited take-over.
- EX-P22-10 GIVEN a save failure, WHEN it occurs, THEN the local buffer is retained and an inline error is shown.
- EX-P22-11 GIVEN a `broll` node, WHEN the runtime estimate recalculates, THEN it is excluded from the spoken word count.

## Verification gate

The three-pane workspace renders with all declared regions; autosave shows relative save time and retains the buffer on failure; the runtime estimate excludes non-spoken nodes and shows the target delta; `term` marks link to their chunk and trace; compliance quotes failed rules and never auto-edits; take-over renders read-only and writes an audit record; submit disables with a stated reason where illegal.
