## User story

COMO architect, QUERO the performance module covered by the same three suites every client-owned surface gets, PARA a new metric table cannot ship without isolation and a guard.

## Context

`testing-strategy.md` §1 makes classes 3, 6 and 7 mandatory: every documented route validates against its schema, every route is exercised against every role, and for every client-owned table tenant A cannot reach tenant B by any repository path. `performance_snapshot` is client-owned, so it joins the table-driven tenancy suite.

## Acceptance criteria

- **AC-1** `GET /performance` validates request and response against the Zod schema in `packages/contracts` (class 3), and the committed OpenAPI matches (FF-18).
- **AC-2** The route declares a guard and appears in the authorization matrix for every role (class 6, FF-17).
- **AC-3** `performance_snapshot` is included in the table-driven tenancy suite so a missing policy fails the suite alongside FF-01 (class 7, `testing-strategy.md` §2).

## BDD examples

- EX-P14-05 GIVEN tenants A and B, WHEN A queries performance, THEN no snapshot belonging to B is reachable by any repository path.
