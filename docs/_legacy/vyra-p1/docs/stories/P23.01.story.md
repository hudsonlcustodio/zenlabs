## User story

COMO administrador, QUERO que toda ação sensível exija uma segunda afirmação de identidade, PARA que uma sessão comprometida não seja suficiente para revogar consentimento ou ajustar consumo.

## Context

`RISK-11` records that a compromised internal `SUPER_ADMIN` can revoke consent or adjust usage, with MFA re-assertion plus audit plus alarms as the accepted residual mitigation. `VYRA_PRODUCT_EXPERIENCE.md` §33.0 makes that mitigation visible: Control's chrome carries the re-assertion dialog and the audit notice, so the operator experiences the control rather than merely being covered by it.

## Acceptance criteria

- **AC-1** The Control route group renders the `P20` shell with Control chrome: surface label, command palette, notification bell, account menu, and dense density applied at the surface root.
- **AC-2** An MFA re-assertion dialog gates every action in the **sensitive-action set**, which is derived from the `P3.08` audit-write list as configuration rather than maintained by hand (`ASM-P23-02`). A sensitive action added to that list without a UI change is still gated.
- **AC-3** Re-assertion is time-bounded: a successful assertion covers a configured window, after which the next sensitive action re-asserts. The window is configuration, never a constant.
- **AC-4** Every sensitive action renders an audit notice stating that the action will be recorded and by whom, **before** it is taken — not afterwards.
- **AC-5** A matrix test enumerates the sensitive-action set and asserts each is gated; a seeded ungated sensitive action fails naming the action.

## BDD examples

- EX-P23-04 GIVEN a sensitive action, WHEN it is attempted, THEN MFA re-assertion is required and the completed action appears in the audit explorer.
- EX-P23-09 GIVEN a sensitive action added to the audit-write list, WHEN the matrix test runs, THEN it is required to be gated.

## Verification gate

Control chrome and dense density render on every route; the sensitive-action set is derived from configuration; every action in it is gated by re-assertion and the matrix test turns red on a seeded ungated action; the re-assertion window is configurable; the audit notice appears before the action.
