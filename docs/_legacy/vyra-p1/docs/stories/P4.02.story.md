# Story P4.02 — Provider error taxonomy

## User story

COMO implementing agent, QUERO one error classification every adapter maps onto, PARA retry, compensation and billing decisions are made on classes rather than on vendor strings.

## Context

`provider-architecture.md` §5 defines the taxonomy. The distinction between a terminal failure with no completed generation and other failures is what makes the billing rule in `usage-ledger.md` §2 expressible.

## Acceptance criteria

- **AC-1** The taxonomy distinguishes at minimum transient, rate-limited, authentication, validation and terminal classes.
- **AC-2** A terminal failure that produced no completed generation is distinguishable from every other outcome, because T12 depends on it.
- **AC-3** Unmapped vendor errors resolve to an explicit unknown class that is treated conservatively rather than as success.
- **AC-4** Error classes are exported from `packages/contracts` so the domain can branch on them without importing the provider package.

## BDD examples

- EX-P4-02 GIVEN a provider returning a rate-limit response, WHEN the adapter maps it, THEN the domain sees the taxonomy's rate-limit class and never the vendor payload.
