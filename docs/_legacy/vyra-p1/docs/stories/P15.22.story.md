# Story P15.22 — FF-17 conformance for every rendered route

- **Story ID**: `P15.22`

## User story

COMO architect, QUERO FF-17 to enumerate rendered routes as well as API routes, PARA the phase's acceptance gate is a build result rather than a review opinion.

## Context

`implementation-sequencing.md` Phase 14 sets the acceptance gate as FF-17 passing for every rendered route, with the definition of done that no screen relies on hidden UI for authorization. `P3.07` AC-3 already reserves `apps/web` server-side routes for this check; this story completes it now that the routes exist.

## Acceptance criteria

- **AC-1** FF-17 enumerates every registered `apps/web` server-side route alongside every `apps/api` route and asserts each declares a role or capability guard.
- **AC-2** A seeded unguarded rendered route turns FF-17 red naming the route, and the seed is removed after the assertion.
- **AC-3** The generated authorization matrix covers rendered `/control/*` and `/studio/*` surfaces with each role, matching the FF-17 mechanism.

## BDD examples

- EX-P15-06 GIVEN a rendered route added without a guard declaration, WHEN CI runs, THEN FF-17 fails naming the route.

## Verification gate

FF-17 green on the clean tree and red on a seeded unguarded rendered route.
