## User story

COMO administrador, QUERO uma tela que responda se a plataforma está saudável e se algo está inseguro, PARA que eu não precise reunir esse quadro a partir de seis lugares.

## Context

`FR-C09` asks for operational and security status. `observability.md` §4 defines the alarm set and `P16.03` guarantees every alarm resolves to a runbook. `VYRA_PRODUCT_EXPERIENCE.md` §33.1 adds the launch gate register, and `ASM-P23-03` fixes its most important property: all twelve gates are open at MVP **by design** (`implementation-sequencing.md` §Rules 4), so the register must present that as the expected state and not as twelve defects.

## Acceptance criteria

- **AC-1** The `L-dashboard` of §33.1 renders four rows: active alarms, provider health strip plus queue tiles, NFR pressure gauges, and the launch gate register.
- **AC-2** Alarms sort by severity and **every alarm links to its runbook**; an alarm without a runbook link fails the resolution assertion, mirroring `P16.03`'s guarantee from the UI side.
- **AC-3** Pressure gauges render `NFR-06` (CPU/memory), `NFR-07` (oldest message age), `NFR-08` (database pressure) and `NFR-09` (disk) as **review triggers**, explicitly labelled as such rather than as autoscaling thresholds (`prd.md` §10).
- **AC-4** The gate register lists all twelve `GATE-*` with their blocked capability, owner and state, and states that open gates block production launch of the affected capability but never a phase (`implementation-sequencing.md` §Rules 4).
- **AC-5** Provider health renders from polled snapshots (`P16.05`) with the last successful sync time; no synchronous provider fetch is offered (`FF-16`).
- **AC-6** All-clear is not an empty page: each tile renders its own `absent-by-design` state so the operator can tell "healthy" from "not loaded".

## BDD examples

- EX-P23-07 GIVEN all twelve external gates open, WHEN the gate register renders, THEN it presents that as the expected MVP state with each gate's owner.
- EX-P23-10 GIVEN an alarm without a runbook link, WHEN the resolution assertion runs, THEN it fails naming the alarm.
- EX-P23-11 GIVEN a healthy platform, WHEN the board renders, THEN each tile shows an all-clear state rather than the page being empty.

## Verification gate

Four rows render in order; alarms sort by severity and every one resolves to a runbook; pressure gauges are labelled as review triggers; the twelve-gate register renders with owner and blocked capability and states the Rules-4 semantics; provider health shows last sync with no synchronous fetch; all-clear renders per tile.
