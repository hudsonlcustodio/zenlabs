## User story

COMO cliente, QUERO pedir conteúdo dizendo apenas o objetivo e o canal, PARA que a barreira para começar seja a menor possível e o detalhe seja opcional.

## Context

`api-contracts.md` §3.1 makes only `objective` and `channel` required — everything else is optional (`brief` §16, `FR-CR03`). `VYRA_PRODUCT_EXPERIENCE.md` §31.4 turns that contract into a composer where the optional block is disclosed rather than presented, and §13.1 inverts the required/optional marking polarity for exactly this form.

## Acceptance criteria

- **AC-1** The composer renders as a 640px drawer at `≥ md` and a full page below, with the required block first and an `Add details` disclosure containing subject, campaign, references, guidance, format, priority and desired date.
- **AC-2** Marking polarity inverts per §13.1: because the majority of fields are optional, required fields carry a `Required` tag.
- **AC-3** The channel selector lists **connected channels only**; a disconnected channel renders with a connect action rather than being silently absent, so the client learns why an option is missing.
- **AC-4** Submission blocks are pre-empted, never discovered on submit: `entitlement_exhausted`, `consent_revoked` and a suspended subscription each disable submit with the reason and a link to the relevant screen, matching the global banner from `P20.07` AC-3.
- **AC-5** Submission sends `Idempotency-Key`; a retry reuses it and an `idempotency_key_reuse` response resolves to the created item rather than an error (`P18.09` AC-5).
- **AC-6** On success the drawer closes, the new item appears in the pipeline with a one-shot highlight, and a toast offers `View item` — the toast is a convenience, and the screen already shows the outcome (§17.2).

## BDD examples

- EX-P21-17 GIVEN entitlement is exhausted, WHEN the composer renders, THEN submit is disabled with the reason and a link to the plan screen.
- EX-P21-18 GIVEN a double submission, WHEN the second request arrives, THEN it resolves to the same content item.
- EX-P21-19 GIVEN a disconnected channel, WHEN the channel selector renders, THEN it appears with a connect action rather than being omitted.

## Verification gate

Required and optional blocks render per §31.4 with inverted marking; only connected channels are selectable and disconnected ones offer connection; each blocking condition disables submit with a matching reason; idempotent retry resolves to the same item; success updates the pipeline and offers a non-load-bearing toast.
