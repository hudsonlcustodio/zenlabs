## User story

COMO QA reviewer, QUERO every transition tested for four cases, PARA the most rule-dense part of the system has no untested edge.

## Context

`testing-strategy.md` class 5: every transition T01-T23 including T11/T11a/T11b/T11c, tested for allowed actor, unauthorized actor, precondition violation and repeat trigger.

## Acceptance criteria

- **AC-1** Every transition in the table has all four cases asserted; a transition missing a case fails the suite.
- **AC-2** The suite is driven by the transition declarations so a new transition without tests fails rather than passes.
- **AC-3** T11, T11a, T11b and T11c are covered explicitly, not folded into a generic render case.
- **AC-4** The suite runs on every pipeline execution per `testing-strategy.md` §6.

## BDD examples

- EX-P8-03 GIVEN an actor not listed for a transition, WHEN the suite runs, THEN the denial is asserted.
- EX-P8-05 GIVEN T11b, WHEN the suite runs, THEN the preserved provider reference and absence of a second render are asserted.
