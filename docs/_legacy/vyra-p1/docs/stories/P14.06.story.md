## User story

COMO portal user, QUERO my performance view to load from stored data, PARA it is fast and never rate-limited by the platform that also has to publish my next post.

## Context

FR-PF05 forbids dashboards from triggering synchronous provider calls on every open. `performance.md` §4 states dashboards read **only** from `performance_snapshot`, which bounds NFR-03 and prevents dashboard traffic from consuming platform rate limits. `api-contracts.md` §3.5 fixes the route.

## Acceptance criteria

- **AC-1** `GET /performance?contentItemId=&platform=&window=` serves exclusively from `performance_snapshot`, with the filters allowlisted per `api-contracts.md` §1.
- **AC-2** The handler performs no provider call on any code path, synchronous or deferred-but-awaited (FR-PF05).
- **AC-3** Results are returned per platform; the module computes no cross-platform aggregate (ASM-PF01, `performance.md` §6).
- **AC-4** The tenant is derived server-side from the session and never accepted from client input (`api-contracts.md` §1).

## BDD examples

- EX-P14-01 GIVEN a performance request, WHEN the endpoint serves it, THEN zero provider calls are observed against the mock.

## Verification gate

Class 3 contract test for the route with the mock provider asserting a zero call count, and read latency held within NFR-01.
