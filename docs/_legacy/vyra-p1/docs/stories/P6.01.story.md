## User story

COMO platform operator, QUERO consumption recorded as append-only entries, PARA history can be audited and recomputed rather than trusted.

## Context

`usage-ledger.md` §1 and §3. FF-11 covers ledgers and audit together; the append-only guarantee is enforced at the database level as in P2.07.

## Acceptance criteria

- **AC-1** `usage_ledger_entry` carries tenant, subscription period, attempt reference, entry kind, quantity and timestamp per `usage-ledger.md` §3.
- **AC-2** UPDATE and DELETE are rejected at the database level for `vyra_app`.
- **AC-3** The table is tenant-scoped and covered by FF-01.
- **AC-4** Quantity is stored in a unit that makes the minimum-billable-duration policy applicable without a schema change (FR-UC08).

## BDD examples

- EX-P6-01a GIVEN an existing ledger entry, WHEN an UPDATE is attempted as `vyra_app`, THEN the database rejects it.
