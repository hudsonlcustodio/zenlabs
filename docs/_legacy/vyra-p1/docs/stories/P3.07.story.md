## User story

COMO architect, QUERO a machine-readable manifest of routes and their guards, PARA an unguarded route fails the build instead of shipping.

## Context

FF-17 requires every administrative route to be authorized server-side. The manifest is what makes the check enumerable rather than a review habit.

## Acceptance criteria

- **AC-1** The manifest is generated from the routes themselves, not hand-maintained.
- **AC-2** A route with no guard declaration fails FF-17, naming the route.
- **AC-3** The check covers `apps/web` server-side routes as well as `apps/api`, since P15 renders authorized screens.
- **AC-4** The manifest is an artefact of the build, available to the class 6 suite.

## BDD examples

- EX-P3-02 GIVEN a route added without a guard declaration, WHEN CI runs, THEN FF-17 fails naming the route.

## Verification gate

FF-17 green on the clean tree and red on a seeded unguarded route.
