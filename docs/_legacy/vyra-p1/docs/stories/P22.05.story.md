# Story P22.05 — Generation queue console

## User story

COMO gerente de operações, QUERO observar e controlar as filas com idade visível e apenas as ações que o motor permite, PARA que eu resolva problemas sem nunca causar um render cobrado indevidamente.

## Context

`FR-S05` covers observing and controlling generation queues. `NFR-07` makes oldest-message age above 60s a review trigger. The hard constraint is `FF-32` and guard G-5: an ingestion failure never triggers a new billable render — only `INGESTING` retry (T11a) or an explicit operator ingestion retry (T11c) may follow T11b. A console that offers a generic retry here would silently violate the architecture's strongest billing guarantee.

## Acceptance criteria

- **AC-1** Queue summary tiles render one per queue from `aws-topology.md` §6, each showing depth and **oldest-message age** against the `NFR-07` threshold, escalating from neutral to warning to danger.
- **AC-2** A job grid lists attempts with their state, queue, tenant, elapsed time and error class, filterable and sortable, over the `P19.03` data grid.
- **AC-3** A job drawer shows the attempt timeline, the error class and the legal next actions for that state — and **only** those. Legality is supplied as data derived from the transition table, never inferred by the screen.
- **AC-4** **No re-render control exists for an ingestion failure.** For a `BLOCKED(ingestion_failed)` attempt the only offered action is the operator ingestion retry (T11c); the drawer states that usage stays committed, that no automatic re-render will occur, and why (`FF-32`, `ADR-0034`, guard G-5). A seeded re-render control fails the no-rerender assertion.
- **AC-5** DLQ contents are visible per queue with a redrive action that links to the `P16.03` runbook; a non-empty DLQ raises the tile to danger.
- **AC-6** Bulk actions over selected jobs offer only actions legal for **every** selected job (`P19.03` AC-5), and each bulk action states how many jobs it will affect before executing.
- **AC-7** The console makes no provider call: queue and job state come from VYRA-side records, and provider state comes from reconciliation loops (`P7.07`), so the screen states the last reconciliation time rather than fetching.

## BDD examples

- EX-P22-01 GIVEN an ingestion failure, WHEN the job drawer renders, THEN no control exists that would create a new billable render.
- EX-P22-07 GIVEN a queue whose oldest message exceeds the NFR-07 threshold, WHEN the console renders, THEN the queue tile shows the age and its severity.
- EX-P22-16 GIVEN a non-empty DLQ, WHEN the console renders, THEN the tile is danger and the redrive action links to its runbook.

## Verification gate

One tile per `aws-topology.md` §6 queue with depth and oldest age escalating at the NFR-07 threshold; the job grid filters and sorts; legal actions come from transition data; the no-rerender assertion is green and turns red on a seeded control; DLQ visibility and runbook link present; bulk actions restricted and counted; zero provider calls from the console.
