## User story

COMO portal user, QUERO a second factor on my account, PARA a stolen password alone cannot approve content in my name.

## Context

`security-architecture.md` §1.1. The portal user is also the identity owner, so account takeover is an identity-abuse vector, not only a data risk.

## Acceptance criteria

- **AC-1** Enrolment produces a secret that is stored encrypted and never re-displayed after confirmation.
- **AC-2** Enrolment is confirmed by a successful challenge before MFA is marked active.
- **AC-3** Challenge verification rejects replay of a code already consumed within its window.
- **AC-4** MFA state changes are audited (P3.08).

## BDD examples

- EX-P3-03a GIVEN a TOTP code already used, WHEN it is presented again inside its window, THEN it is rejected.

## Verification gate

Integration tests green including replay rejection.
