## User story

COMO platform operator, QUERO the generation and ingestion transitions implemented exactly, PARA the consumption rule and the ingestion separation hold at the transition level.

## Context

`workflows-state-machines.md` T08-T12 plus T11a, T11b and T11c. §2.4 expresses the consumption rule as transitions: T08 reserves, T11 commits, T12 releases, T11b keeps the commit. ADR-0034 is the reason `INGESTING` exists.

## Acceptance criteria

- **AC-1** T08 acquires the usage reservation with the exact key `sha256(scriptVersionId+voiceCloneId+params)`.
- **AC-2** T11 commits usage and records provider cost when the provider reports a completed billable generation, and declares no compensation because the commit is final.
- **AC-3** T11a creates the `MediaAsset` only after the asset is copied into VYRA-owned storage and its checksum verified.
- **AC-4** T11b preserves `providerJobId` and the provider asset reference, raises `ingestion_failed`, keeps usage committed, performs no release and triggers no automatic re-render.
- **AC-5** T11c allows an `OPERATIONS_MANAGER` to retry ingestion only, using the preserved reference.
- **AC-6** T12 releases the reservation only when the provider failure produced no completed billable generation.

## BDD examples

- EX-P8-04 GIVEN a provider that completed a billable generation, WHEN T11 fires, THEN usage is committed and no compensation path exists to reverse it.
- EX-P8-05 GIVEN the ingestion retry budget exhausted, WHEN T11b fires, THEN the item is BLOCKED with the provider reference preserved and no second render is submitted.
