## User story

COMO platform operator, QUERO VYRA provider cost recorded separately from client consumption, PARA revenue minus provider cost is computable later without conflating the two.

## Context

FR-PC01 separates the concepts; module 19's invariant is that client usage and VYRA cost never share a row. FR-PC02 lists HeyGen, ElevenLabs, LLM and allocable AWS. GATE-COST01 covers unconfirmed cost fields.

## Acceptance criteria

- **AC-1** `provider_cost_entry` records provider, attempt reference, cost amount, currency and the traceability needed by FR-PC03.
- **AC-2** The table is append-only and covered by FF-11.
- **AC-3** A cost that the provider does not expose is stored as null with an explicit reason rather than as a fabricated number (GATE-COST01).
- **AC-4** No row joins client consumption and VYRA cost into a single record.

## BDD examples

- EX-P6-04a GIVEN a provider that exposes no per-call cost, WHEN an entry is written, THEN cost is null with a recorded reason rather than estimated.

## Verification gate

Integration tests plus FF-11 for the table.
