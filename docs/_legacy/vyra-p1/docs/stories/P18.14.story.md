## User story

COMO frontend engineer, QUERO skeleton, empty e error como primitivos de primeira classe, PARA que as quatro telas que toda tela tem sejam projetadas uma vez e não improvisadas vinte vezes.

## Context

PD-09 states it plainly: every screen has four other screens. `VYRA_PRODUCT_EXPERIENCE.md` §18, §19 and §20 fix the loading selection table, the four kinds of empty state, the five error scopes and the disclosure rules that keep `not_found` indistinguishable from a cross-tenant object.

## Acceptance criteria

- **AC-1** A skeleton primitive is composed from the **same layout primitives** as real content, so geometry cannot drift. A geometry test compares the skeleton and loaded render of each composed region and fails on mismatch.
- **AC-2** Loading selection follows §18.1: skeleton where layout is known, inline spinner only inside buttons and ≤ 24px inline slots, determinate progress for measurable jobs, and a live state chip with elapsed time for indeterminate jobs. **No full-page spinner is expressible**, and no fake progress bar is offered for an indeterminate job.
- **AC-3** Skeletons display for at least 200ms and at most 8s, after which the region switches to its error state with a retry. Shimmer disables under `prefers-reduced-motion`.
- **AC-4** Four empty-state kinds exist and are distinct by API: `first-run` (one primary action), `filtered` (clear-filters primary), `absent-by-design` (no action), `restricted` (no action, no disclosure). Copy is required and a generic "No data" string fails the copy lint.
- **AC-5** Empty-state marks are geometric compositions built from tokens; a raster image, stock illustration or 3D asset in an empty state fails the asset lint (§19.2, closes `OQ-PX-05`).
- **AC-6** Five error scopes exist — field, form, region, page, global — each rendering the §20.2 anatomy: what happened, what to do, the recovery action, the stable `code` chip and a copyable correlation id. A retry is offered only where a retry is safe; writes retry only with the original `Idempotency-Key`.
- **AC-7** `not_found` and the restricted/cross-tenant case render **byte-identically**, and `forbidden` discloses nothing about what the session lacks. A snapshot test asserts the two renders are equal (§20.3, `api-contracts.md` §2).

## BDD examples

- EX-P18-09 GIVEN a skeleton whose geometry differs from its loaded content, WHEN the geometry test runs, THEN it fails naming the component.
- EX-P18-32 GIVEN a `not_found` render and a cross-tenant render, WHEN they are snapshotted, THEN the two snapshots are identical.
- EX-P18-33 GIVEN an indeterminate job, WHEN it renders, THEN a live state chip with elapsed time is shown and no progress percentage is invented.

## Verification gate

Skeleton geometry matches loaded content for every composed region; no full-page spinner exists in the API; the four empty kinds and five error scopes render their required anatomy; the copy lint rejects generic strings; the asset lint rejects raster marks; the `not_found`/cross-tenant snapshot equality holds.
