## User story

COMO administrador, QUERO ver saúde, saldo e integrações com estados honestos e sem nunca ver um token, PARA que eu aja sobre um provedor degradado sem criar um risco de credencial.

## Context

`FR-C06` covers provider health and balance and `FR-C08` covers integrations. `FF-10` encrypts social tokens at rest and the UI's part of that guarantee is simple: never render one. `P16.05` polls provider balance, so the surface states the last successful sync rather than fetching. Four gates surface here — `GATE-MT01`, `GATE-MT02`, `GATE-TT01` and `GATE-COST01`.

## Acceptance criteria

- **AC-1** Provider cards render the five states of §21.4 — `healthy`, `degraded`, `unavailable`, `balance_low`, `balance_depleted` — plus circuit-breaker state (open, half-open, closed) from `P4.03`.
- **AC-2** Balance renders as a meter with history, stating the **last successful sync time** from `P16.05`; a stale sync is stated rather than hidden, and no synchronous provider fetch is offered (`FF-16`).
- **AC-3** A depleted balance states the count of affected items and links to its runbook. Which state affected items occupy follows the reconciliation of `OQ-P16-05` / `OQ-P23-01`; the screen renders the reconciled behaviour and does not choose it.
- **AC-4** An error-class breakdown renders from the `P4.02` taxonomy so an operator sees error classes, never raw vendor error text (`FF-20`).
- **AC-5** The integration grid renders tenant × channel × state × token expiry with reconnect actions for expiring, expired and `connection_invalid` rows.
- **AC-6** Gate-dependent conditions are stated plainly: `GATE-MT01` as a pending app review, `GATE-MT02` naming the missing scope resolved from configuration, `GATE-TT01` as publication restricted to `SELF_ONLY`.
- **AC-7** **No token value is ever displayed, copyable or partially revealed.** Only state and expiry render, and a seeded token render fails the token-display assertion (`FF-10`).

## BDD examples

- EX-P23-03 GIVEN any integration surface, WHEN it renders, THEN no token value appears in whole or in part.
- EX-P23-08 GIVEN a depleted provider balance, WHEN the provider screen renders, THEN it states the affected item count and links to the runbook.
- EX-P23-21 GIVEN a stale balance sync, WHEN the meter renders, THEN the last successful sync time is stated.

## Verification gate

Five provider states and breaker state render; balance shows history and last successful sync with no synchronous fetch; depleted balance states affected count and links to a runbook; error classes come from the taxonomy with no vendor text; the integration grid renders with reconnect actions; the four gate conditions are stated; the token-display assertion turns red on a seeded token render.
