## User story

COMO implementing agent, QUERO user and session persistence shaped for server-side revocation, PARA P3 can revoke a session without inventing a schema change.

## Context

ADR-0005 fixes opaque server-side sessions. `architecture.md` §4 gives module `identity` the invariant that a session is revocable server-side at any time. `database-schema.md` §2.1 lists which of these carry a nullable `tenant_id`.

## Acceptance criteria

- **AC-1** `user` stores a credential hash column with no plaintext or reversible field.
- **AC-2** `session` is opaque, server-stored, and carries an explicit revocation marker plus expiry.
- **AC-3** Nullable-`tenant_id` treatment for internal users follows `database-schema.md` §2.1 exactly and each exception is annotated in the schema.

## BDD examples

- EX-P2-04a GIVEN a revoked session row, WHEN the next request presents it, THEN it is rejected (behaviour implemented in P3.02).
