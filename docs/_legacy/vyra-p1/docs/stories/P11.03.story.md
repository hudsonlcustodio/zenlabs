## User story

COMO implementing agent, QUERO the render driven by our uploaded audio asset, PARA voice identity comes from our synthesis rather than from the render vendor's voices.

## Context

`provider-architecture.md` §3.1 and ADR-0013. `prd.md` §9.1 confirms the Upload Asset API returns an asset id and that generation accepts `audio_url` or `audio_asset_id`, exactly one of the two.

## Acceptance criteria

- **AC-1** Audio is uploaded through the video port and the returned asset reference is stored on the attempt.
- **AC-2** Exactly one of the two audio inputs is supplied per submission, never both.
- **AC-3** The capability registry from P4.04 is consulted before submission (ASM-HG01).
- **AC-4** GATE-HG01, GATE-HG02 and GATE-HG03 are recorded on the affected paths; API and Studio credit semantics are never conflated.

## BDD examples

- EX-P11-04a GIVEN a look whose capabilities exclude the requested engine, WHEN submission is prepared, THEN it is refused before any provider call.
