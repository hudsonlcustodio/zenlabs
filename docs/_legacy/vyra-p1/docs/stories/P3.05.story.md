# Story P3.05 — CSRF protection

## User story

COMO security reviewer, QUERO state-changing requests protected against cross-site forgery, PARA a cookie-authenticated session cannot be driven by another origin.

## Context

`security-architecture.md` §1.3. Sessions are cookie-borne, so CSRF is a live concern rather than a theoretical one.

## Acceptance criteria

- **AC-1** Every state-changing route requires and validates a CSRF token or an equivalent documented control.
- **AC-2** Safe methods are exempt and that exemption is explicit rather than incidental.
- **AC-3** A missing or mismatched token yields a deny with a stable error code.

## BDD examples

- EX-P3-05a GIVEN a cross-origin POST carrying a valid session cookie but no CSRF token, WHEN it is received, THEN it is denied.
