## User story

COMO platform operator, QUERO the four ledger operations implemented exactly at their specified lifecycle points, PARA the consumption rule holds under retry, failure and concurrency.

## Context

`usage-ledger.md` §4 fixes the exact lifecycle points and §4.1 states that reserve to commit is not a transfer. FR-UC03, FR-UC04 and FR-UC04a fix the billing semantics; FR-UC07 requires idempotency.

## Acceptance criteria

- **AC-1** Reserve, commit, release and adjustment each exist as distinct operations at the lifecycle points fixed by `usage-ledger.md` §4.
- **AC-2** Commit is final: no operation reverses a commit, and T22 releases only held reservations (`workflows-state-machines.md` T22).
- **AC-3** Release occurs only where the provider produced no completed billable generation (T12).
- **AC-4** An ingestion failure after a completed generation leaves the commit standing and produces no release (FR-UC04a, T11b).
- **AC-5** Every operation is idempotent under its key from `usage-ledger.md` §5; a repeat is a no-op rather than a second effect.
- **AC-6** Adjustment is the only mechanism for correcting a past entry, and it appends rather than edits.

## BDD examples

- EX-P6-03 GIVEN a completed generation that VYRA failed to ingest, WHEN the ledger is folded, THEN the commit stands and no release occurs.
- EX-P6-04 GIVEN the same attempt committed twice, WHEN the second commit is written, THEN the unique index rejects it.
