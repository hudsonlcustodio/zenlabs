## User story

COMO implementing agent, QUERO as nove filas e seus DLQs provisionadas e reconciliadas contra a arquitetura e contra os manifests dos workers, PARA que uma fila renomeada em um lugar e não no outro seja um erro de CI e não um incidente.

## Context

`aws-topology.md` §6 fixes nine standard queues, each with a dedicated DLQ and `maxReceiveCount`, and records why they are Standard rather than FIFO. `P7.03` fixes the queue **contract and behaviour** against LocalStack; `P1.09` records each worker's intended queue set as a machine-readable manifest. This story creates the real resources and makes all three sources agree.

## Acceptance criteria

- **AC-1** All nine queues from `aws-topology.md` §6 exist per environment — `knowledge-ingest`, `content-generate`, `voice-synthesize`, `video-render`, `media-ingest`, `publish`, `metrics-collect`, `webhook-process`, `notification-send` — each with a dedicated DLQ and a configured `maxReceiveCount`.
- **AC-2** A **reconciliation check** compares three sources with zero tolerance: the queue table in `aws-topology.md` §6, the per-worker manifests from `P1.09`, and the provisioned resource set. Any difference in name, ownership or DLQ pairing fails CI naming the queue and the disagreeing sources.
- **AC-3** Visibility timeout is parameterised per queue and its configured value is asserted to be at least 6× the documented p99 handler duration for that queue, so the rule in §6 is enforced rather than remembered.
- **AC-4** Queues are Standard, not FIFO; a FIFO queue in the plan fails the check citing the ordering rationale in §6.
- **AC-5** Encryption at rest with KMS is enabled on every queue and DLQ, and the environment's instance profile is the only principal permitted to send or receive.

## BDD examples

- EX-P17-16 GIVEN a queue renamed in `aws-topology.md` §6 but not in a worker manifest, WHEN the reconciliation check runs, THEN it fails naming the queue and both sources.
- EX-P17-17 GIVEN a visibility timeout below 6× the documented p99, WHEN the check runs, THEN it fails naming the queue.

## Verification gate

Nine queues and nine DLQs exist per environment; the three-way reconciliation is green and turns red on a seeded rename; the visibility-timeout assertion passes for every queue; no FIFO queue exists; queue encryption and the send/receive principal set are asserted.
