## User story

COMO usuário, QUERO falhar dentro do produto e não fora dele, PARA que um erro nunca me deixe numa página sem saída nem revele o que existe do outro lado.

## Context

`api-contracts.md` §2 returns `404` rather than `403` on an object-scope mismatch to avoid existence disclosure, and `EX-P15-09` requires the screen to render a not-found state indistinguishable from a nonexistent item. `VYRA_PRODUCT_EXPERIENCE.md` §20.3 turns that into five rules, and §20.2 into one anatomy.

## Acceptance criteria

- **AC-1** Page-level surfaces exist for `not_found`, `forbidden`, 5xx and offline, all rendered **inside the shell** with the rail present so the user is never stranded (AE6).
- **AC-2** `not_found` and the cross-tenant case render **byte-identically**, asserted by snapshot equality, and the client introduces no timing difference between them.
- **AC-3** `forbidden` states nothing about what the session lacks and nothing about what exists.
- **AC-4** Each surface renders the §20.2 anatomy: what happened, what to do, the recovery action, a `mono-sm` stable `code` chip and a copyable `X-Correlation-Id`. No provider or vendor text and no stack trace reaches the screen (`FF-20`).
- **AC-5** The offline surface states that nothing was lost, offers retry, and preserves any unsaved input for the reconnection.
- **AC-6** Errors reaching a user emit a metric carrying the stable `code` and the screen id and **never** the payload, so `P16.01` has a real signal without a privacy cost.

## BDD examples

- EX-P20-07 GIVEN a `not_found` route and a cross-tenant route, WHEN both render, THEN the two renders are identical and the rail is still present.
- EX-P20-08 GIVEN the browser goes offline, WHEN the user continues, THEN the offline surface states that nothing was lost and offers retry.
- EX-P20-18 GIVEN a 5xx response carrying vendor text, WHEN the page renders, THEN only the stable code and correlation id are shown.

## Verification gate

Four page-level surfaces render inside the shell with the rail present; the `not_found`/cross-tenant snapshot equality holds; `forbidden` discloses nothing; the §20.2 anatomy is present on each with no vendor text; the offline surface preserves input; the error metric carries code and screen id only.
