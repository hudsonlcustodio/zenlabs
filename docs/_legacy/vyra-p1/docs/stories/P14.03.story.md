# Story P14.03 — Idempotent collection per publication and bucket

## User story

COMO architect, QUERO a retried collection to be a no-op, PARA at-least-once delivery cannot duplicate or corrupt a tenant's history.

## Context

`architecture.md` §7 declares the performance snapshot idempotency key as `(publication_id, captured_at_bucket)` with a unique index; `performance.md` §3 states the same index makes collection idempotent. ADR-0030 requires the constraint to be in the database, with the handler treating a unique violation as success.

## Acceptance criteria

- **AC-1** `UNIQUE (publication_id, captured_bucket)` exists on `performance_snapshot` and is asserted against the migrated database (`database-schema.md` §3.6).
- **AC-2** A retried collection for the same bucket inserts nothing twice and updates nothing; the unique violation is handled as success, not as an error path (ADR-0030).
- **AC-3** The key is covered by the class 10 suite, which double-invokes every key enumerated in `architecture.md` §7 and asserts a single effect.

## BDD examples

- EX-P14-03 GIVEN a collection for the same `(publication_id, captured_bucket)`, WHEN it is retried, THEN exactly one row exists.

## Verification gate

Class 10 idempotency coverage of the performance snapshot key, green with concurrent duplicate collections.
