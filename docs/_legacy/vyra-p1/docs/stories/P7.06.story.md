# Story P7.06 — Webhook intake with signature verification

## User story

COMO security reviewer, QUERO webhooks verified and treated as untrusted hints, PARA an attacker cannot advance a content item by posting a payload.

## Context

ADR-0031 treats webhooks as untrusted hints. `provider-architecture.md` §8 and `api-contracts.md` §6 fix the intake. GATE-HG04 leaves the HeyGen scheme unconfirmed, so verification is done through a port.

## Acceptance criteria

- **AC-1** Signature verification runs before any parsing of business fields; an invalid signature yields rejection with no state effect.
- **AC-2** The `provider_event_id` is recorded and a repeat produces exactly one effect (class 11).
- **AC-3** Payload contents are treated as a hint: the system confirms state with the provider or its own records rather than trusting the body (ADR-0031).
- **AC-4** Verification is performed through a port so an unconfirmed scheme (GATE-HG04) does not block the endpoint.
- **AC-5** The endpoint is exempt from CSRF by design and that exemption is explicit rather than incidental.

## BDD examples

- EX-P7-03 GIVEN a webhook with an invalid signature, WHEN it is received, THEN no state transition occurs and the request is rejected.
- EX-P7-02 GIVEN the same `provider_event_id` delivered twice, WHEN both are processed, THEN exactly one effect occurs.

## Verification gate

Class 11 webhook replay suite green including the unsigned case.
