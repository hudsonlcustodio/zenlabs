## User story

COMO portal user, QUERO an editorial calendar grouping my content by campaign, date and channel, PARA I can see what goes out and when without opening each item.

## Context

FR-CA01 requires a calendar carrying channel, date, time, campaign, status, automatic/manual publication and external post id. `domain-model.md` §8 models `Campaign` as name, window and objective; `api-contracts.md` §3.3 places the range query on the Portal surface.

## Acceptance criteria

- **AC-1** `campaign` exists as a tenant-owned table with name, window start, window end and objective (`database-schema.md` §3.6), under the RLS rules P2 established (FF-01).
- **AC-2** `GET /calendar?from=&to=` returns scheduled publications in the range with channel, `scheduled_for`, campaign, status, `mode` and `external_post_id` — every FR-CA01 field.
- **AC-3** `campaignId` filters content items and is accepted on content request creation, matching the existing contracts in `api-contracts.md` §3.1 and §3.2.
- **AC-4** The range query is read-only and derives its tenant from the session; no `tenantId` is accepted from the client (`api-contracts.md` §1).

## BDD examples

- EX-P13-01a GIVEN publications in and outside the requested window, WHEN the calendar is read, THEN only publications inside the window are returned.

## Verification gate

Class 3 contract test for `GET /calendar` plus an integration test asserting the campaign association survives a round trip.
