## User story

COMO usuário, QUERO ser avisado antes da sessão expirar e nunca perder trabalho por isso, PARA que segurança de sessão não custe um formulário preenchido.

## Context

`P3.02` builds opaque server-side sessions with revocation. `VYRA_PRODUCT_EXPERIENCE.md` §31.0 lists session-expiry as a global shell state, and §17.3 places it at hierarchy level 3 — a page-level banner, not a toast, because the user must read it to act.

## Acceptance criteria

- **AC-1** An account menu in the topbar exposes the user's name, the active surface, the theme control from `P18.02` AC-3, a link to profile and security, and sign-out.
- **AC-2** A session approaching expiry raises a **global banner** at a configured margin, offering extension. The margin is configuration, never a constant.
- **AC-3** **No work is lost.** If the session expires with unsaved input, the input is preserved locally, the user is returned to sign-in, and after re-authentication they return to the same route with the input restored. A test asserts the round-trip with a dirty form.
- **AC-4** A revoked session (`P3.02`) is detected on the next request and resolves to the sign-in screen with a neutral explanation that discloses nothing about why (`security-architecture.md` §1).
- **AC-5** Sign-out clears local preferences that could identify the previous user, revokes the session server-side, and the post-sign-out state exposes no cached tenant data.

## BDD examples

- EX-P20-06 GIVEN a session approaching expiry, WHEN the margin is reached, THEN a global banner offers extension and no work is lost if it is ignored.
- EX-P20-13 GIVEN a dirty form and an expired session, WHEN the user re-authenticates, THEN they return to the same route with the input restored.

## Verification gate

Account menu renders with theme control and sign-out; the expiry banner appears at the configured margin; the dirty-form round-trip restores input after re-authentication; a revoked session resolves neutrally to sign-in; sign-out leaves no cached tenant data.
