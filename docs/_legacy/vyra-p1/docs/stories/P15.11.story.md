## User story

COMO portal user and identity owner, QUERO to see my plan consumption, my subscription situation and my Digital Twin state, and to record consent explicitly, PARA my capacity and my likeness are both things I can see and control.

## Context

This story carries four forward references: the plan screen for `epic-P6`, the Twin status screen for `epic-P5`, consent capture from `P5.01` and balance presentation from `P6.01`. FR-P09, FR-P10 and FR-P11 fix the three views; FR-ID02 fixes what a consent record must carry.

## Acceptance criteria

- **AC-1** Consumption is presented as a fold over the ledger via `GET /usage/current-cycle`; no mutable `remaining_minutes` is presented as authoritative, per FR-UC05 and FF-07.
- **AC-2** The plan view shows entitlement against consumption for the current cycle, with entitlement read as derived rather than editable (module 16 invariant, `architecture.md` §4).
- **AC-3** The account view renders plan, cycle and payment status from `GET /subscription`, and offers no payment action, because FR-BL01 puts payment outside the product.
- **AC-4** Twin status renders the states FR-P11 names — provisioning, active, suspended, revoked — from `GET /digital-twin/status`, and a revoked twin exposes no generation action.
- **AC-5** Consent capture records scope, prohibited uses and validity as FR-ID02 requires, is versioned so audit can name the active version (FR-ID03), and revocation is presented as irreversible per the governance posture in `security-architecture.md` §11.

## BDD examples

- EX-P15-08 GIVEN a revoked Digital Twin, WHEN the twin-status screen renders, THEN it reports `revoked` and exposes no generation action.

## Verification gate

Integration coverage asserting the presented balance equals an independently computed ledger fold, and that a revoked twin renders no generation affordance.
