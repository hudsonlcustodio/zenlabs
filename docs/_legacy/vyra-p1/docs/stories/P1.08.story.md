# Story P1.08 — `apps/api` NestJS bootstrap per ADR-0004

- **Story ID**: `P1.08`
- **Epic**: `P1` (`docs/epics/epic-P1.md`)
- **Status**: `done`
- **Wave**: 1
- **Priority**: P0
- **Story points**: 8
- **Depends on**: `P1.05`
- **IMPLEMENTATION COMPLETE**

## User story

COMO implementing agent, QUERO the HTTP application that owns transactions to exist as a bootstrapped, verified process, PARA no later story has to invent the framework, the module layout or the request pipeline of `apps/api`.

## Context

`ADR-0004` fixes **NestJS + REST + OpenAPI** for `apps/api`, and `architecture.md` §2.1 makes it the command/query entry point that owns transactions. Until this story, `ADR-0004` was the only ADR fixing a runtime technology with no owning story: `P1.02` scaffolds `packages/*`, and `P3.06` already assumes guards "run server-side in `apps/api`" at wave 3. This story closes gap **G-01** by creating the process before anything is asked to live inside it. It ships **no route with product behaviour**: the only endpoint is health.

## Acceptance criteria

- **AC-1** `apps/api` boots as a NestJS application with a typed configuration loaded from `packages/config` (`P1.05`), failing fast and non-zero when a required key is absent.
- **AC-2** The module layout is declared and empty: one root module, a per-domain-module registration point, and a documented rule that a domain module is registered here and nowhere else — so `architecture.md` §4.1 boundaries survive contact with the framework.
- **AC-3** The global request pipeline exists and is asserted by test: correlation-id middleware (accept and echo `X-Correlation-Id`, generate when absent), a validation pipe bound to `packages/contracts` Zod schemas, and an exception filter that renders **RFC 9457 `application/problem+json`** with a stable `code` from `api-contracts.md` §1.1. No handler may return an ad-hoc error shape.
- **AC-4** `GET /api/v1/health` returns the running commit SHA, satisfying the image-traceability requirement in `cicd.md` §3. It performs no database, queue or provider call.
- **AC-5** `apps/api` depends only on `packages/contracts`, `packages/config` and `packages/observability` at this point; the dependency assertion from `P1.03` covers `apps/*` as well as `packages/*` and fails on any other edge.
- **AC-6** The application is stateless: a test asserts that no write to the local filesystem occurs during boot or during a health request (`NFR-11`, precursor to `FF-21`).

## BDD examples

- EX-P1-04 GIVEN a required environment key is absent, WHEN `apps/api` boots, THEN it exits non-zero before binding a port.
- EX-P1-05 GIVEN a request without `X-Correlation-Id`, WHEN it reaches any route, THEN a correlation id is generated and echoed in the response.
- EX-P1-06 GIVEN a handler throws an unmapped error, WHEN the response is rendered, THEN it is `application/problem+json` with a stable `code` and no stack trace or vendor text.

## Verification gate

`apps/api` boots in CI; the health route returns the commit SHA; the problem-details filter is asserted for one mapped and one unmapped error; the `apps/api` dependency edge set matches its declared manifest; a fail-fast boot test exits non-zero on a missing key.
