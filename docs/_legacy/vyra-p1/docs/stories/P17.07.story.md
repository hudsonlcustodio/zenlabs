# Story P17.07 — Secrets Manager, KMS keys and the least-privilege instance profile

## User story

COMO implementing agent, QUERO os cofres, chaves e a policy de execução criados com o menor privilégio possível, PARA que o resolver de `P4.11` tenha de onde ler e nada além do seu ambiente esteja ao alcance.

## Context

`ADR-0022` fixes Secrets Manager + KMS + IAM least privilege. `aws-topology.md` §3 requires an instance profile granting least-privilege access to S3 prefixes, SQS queues, Secrets Manager paths and KMS keys **for that environment only**. `P4.11` owns the runtime resolver and `FF-14`; this story owns the resources and the policies it reads through.

## Acceptance criteria

- **AC-1** A Secrets Manager path prefix per environment (`vyra/<env>/*`) holds one secret container per credential the architecture names. Containers are created empty or with an explicit placeholder; **no secret value appears in code, in state, or in a plan output**.
- **AC-2** A customer-managed KMS key per environment encrypts secrets, S3 objects, RDS storage and SQS messages, with rotation enabled and a key policy that names only that environment's principals.
- **AC-3** The instance profile grants, and grants only: read on `vyra/<env>/*` secrets, decrypt on that environment's KMS key, `s3:GetObject`/`PutObject` limited by prefix condition to `<env>/*` in that environment's two buckets, send/receive on that environment's nine queues, and `logs:PutLogEvents` on that environment's log groups. Any wildcard resource ARN fails the policy check.
- **AC-4** A **least-privilege assertion** enumerates every action×resource pair the profile can reach and fails when the set differs from the declared allowlist, so a widened policy is a CI failure rather than a silent drift.
- **AC-5** The separation check from `P17.02` AC-3/AC-4 is asserted to be green for these resources: no environment's profile can read another environment's secret path or decrypt with another environment's key.

## BDD examples

- EX-P17-18 GIVEN an instance-profile statement with a wildcard resource ARN, WHEN the policy check runs, THEN it fails naming the statement.
- EX-P17-19 GIVEN the staging instance profile, WHEN it attempts to read a `vyra/production/*` secret, THEN access is denied.

## Verification gate

Secret containers, KMS keys and the instance profile exist per environment; the least-privilege assertion is green and turns red on a seeded widened statement; a cross-environment secret read is denied in the deployed non-production environments; no secret value appears in any committed file or plan artifact.
