## User story

COMO cliente, QUERO que carregando, vazio, erro e negado sejam telas projetadas, PARA que o produto pareça acabado nos momentos em que a maioria dos produtos parece quebrada.

## Context

PD-09: every screen has four other screens, and they ship in the same story as the happy path. This story is the **coverage gate** that proves it for the Portal — it enumerates every blueprint in `VYRA_PRODUCT_EXPERIENCE.md` §31 and fails on any missing state, rather than re-implementing states the primitives already provide.

## Acceptance criteria

- **AC-1** A coverage check enumerates every Portal blueprint in §31 and asserts each has an implemented loading, empty, error and denied state. A new Portal route without them fails CI naming the route.
- **AC-2** Empty states are of the **correct kind** per §19.1 — `first-run`, `filtered`, `absent-by-design` or `restricted` — and the check asserts the kind, not merely the presence. A generic "No data" string fails the copy lint.
- **AC-3** Error states carry the §20.2 anatomy at the correct scope, render only stable `code` values, and expose a copyable correlation id. No provider or vendor text reaches any Portal screen (`FF-20`, PD-01).
- **AC-4** Denied and not-found render identically wherever the difference would disclose existence, asserted by snapshot equality per route (`api-contracts.md` §2, `EX-P15-09`).
- **AC-5** Loading states match their loaded geometry (`P18.14` AC-1) for every Portal region, and no Portal screen shows a full-page spinner or a fake progress bar for an indeterminate job.

## BDD examples

- EX-P15-09 GIVEN a content item owned by another tenant, WHEN its identifier is requested from a Portal screen, THEN the response is `404` and the screen renders a not-found state indistinguishable from a nonexistent item.
- EX-P21-09 GIVEN every Portal blueprint, WHEN the coverage check runs, THEN each has an implemented loading, empty, error and denied state.
- EX-P21-30 GIVEN a Portal route added without an empty state, WHEN CI runs, THEN the coverage check fails naming the route.

## Verification gate

The blueprint coverage check is green across every §31 screen and turns red on a seeded missing state; empty-state kinds are asserted, not just presence; the copy lint rejects generic strings; error states carry the correct scope, code and correlation id with no vendor text; denied/not-found snapshot equality holds per route; skeleton geometry matches for every region and no full-page spinner exists.
