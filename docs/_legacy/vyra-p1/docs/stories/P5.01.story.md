## User story

COMO identity owner, QUERO my consent recorded with an explicit scope, prohibited uses and validity, PARA my likeness and voice are used only in ways I actually authorised.

## Context

FR-ID02 and `domain-model.md` §3 (P0 area). Consent is versioned so that audit can state which version was active at the time of any generation (FR-ID03).

## Acceptance criteria

- **AC-1** Consent records the owner, authorized scope, prohibited uses, validity window and version.
- **AC-2** A consent change creates a new version rather than mutating the current one.
- **AC-3** The active consent version at any instant is derivable for audit purposes.
- **AC-4** Consent is tenant-scoped and RLS-protected like every client-owned entity.
- **AC-5** An expired validity window makes consent inactive without requiring an explicit revocation event.

## BDD examples

- EX-P5-01a GIVEN a consent whose validity window has passed, WHEN generation is guarded, THEN consent evaluates as inactive.
