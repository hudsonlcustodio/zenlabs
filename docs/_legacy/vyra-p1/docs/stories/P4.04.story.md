# Story P4.04 — Capability registry

- **Story ID**: `P4.04`
- **Epic**: `P4` (`docs/epics/epic-P4.md`)
- **Status**: `draft`

## User story

COMO implementing agent, QUERO capabilities queried before a generation is prepared, PARA we never submit a request the selected avatar or voice cannot serve.

## Context

`provider-architecture.md` §2 and ASM-HG01: Avatar V is not assumed for every look. T10 requires capability support before submission.

## Acceptance criteria

- **AC-1** Capabilities are queried and cached per provider entity rather than assumed globally.
- **AC-2** A requested engine or feature unsupported by the target entity is refused before submission.
- **AC-3** Cache invalidation is explicit, because a capability can change on the provider side.
- **AC-4** The registry is consulted by the T10 guard rather than duplicated inside it.

## BDD examples

- EX-P4-04 GIVEN a look whose capability set excludes the requested engine, WHEN generation is prepared, THEN the registry refuses before submission.

## Verification gate

Class 4 suite covering supported and unsupported capability fixtures.
