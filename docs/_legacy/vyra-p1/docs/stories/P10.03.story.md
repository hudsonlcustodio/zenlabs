## User story

COMO platform operator, QUERO model choice resolved by policy at runtime, PARA cost, quality and availability are tunable without a release.

## Context

FR-IN02 requires routing per task, tenant or quality profile, cost, availability, fallback and environment. ADR-0015 fixes the approach. `prd.md` §9.5 records commercial guidance without fixing an identifier.

## Acceptance criteria

- **AC-1** Routing resolves per task, tenant or quality profile, cost, availability, fallback and environment, as FR-IN02 requires.
- **AC-2** All identifiers and policy values come from configuration (FF-09, ASM-P10-01).
- **AC-3** An unavailable primary resolves to the declared fallback, and the resolved choice is recorded on the generation.
- **AC-4** Cost ceilings are enforceable per task so an expensive tier cannot be selected by accident.
- **AC-5** Routing decisions are observable as metrics for P16.01.

## BDD examples

- EX-P10-03 GIVEN the primary model unavailable, WHEN routing resolves, THEN the declared fallback is used and the choice is recorded.
