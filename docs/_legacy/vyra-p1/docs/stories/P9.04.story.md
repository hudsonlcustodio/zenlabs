# Story P9.04 — Embedding generation

## User story

COMO implementing agent, QUERO embeddings produced through the provider port, PARA the embedding vendor is replaceable and the model identifier stays in configuration.

## Context

`knowledge-engine.md` §1. The embedding call goes through the P4 LLM port; FF-09 forbids model identifiers outside configuration.

## Acceptance criteria

- **AC-1** Embeddings are produced through the provider port, never by a direct SDK call (FF-02).
- **AC-2** The embedding model identifier lives in configuration (FF-09, OQ-P9-01).
- **AC-3** Embedding failures are classified by the P4 taxonomy and retried only where retryable.
- **AC-4** Vector dimensionality is recorded so a model change is a detectable, migratable event rather than silent corruption.

## BDD examples

- EX-P9-04a GIVEN a change of embedding model, WHEN the recorded dimensionality differs, THEN the mismatch is detected rather than stored alongside incompatible vectors.

Integration plus class 4 fixtures for embedding failures.
