# Story P13.11 — FF-10 social tokens encrypted at rest

- **Story ID**: `P13.11`

## User story

COMO architect, QUERO a build check proving no plaintext token can be stored, PARA I-SP1 is enforced by the schema rather than by discipline.

## Context

FF-10 verifies there is no plaintext token column and no plaintext write path. `security-architecture.md` §5 states there is no column that can hold a plaintext token. Phase 12's definition of done names "no plaintext token column" explicitly.

## Acceptance criteria

- **AC-1** A schema assertion proves `social_connection` exposes only `*_ciphertext bytea` and has no `access_token` or `refresh_token` text column.
- **AC-2** An integration test connects with a known fixture token, reads the raw row and asserts the fixture bytes are absent.
- **AC-3** The check runs in the CI fitness-function stage from P1.06 and fails the build on any plaintext column or fixture-byte match.

## BDD examples

- EX-P13-02 GIVEN a stored social connection, WHEN the raw row is read, THEN the known fixture token bytes are absent.

## Verification gate

FF-10 green on the clean tree and red when a plaintext column is seeded in a migration.
