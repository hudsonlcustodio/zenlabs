## User story

COMO implementing agent, QUERO deploy e smoke como estágios bloqueantes com os portões de ambiente do `cicd.md` §5 aplicados pelo pipeline, PARA que `P16.09` tenha um staging real para medir e `P16.10` tenha um portão real para verificar.

## Context

`cicd.md` §1 stages 9 and 10 and §5's environment gates were verified by `P16.10` AC-4 but built by nothing — the last and largest component of gap **G-03**. `P16.09` runs load tests "against staging"; without this story, staging does not exist as a deployed environment.

## Acceptance criteria

- **AC-1** Stage 9 (`deploy`) targets one environment per run and executes the health-checked cutover from `P17.08` AC-3. A failed health check fails the stage without switching traffic.
- **AC-2** Stage 10 (`smoke`) runs post-deploy critical-path checks against the deployed environment and **triggers rollback on failure** (`cicd.md` §1). At this wave the critical path is the health and readiness surface of the five processes; the suite is designed so each later epic appends its own checks, and a registry lists which epic owns which check.
- **AC-3** The environment gates of `cicd.md` §5 are enforced by the pipeline: development deploys on a push to any branch with the pipeline green; staging deploys on a merge to `main` with the pipeline green; production deploys only on manual dispatch **and** only with a green staging smoke on the same SHA, a reviewed migration plan, and a human approval recorded.
- **AC-4** Production additionally requires the `security/static` stage to be green on the exact SHA being deployed; a deploy of a SHA whose security stage is red or absent is refused (`cicd.md` §5).
- **AC-5** A failed smoke rolls back automatically to the previous image using `P17.08` AC-4, and the rollback outcome is reported on the pipeline run rather than left to be discovered.
- **AC-6** Every deploy records the SHA, the environment, the operator and the outcome in a durable, queryable form, so `P16.10`'s production gate register has a real source rather than a manual list.

## BDD examples

- EX-P17-06 GIVEN a staging deploy whose smoke stage fails, WHEN the pipeline completes, THEN the previous image is running and the failure is reported.
- EX-P17-08 GIVEN a production deploy attempted without a green staging smoke on the same SHA, WHEN the gate is evaluated, THEN the deploy is refused.
- EX-P17-27 GIVEN a production deploy of a SHA whose security stage is red, WHEN the gate is evaluated, THEN the deploy is refused naming the stage.

## Verification gate

Stages 9 and 10 are blocking; a merge to `main` deploys staging and runs smoke; a seeded red smoke rolls back automatically to the previous image and reports it; the three environment gates are each exercised, including two refusals on the production path; the deploy record contains SHA, environment, operator and outcome for every run.

## Out of scope

- The content of later smoke checks, which each owning epic appends.
- Load testing (`P16.09`) and the launch gate register (`P16.10`), both of which consume this story's output.
- Blue/green or canary strategies, which the single-instance baseline does not support and no gate has fired for.
