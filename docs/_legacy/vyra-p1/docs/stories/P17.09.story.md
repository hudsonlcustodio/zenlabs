# Story P17.09 — CI stages 6–7: build and container build to ECR tagged by commit SHA

## User story

COMO implementing agent, QUERO os estágios de build e container build do `cicd.md` §1, PARA que todo artefato executável seja rastreável ao commit que o produziu.

## Context

`cicd.md` §1 defines ten stages; `P1.06` built stages 1–5 and its Out of scope reads "Deployment". Stages 6–10 had no owner — that is the third component of gap **G-03**. This story builds stages 6 and 7. `cicd.md` §3 requires images tagged by commit SHA, never only `latest`, with the running SHA exposed on a health endpoint — which `P1.08` AC-4 and `P1.09` AC-4 already provide.

## Acceptance criteria

- **AC-1** Stage 6 (`build`) builds every application and package in the workspace and fails on any build error. It runs after `security/static` and before container build, exactly in the `cicd.md` §1 order.
- **AC-2** Stage 7 (`container build`) produces one image per process — `web`, `api`, `worker-ai`, `worker-media`, `worker-social` — tagged `<service>:<commit-sha>` and pushed to a per-environment ECR repository.
- **AC-3** No image is tagged only `latest`. A moving tag may exist **in addition** to the SHA tag; a push whose only tag is moving fails the stage (`cicd.md` §3).
- **AC-4** The commit SHA baked into each image matches the SHA the health endpoint reports; an integration check runs the built image and asserts the two agree.
- **AC-5** Both stages are blocking on the default branch and neither may be skipped (`cicd.md` §1). The build carries `PROVIDER_MODE=mock` and holds no provider credential, keeping `FF-08` green.
- **AC-6** ECR repositories have image scanning enabled and a lifecycle policy that retains at least the last N images so `P17.08`'s rollback target always exists.

## BDD examples

- EX-P17-23 GIVEN an image pushed with only a moving tag, WHEN stage 7 runs, THEN it fails citing `cicd.md` §3.
- EX-P17-24 GIVEN a built image is started, WHEN its health endpoint is queried, THEN the SHA it reports equals the image tag.

## Verification gate

Stages 6 and 7 run in the documented order and are blocking; five images are produced and pushed per build, each SHA-tagged; the SHA agreement check passes; a seeded moving-tag-only push fails; the ECR lifecycle retains at least the rollback depth `P17.08` requires.
