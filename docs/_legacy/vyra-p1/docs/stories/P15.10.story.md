# Story P15.10 — Portal performance screen reading snapshots only

- **Story ID**: `P15.10`
- **Epic**: `P15` (`docs/epics/epic-P15.md`)

- **Depends on**: `P15.04`, `P14`
- **IMPLEMENTATION NOT STARTED**

## User story

COMO portal user, QUERO performance metrics per published item, PARA I can judge what worked without the screen hammering a platform API every time I open it.

## Context

FR-P08 requires performance per published item. FR-PF05 forbids dashboards triggering synchronous provider calls on open, and FF-16 turns that into a build failure. `performance.md` §3 fixes the collection windows and §4 fixes that dashboards read snapshots. FR-PF03 allows null fields where a platform does not expose them.

## Acceptance criteria

- **AC-1** The screen reads only `GET /performance` from `api-contracts.md` §3.5, which is snapshot-backed, and makes zero provider calls.
- **AC-2** Window labels rendered are the `captured_bucket` values from `performance.md` §3, treated as configuration rather than as screen constants.
- **AC-3** A field absent on a platform renders as absent, not as zero; FR-PF03 forbids assuming platform parity.
- **AC-4** The charting library is selected here per ADR-0003 and recorded; no chart library is assumed by any earlier story (ASM-P15-01).

## BDD examples

- EX-P15-04 GIVEN the performance screen is opened, WHEN it renders, THEN zero provider calls are recorded against the mock.
