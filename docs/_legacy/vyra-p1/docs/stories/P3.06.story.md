## User story

COMO platform operator, QUERO every route to state which roles may call it, PARA authorization is a declared property rather than an emergent one.

## Context

`prd.md` §3.1 fixes eight actors: portal user, identity owner, SUPER_ADMIN, ADMIN, OPERATIONS_MANAGER, CONTENT_STRATEGIST, QA_REVIEWER, PUBLISHER. `security-architecture.md` §2 and `api-contracts.md` §2 fix the model.

## Acceptance criteria

- **AC-1** All eight actors from `prd.md` §3.1 exist as roles with their permissions declared centrally.
- **AC-2** Guards run server-side in `apps/api` before any handler logic.
- **AC-3** A tenant-scoped role can never act on another tenant even when the route would otherwise allow the action.
- **AC-4** Denials are denials, not silently filtered successes.
- **AC-5** The identity owner's rights over consent and revocation are modelled distinctly from the portal user's, even when the same human holds both.

## BDD examples

- EX-P3-04 GIVEN a `QA_REVIEWER` token, WHEN a Control-only route is called, THEN the response is a deny, not a filtered success.

## Verification gate

Class 6 authorization matrix green for every route by every role.
