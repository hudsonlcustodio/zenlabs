## User story

COMO portal user, QUERO a library of my approved and published assets, PARA I can find and download my content without it ever being publicly reachable.

## Context

This is the Library UI that `epic-P11` and `P11.07` place out of their own scope. FR-P07 requires viewing the content library. `api-contracts.md` §3.4 returns metadata only and issues a short-lived signed URL on demand; media bytes are never proxied through the API and never served from a public bucket.

## Acceptance criteria

- **AC-1** The list renders metadata from the §3.4 route; the screen never receives media bytes through the API.
- **AC-2** Playback and download request a signed URL per view, honouring the configured short TTL from `security-architecture.md` §6 rather than caching a URL in the client.
- **AC-3** A signed URL is issued only after the authorization check, so an expired or foreign asset produces a denial rather than a broken player.
- **AC-4** Object keys are never exposed as meaningful identifiers, consistent with the non-semantic tenant-prefixed key layout in `aws-topology.md` §5.

## BDD examples

- EX-P15-05 GIVEN a media asset in the library, WHEN it is viewed, THEN delivery uses a short-TTL signed URL and never a public object.

## Verification gate

Integration coverage of signed-URL issuance from the rendered screen; class 13 coverage of signed-URL expiry per `testing-strategy.md` class 13.
