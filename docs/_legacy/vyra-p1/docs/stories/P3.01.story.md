## User story

COMO security reviewer, QUERO credentials stored with a memory-hard hash and explicit parameters, PARA an offline dump does not yield usable passwords.

## Context

`security-architecture.md` §1 and ADR-0005 fix Argon2id. Parameters are configuration so they can be raised without a schema change.

## Acceptance criteria

- **AC-1** Argon2id is used with parameters loaded from `packages/config`, not literals in code.
- **AC-2** The hash column stores the parameters alongside the digest so re-hashing on login is possible.
- **AC-3** No endpoint, log line or error message ever returns or echoes a credential.
- **AC-4** Password policy is enforced server-side and its thresholds are configuration.

## BDD examples

- EX-P3-01a GIVEN a stored credential, WHEN parameters are raised in configuration, THEN the next successful login re-hashes transparently.
