## User story

COMO security owner, QUERO logs that are structured, correlated and provably redacted, PARA diagnosis never becomes the leak.

## Context

`observability.md` §1 fixes JSON-only logging with a mandatory field set and a never-logged denylist; §2 fixes correlation entering at the edge and propagating through HTTP, outbox, SQS, worker and provider call. `security-architecture.md` §10 places the redaction layer in `packages/observability` and FF-20 is the proof. `P7.04` AC-3 already propagates correlation identifiers into jobs; `P1.05` respected the FF-20 precondition of not echoing configuration values.

## Acceptance criteria

- **AC-1** Every record carries the mandatory fields from `observability.md` §1, with `tenantId` present as an opaque UUID and nothing personal added to it.
- **AC-2** Tokens, secrets, full audio, private documents, complete prompts, raw model output containing client content, password hashes and signed URLs do not survive the redaction layer.
- **AC-3** Request and response bodies are never logged wholesale, and a test asserts no logger call site passes a raw request body.
- **AC-4** `console.*` is banned outside `packages/observability` by ESLint, as FF-20 specifies.
- **AC-5** `correlationId` is accepted at the edge via `X-Correlation-Id` or generated, and `causationId` links an event to its cause, so a published video is traceable back through publication, approval, render attempt, synthesis, script, context snapshot and knowledge chunks.

## BDD examples

- EX-P16-01 GIVEN a log record carrying a token, a complete prompt and document text, WHEN it passes the redaction layer, THEN none of the fixtures survive.
- EX-P16-09 GIVEN a correlation identifier accepted at the edge, WHEN the work traverses HTTP, outbox, queue and worker, THEN every emitted record carries the same identifier.

## Verification gate

FF-20 green: redaction unit tests pass, the `console.*` ban holds, and no call site passes a raw request body.
