## User story

COMO content strategist, QUERO to manage a tenant's knowledge sources and see which chunks informed a generation, PARA an off-brand output can be diagnosed rather than guessed at.

## Context

This is the Studio knowledge screen that `epic-P9` places out of its own scope, and the trace visualisation that `P9.08` defers. FR-S03 requires managing knowledge sources and their processing state; FR-KN04 fixes the lifecycle facts to display; FR-IN05 makes each script traceable to the context and prompt version that produced it.

## Acceptance criteria

- **AC-1** Sources render with processing status distinguishing pending, processing, succeeded and failed with a reason, matching the lifecycle in `P9.09`.
- **AC-2** The screen uses `GET /studio/knowledge-sources?tenantId=` from `api-contracts.md` §4, which requires the `CONTENT_STRATEGIST` role and, being an internal route, takes an explicit `tenantId`.
- **AC-3** The retrieval trace for a generated script shows which chunks were retrieved and the prompt version used, per FR-IN05.
- **AC-4** Retrieved document text is displayed as data and is never rendered into a control that could re-enter a prompt, keeping the containment posture FF-27 verifies.

## BDD examples

- EX-P15-01 GIVEN a `QA_REVIEWER` session, WHEN a Control screen route is requested, THEN the server denies it rather than rendering a filtered view.

## Verification gate

Integration coverage of the source list and trace view; class 6 coverage asserting the route is denied to non-internal roles.
