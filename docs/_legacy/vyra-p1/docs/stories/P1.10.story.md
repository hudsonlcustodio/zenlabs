# Story P1.10 — OpenAPI generation and the FF-18 generate-and-diff check

- **Story ID**: `P1.10`
- **Epic**: `P1` (`docs/epics/epic-P1.md`)
- **Status**: `done`

## User story

COMO implementing agent, QUERO the published OpenAPI document to be generated from the code and diffed in CI from the first route onwards, PARA contract drift between `packages/contracts` and the published spec can never accumulate unnoticed.

## Context

`FF-18` — *"OpenAPI matches the contracts"* — had no owning story: it was named once, in `P14.08` AC-1, as an assertion about a single route. `ADR-0004` and `ADR-0032` make REST + OpenAPI the API style, and `api-contracts.md` is the canonical contract source. This story closes the second half of gap **G-01**.

It is deliberately placed in `P1`, on the same argument `epic-P1.md` makes for boundary lint: a generate-and-diff check added after fifty routes exist produces an unpayable diff, while the same check added when zero routes exist is free and stays free. The check therefore ships against an **empty route set** and grows automatically with every epic that adds a route.

## Acceptance criteria

- **AC-1** `docs/api/openapi.yaml` is **generated** from the `apps/api` route metadata and the `packages/contracts` Zod schemas by one command, and is committed to the repository.
- **AC-2** CI regenerates the document and fails when the regenerated output differs from the committed one, naming the changed paths and schema components. This is `FF-18`.
- **AC-3** The generated document is validated against the OpenAPI specification and against the conventions in `api-contracts.md` §1: base path `/api/v1`, cursor pagination shape, RFC 9457 problem responses, and no `tenantId` parameter on any client-facing route.
- **AC-4** Every stable error `code` in `api-contracts.md` §1.1 is present in the generated problem-details schema as an enumerated value; a code added to the contracts package without appearing in the spec fails the check.
- **AC-5** The check is wired into the `security/static` stage of `cicd.md` §1 alongside the other fitness functions, and is green on an empty route set.
- **AC-6** A seeded divergence — a route whose response schema is edited without regenerating — turns `FF-18` red naming that route.

## BDD examples

- EX-P1-09 GIVEN a route response schema is changed and the spec is not regenerated, WHEN CI runs, THEN FF-18 fails naming the route.
- EX-P1-10 GIVEN a new stable error code is added to `packages/contracts`, WHEN the spec is regenerated, THEN the problem-details enum contains it and the diff is clean.
- EX-P1-11 GIVEN a client-facing route declares a `tenantId` parameter, WHEN the convention check runs, THEN it fails citing `api-contracts.md` §1.

## Verification gate

`FF-18` present in the fitness suite and green; `docs/api/openapi.yaml` committed and reproducible byte-for-byte from a clean checkout; the seeded-divergence test turns the check red; the convention assertions pass.
