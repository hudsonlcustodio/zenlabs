## User story

COMO user of any surface, QUERO to sign in and complete an MFA challenge, PARA I reach my surface without the screen ever becoming the thing that decides my permissions.

## Context

`security-architecture.md` §1 fixes Argon2id credentials and opaque server-side sessions, §1.1 fixes TOTP MFA required for `ADMIN` and `SUPER_ADMIN`, §1.2 fixes lockout and rate limiting, §1.3 fixes CSRF. All of that already exists from P3; this story renders it.

## Acceptance criteria

- **AC-1** Login, MFA enrolment and MFA challenge screens exist and post to the routes contracted in `api-contracts.md` §2, carrying the CSRF token on unsafe methods per `api-contracts.md` §1.
- **AC-2** A lockout is presented as a lockout, and the screen does not disclose whether the account exists, consistent with the existence-disclosure posture in `api-contracts.md` §2.
- **AC-3** A session revoked server-side produces a re-authentication prompt on the next request, never a stale rendered view.
- **AC-4** No credential, MFA secret or session token is written to client storage or to a log, per `security-architecture.md` §10.

## BDD examples

- EX-P15-02 GIVEN a screen that hides an action for a role, WHEN the underlying route is called directly, THEN the server denies it.
