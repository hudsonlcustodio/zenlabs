## User story

COMO frontend engineer, QUERO um sistema de formulário que valide no momento certo e traduza códigos estáveis da API em frases VYRA, PARA que nenhum texto de fornecedor chegue ao usuário e nenhum erro fique sem próxima ação.

## Context

`api-contracts.md` §1 fixes RFC 9457 problem responses with a stable `code`, and §1.1 enumerates thirteen codes. `VYRA_PRODUCT_EXPERIENCE.md` §13 fixes label placement, the validation moment, the code→sentence mapping, destructive-form discipline and the idempotency contract for submissions.

## Acceptance criteria

- **AC-1** Label above control, no placeholder-as-label anywhere, and the optional/required marking polarity inverts per form as §13.1 prescribes. A placeholder used as the only label fails the form lint.
- **AC-2** Validation never fires on keystroke before a field's first blur; after first blur, live re-validation clears the error. On submit, focus moves to the first invalid field and an `alert` summary lists each error as a link to its field (§13.3, WCAG SC 3.3.1).
- **AC-3** A code→message map covers **all thirteen** stable codes of `api-contracts.md` §1.1. Each entry renders a VYRA sentence, the next action, a `mono-sm` code chip and a copyable correlation id. The RFC 9457 `detail` field is **never** rendered. A fixture exists per code and a missing entry fails the completeness test.
- **AC-4** Scope is correct per code: `validation_failed` renders field-scoped; `conflict`, `state_transition_not_allowed`, `entitlement_exhausted`, `consent_revoked`, `capability_unsupported`, `provider_unavailable`, `rate_limited` and `connection_invalid` render form-scoped with their specific next action.
- **AC-5** Submission sends `Idempotency-Key` on every form that creates a billable or external effect; a retry reuses the key, and an `idempotency_key_reuse` response resolves to the existing object rather than showing an error (§13.4, `api-contracts.md` §1).
- **AC-6** The destructive-form pattern of §13.5 exists: typed confirmation of the object name, confirm disabled until exact match, danger styling, and the consequence sentence directly above the control — never in a tooltip.

## BDD examples

- EX-P18-07 GIVEN an RFC 9457 problem response with code `entitlement_exhausted`, WHEN the form renders it, THEN it renders the VYRA sentence, the code chip and the correlation id, and no `detail` text.
- EX-P18-23 GIVEN a field that has never been blurred, WHEN the user types an invalid value, THEN no error is shown until blur or submit.
- EX-P18-24 GIVEN a destructive form, WHEN the typed confirmation does not match exactly, THEN the confirm control stays disabled.

## Verification gate

A fixture per stable code renders the correct scope, sentence, chip and correlation id with no `detail` leakage; the completeness test fails on a missing code; the validation-timing test passes; the idempotency retry resolves without an error; the destructive pattern is asserted.
