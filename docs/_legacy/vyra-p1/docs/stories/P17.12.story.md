# Story P17.12 — Log groups, metric namespace and alarm substrate

## User story

COMO implementing agent, QUERO os grupos de log, o namespace de métricas e o substrato de alarme criados por ambiente, PARA que `P16` construa observabilidade sobre recursos existentes em vez de criá-los junto com os dashboards.

## Context

`aws-topology.md` §2 places CloudWatch in the baseline and `ADR-0023` fixes observability. `P16.01`, `P16.02`, `P16.03` and `P16.08` build metric emission, alarms, runbooks and dashboards — all of which need log groups, a metric namespace and an alarm notification target to already exist. This story creates exactly that substrate and no observability content, keeping the `P17`/`P16` boundary clean.

## Acceptance criteria

- **AC-1** One log group per process per environment exists with an explicit retention period set per environment — never the default "never expire", which is both a cost and a privacy defect.
- **AC-2** A single metric namespace per environment is defined and its name is exposed to `packages/config` so `P16.01` emits into it rather than choosing one.
- **AC-3** An alarm notification target per environment exists and is subscribable, so `P16.02` attaches alarms to a target that already routes somewhere.
- **AC-4** Log group access is least-privilege: the instance profile may write, and only named operator principals may read (`P17.07` AC-3).
- **AC-5** No dashboard, no alarm and no metric filter is created here; the epic boundary is asserted by a check that the plan contains zero alarm and zero dashboard resources.

## BDD examples

- EX-P17-28 GIVEN a log group without an explicit retention period, WHEN the plan is checked, THEN it fails naming the group.
- EX-P17-29 GIVEN an alarm resource in the `P17` plan, WHEN the boundary check runs, THEN it fails, because alarms belong to `P16.02`.

## Verification gate

Log groups exist per process per environment with explicit retention; the metric namespace is exposed to configuration; the notification target exists and is subscribable; the least-privilege read/write split is asserted; the plan contains zero alarm and zero dashboard resources.
