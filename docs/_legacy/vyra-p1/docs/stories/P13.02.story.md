## User story

COMO portal user, QUERO to connect my Instagram, Facebook and TikTok accounts through the official authorization flow, PARA VYRA can publish on my behalf without ever holding a readable token.

## Context

FR-SP02 requires the full OAuth token lifecycle with encrypted storage. `security-architecture.md` §5 fixes envelope encryption: a KMS CMK wraps a per-tenant data key and tokens are encrypted with AES-256-GCM, with no column able to hold plaintext. `api-contracts.md` §3.7 fixes the four routes.

## Acceptance criteria

- **AC-1** `POST /social-connections/{platform}/start` begins the authorization code flow with a `state` parameter bound to the session, and `GET /social-connections/callback` completes it (`api-contracts.md` §3.7).
- **AC-2** `social_connection` stores `access_token_ciphertext` and `refresh_token_ciphertext` as `bytea` and exposes no text token column (`database-schema.md` §3.6, I-SP1).
- **AC-3** Encryption is envelope encryption per `security-architecture.md` §5; decryption happens in the worker at call time and plaintext is never logged (FF-20).
- **AC-4** The scope set is resolved from configuration, not hardcoded; the exact Meta scope names remain GATE-MT02 and are not invented (`social-publishing.md` §2.2).
- **AC-5** `DELETE /social-connections/{id}` disconnects, and the connection status vocabulary is `connect → active → expiring → refreshed | revoked | invalid` (`social-publishing.md` §2.2).

## BDD examples
