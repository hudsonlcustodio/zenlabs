## User story

COMO frontend engineer, QUERO card, panel, metric card, section e inset como primitivos com a regra de aninhamento aplicada por lint, PARA que agrupamento seja um ato deliberado e não a resposta padrão para qualquer conteúdo.

## Context

`VYRA_PRODUCT_EXPERIENCE.md` §15 fixes the card anatomy, five variants, the metric-card rules and — the one that matters most for looking premium rather than templated — §15.4's nesting rule and §15.5's default of no card at all.

## Acceptance criteria

- **AC-1** The card anatomy of §15.1 exists as one composition: optional eyebrow (`label-sm`, uppercase, tertiary), title, optional divider, body, optional footer, with padding from `--vyra-card-pad`.
- **AC-2** Five variants exist and no sixth: `panel`, `metric`, `object`, `action`, `inset`. An `action` card exposes exactly one primary button by API — a second is a type error, not a review comment.
- **AC-3** The metric card of §15.3 renders eyebrow, `metric-xl` tabular value, optional delta chip, optional 40px sparkline slot and optional footnote, and refuses a second metric of equal weight.
- **AC-4** A **nesting lint** enforces §15.4: a card inside a card is permitted only when the inner element is independently navigable or actionable; maximum depth is 2; at depth 2 the inner surface steps one level and drops shadow entirely. Depth 3 fails naming the outermost card.
- **AC-5** A `section` primitive exists for the §15.5 default — eyebrow, heading, divider, content, directly on `bg-base`, no card — so the cheap path is the correct one.

## BDD examples

- EX-P18-08 GIVEN a card nested three levels deep, WHEN the nesting lint runs, THEN it fails naming the outermost card.
- EX-P18-25 GIVEN an `action` card with two primary buttons, WHEN it is compiled, THEN it is a type error.

## Verification gate

Five variants and no sixth; the nesting lint turns red at depth 3 and on a non-actionable nested card; the metric card refuses a second equal-weight metric; the section primitive renders without a surface.
