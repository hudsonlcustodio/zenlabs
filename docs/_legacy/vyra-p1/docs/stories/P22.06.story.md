# Story P22.06 — QA workspace with annotation and explicit human verdict

- **Story ID**: `P22.06`

## User story

COMO revisor de QA, QUERO revisar o vídeo com o roteiro ao lado e registrar um veredito humano explícito, PARA que nenhuma automação assine no meu lugar.

## Context

`ADR-0033` fixes MVP QA policy as `HUMAN_REQUIRED`: T13 requires a QA record with an explicit human verdict, and `FF-33` guarantees no client approval setting can skip VYRA QA. `AI_ASSISTED` pre-population is the modelled relief path for `RISK-18`, not a replacement for the verdict. `VYRA_PRODUCT_EXPERIENCE.md` §32.11 fixes the workspace.

## Acceptance criteria

- **AC-1** The `L-workspace` of §32.11 renders: QA queue rail, the `P19.05` player, and the checklist and verdict pane, with the approved script available as a reference.
- **AC-2** A verdict **cannot** be recorded without an explicit human decision. There is no path — keyboard, bulk, default or timeout — by which a verdict is produced automatically. A seeded auto-verdict attempt fails the human-verdict assertion (`ADR-0033`, T13).
- **AC-3** `AI_ASSISTED` pre-population, where enabled, renders as a clearly-marked **suggestion** on each checklist item, visually distinct from a human answer, and submitting requires the reviewer to confirm each suggested item rather than the form as a whole.
- **AC-4** Timestamp annotation marks the scrubber and attaches the note to the QA record (`P19.05` AC-7); marks are keyboard-addable at the current playhead and are listed beside the player.
- **AC-5** Failing QA (T14) requires a reason; the reason and the marks travel with the item so the client's video-approval surface can show what QA already found (`P21.09` AC-2) and the strategist does not repeat it.
- **AC-6** Queue claiming is explicit: an item claimed by another reviewer renders read-only with the holder's name; claim and release are audited.
- **AC-7** Queue age renders per item and in aggregate against a configured threshold, making `RISK-18`'s throughput bottleneck measured rather than felt.

## BDD examples

- EX-P22-02 GIVEN AI-assisted QA pre-population, WHEN the verdict bar renders, THEN the suggestion is visibly a suggestion and a human verdict is still required.
- EX-P22-17 GIVEN an attempt to submit a verdict without an explicit human decision, WHEN it is made, THEN it is refused.
- EX-P22-18 GIVEN a failed QA with marks, WHEN the client opens video approval, THEN the QA findings are visible there.

## Verification gate

The QA workspace renders its three regions; the human-verdict assertion proves no automatic verdict path exists; AI suggestions are visually distinct and require per-item confirmation; keyboard annotation attaches marks to the record; failing requires a reason and propagates marks to the client surface; claiming is exclusive and audited; queue age renders per item and in aggregate.
