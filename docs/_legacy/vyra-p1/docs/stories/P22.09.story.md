# Story P22.09 — Clients, requests and identity-asset experience

## User story

COMO operador, QUERO gerenciar clientes, pedidos e ativos de identidade com o consentimento sempre visível, PARA que nenhuma ação de geração seja possível quando a governança não permite.

## Context

This story covers `FR-S01` (clients), `FR-S02` request and briefing management, `FR-S04` (twin and voice lifecycles) and `FR-S07` (acting on a tenant's behalf). `FF-30` enforces consent before every generation and `FF-12` forbids any mechanism that bypasses provider voice verification — both must be visible as absent affordances, not as failed attempts.

## Acceptance criteria

- **AC-1** The client grid and client detail render per §32.2 and §32.3, with tabs for Overview, Configuration, Identity, Knowledge, Content and Audit, and a `Set as scope` action that drives the whole surface.
- **AC-2** Consent state is visible on the client header; when consent is revoked, **every generation action across every tab is disabled with the reason** rather than failing on submit (`FF-30`, guard G-1).
- **AC-3** The request grid and briefing drawer render per §32.4, including a briefing that failed with the retry path legal for its state.
- **AC-4** Twin and voice management render per §32.8 and §32.9 with the five identity states, the capability list and the identity version timeline; provisioning is disabled with the reason when consent is absent.
- **AC-5** **No voice-verification override exists.** A voice clone awaiting provider verification offers no bypass, and the screen states why (`FF-12`). A seeded override control fails the assertion.
- **AC-6** Revocation of a twin or voice uses the destructive pattern with typed confirmation, states the T22 consequence, offers no undo, and shows propagation status afterwards.
- **AC-7** Acting on a tenant's behalf (`FR-S07`) is only possible while the `P22.01` banner is present; each such action writes an audit record and appears in the item's history as performed on behalf of the tenant (§28.7).

## BDD examples

- EX-P22-03 GIVEN an operator acts on a tenant's behalf, WHEN the action completes, THEN the banner was present and the action appears in the item history.
- EX-P22-23 GIVEN consent is revoked, WHEN any client tab renders, THEN every generation action is disabled with the consent reason.
- EX-P22-24 GIVEN a voice clone awaiting verification, WHEN the screen renders, THEN no override control exists.

## Verification gate

Client grid and detail render with all tabs and the scope action; revoked consent disables every generation action with its reason; request and briefing surfaces render including the failed-briefing path; identity states, capabilities and version timeline render; the voice-verification override assertion turns red on a seeded control; revocation follows the destructive pattern and shows propagation; acting-on-behalf actions are banner-gated and audited.
