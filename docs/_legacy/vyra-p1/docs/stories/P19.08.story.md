## User story

COMO frontend engineer, QUERO primitivos de arrastar que expressem intenção e tenham equivalente de teclado, PARA que nenhum usuário fique excluído e nenhuma tela mova um estado que o motor de workflow não permite.

## Context

`ADR-0035` selects dnd-kit. `FF-06` makes the workflow engine the only mutator of `ContentItem.state`, which fixes the semantics of a drag in this product: **a drag expresses intent; the server decides**. `VYRA_PRODUCT_EXPERIENCE.md` §26.3 fixes the four sanctioned drags and §26.4 makes keyboard equivalence a defect gate.

## Acceptance criteria

- **AC-1** Drag primitives exist for two shapes — sortable/movable cards between lanes, and draggable items onto grid cells — with VYRA-shaped props. Valid targets are supplied by the caller as data; the primitive never derives permission itself.
- **AC-2** The boundary holds: a direct import of dnd-kit outside `packages/ui` fails the boundary lint naming the file.
- **AC-3** **Keyboard equivalence is complete**: focus the item, `Space` to lift, arrow keys to move between valid targets with invalid targets skipped and announced, `Space` to drop, `Escape` to cancel. Every step announces the target and its validity through a live region. A drag primitive without this path does not pass review.
- **AC-4** Optimism is reversible: an optimistic move that the server refuses animates back to origin with `emphasized` easing and raises a **region-level** error — never a toast, per §17.2 and §26.3.
- **AC-5** A non-draggable item states why on grab attempt rather than silently refusing, and the reason comes from the caller as data.
- **AC-6** Touch requires a deliberate 200ms long-press to start a drag; under `prefers-reduced-motion` the lift and drop animations are removed while the keyboard path and the drop behaviour are unchanged (§10.4, §22.4).

## BDD examples

- EX-P19-07 GIVEN a drag started with the keyboard, WHEN the user moves between targets, THEN invalid targets are skipped and each valid target is announced.
- EX-P19-08 GIVEN an optimistic drop the server refuses, WHEN the response arrives, THEN the item animates back to origin and a region-level error is shown.
- EX-P19-23 GIVEN a non-draggable card, WHEN a grab is attempted, THEN the reason is announced.

## Verification gate

Both drag shapes work with VYRA-shaped props; the boundary lint turns red on a seeded direct import; the complete keyboard path is asserted end-to-end with announcements; a refused drop reverts and raises a region error; a non-draggable item states its reason; touch long-press and reduced-motion behaviour asserted.
