## User story

COMO portal user, QUERO to reprocess or delete a source and see its processing status, PARA my knowledge base stays accurate and under my control.

## Context

FR-KN04 requires versioning, provenance, processing status, reprocessing, deletion, deduplication, limits and failure handling. `knowledge-engine.md` §6 fixes failure semantics.

## Acceptance criteria

- **AC-1** Processing status is visible per source and distinguishes pending, processing, succeeded and failed with a reason.
- **AC-2** Reprocessing is idempotent under the P7.05 keys and produces a new version.
- **AC-3** Deletion removes chunks from retrieval reach, and offboarding deletes them outright per `database-schema.md` §5.
- **AC-4** Per-tenant limits on source count and total size are enforced from configuration.
- **AC-5** A partial failure leaves the source in a recoverable state rather than half-ingested and reachable.

## BDD examples

- EX-P9-05 GIVEN a source deleted by its tenant, WHEN retrieval runs, THEN its chunks are no longer reachable.

## Verification gate

Integration tests across the lifecycle including partial-failure recovery.
