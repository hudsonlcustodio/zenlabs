## User story

COMO governance owner, QUERO an audit trail that cannot be rewritten, PARA governance evidence is only worth what its immutability is worth.

## Context

`security-architecture.md` §9 and `architecture.md` §4 module 22 require append-only audit. FF-11 covers ledgers and audit together. Retention is five years per `database-schema.md` §5.

## Acceptance criteria

- **AC-1** `audit_record` captures actor, action, subject, timestamp and the versions active at the time.
- **AC-2** UPDATE and DELETE are rejected at the database level for `vyra_app`, not only in application code.
- **AC-3** The table is tenant-scoped where the action is client-owned, following `database-schema.md` §2.1 for platform-level actions.
- **AC-4** The five-year retention column shape exists; enforcement is scheduled in P16.04 (OQ-P2-01).

## BDD examples

- EX-P2-03 GIVEN an existing `audit_record` row, WHEN an UPDATE is attempted as `vyra_app`, THEN the database rejects it.
