# Story P2.06 — TenantContext transaction primitive

- **Story ID**: `P2.06`
- **Epic**: `P2` (`docs/epics/epic-P2.md`)
- **Status**: `draft`
- **Wave**: 2

- **IMPLEMENTATION NOT STARTED**

## User story

COMO implementing agent, QUERO one primitive that opens a transaction with the tenant GUC already set, PARA no request or job can accidentally run outside a tenant scope.

## Context

`architecture.md` §5 layer 2 requires every request and job to open its transaction with the tenant setting applied. Workers inherit this in P7.04.

## Acceptance criteria

- **AC-1** A single exported primitive opens the transaction, sets the GUC, and resets it on exit including on error.
- **AC-2** Data access outside the primitive is rejected by lint or by a repository base class, not merely discouraged.
- **AC-3** Nested use does not silently widen the scope to another tenant.
- **AC-4** The primitive is usable from both HTTP request handling and background job execution.

## BDD examples

- EX-P2-06a GIVEN a repository call made outside the primitive, WHEN lint or the base class check runs, THEN it is rejected.

## Verification gate

Class 7 isolation suite green through the primitive; leak attempts fail.
